# 不确定性与必要缺口

在歧义影响观察判断, 或准备填写 open_questions/gaps 时使用. 先决定当前任务需要知道什么, 再决定是否记录未知.

## 先核对可见事实

回看原图中相关区域及全图位置, 区分“看得见”与“名称让人联想到”:

- 方位用画面坐标描述, 指明相对于哪个对象. 裁切需实际触及图边, 内部遮挡与画外截断分别描述.
- 轮廓只描述可见部分; 用可见端点、弯折与连接支持形态判断.
- 数量、颜色、尺寸采用图像支持的精度; 不靠猜测补齐精确数值.
- 静态姿态、明暗和叠加外观是观察; 运动、材质成因、隐藏形状或算法是解释, 不作为单图已证实事实.

修正能看清的错误后, 只对剩余的必要问题分类.

## 选择记录方式

| 情况 | 做法 |
| --- | --- |
| 现象清楚, 只有精确数值未测, 且用户未要求该精度 | 在 F/R 中用合适的定性描述, 无需未知项 |
| 两种读法会影响必要观察, 但共同可见部分仍可描述 | F/R 写确定部分; open_questions 记录待确认问题 |
| 某个必要可见目标仍未被可靠覆盖 | gaps 写明缺哪一目标、原因及范围; 有具体歧义时可同时记录 open_questions |
| 问题只涉及实现、不可见部分或当前任务外信息 | 留给后续阶段, 不作为观察缺口 |
| 整体无法形成可靠观察 | 调用 stop_analysis 说明受阻原因 |

open_questions 表示待确认的观察判断, gaps 表示实际未覆盖的必要目标; 两者可以同时存在. 已写了“看不清”不代表完成了该目标.
问题引用使用本图已有 E/F/R ID; 没有适用对象时 refs 留空. 描述具体问题, 不用泛化的“可能不准确”占位.

## 边界示例

- 未测一块色面的 RGB, 但色相和渐变方向清楚: 正常描述, 不填 gaps.
- 中央结构究竟相接还是分离会改变连接关系, 原图仍辨不清: 描述可见线段, 记录 open_questions; 若必要连接关系因此无法覆盖, 同时声明该 gaps.
- 用户明确要求每个标记的数量, 密集区无法数清: 这是必要缺口, 即使整体分布已描述.

完成检查即可提交. 不为填写可选列表寻找问题, 也不通过清空真实缺口取得完成状态.
