# 独立视觉探索

本任务的交付是有依据的观察、候选实现方法、草图组合，以及真实未知项。仅使用当前任务的原图、要求、目标范围和探索方向。机制是待验证的实现假设，提交通过不等于视觉效果正确。

按“观察 → 机制 → 草图 → 完成”推进。每步先核对回执中的已登记对象，再创建依赖它们的条目。ID 在本报告内唯一；同一条目修正时沿用原 ID，新增条目使用新 ID。

## 1. 记录观察

先描述目标内部可见的形状、位置、颜色、边界和层次。区分看见的现象与推测的成因；数值目测标为估计。每个 F 对应可定位的现象，每个 R 描述至少两个不同参与者之间的联系。

有 `save_observations` 时，每次保存少量相关 F/R。观察阶段只填写 ID、描述和关系参与者；机制关联留到下一步。工具返回成功回执后，核对实际登记的 ID 和描述。观察暂时没有候选机制是合法草稿状态。

完成条件：目标的主要可见现象已有清楚条目，关系参与者均已登记，尚不能观察的内容有明确缺口。下一轮调用 `advance_exploration_stage` 进入机制阶段。

## 2. 提出机制并建立关联

为观察提出可复用的构造方法，说明方法本身的条件。机制正文使用通用参数，不绑定本图的 F/R/E；它与本图观察的对应理由放在候选关联中。

有 `save_mechanisms` 时，分批提交 M，并用 bindings 明确关联到已有 F/R。每次 binding 替换该目标的完整候选清单，保留仍适用的候选。新机制与使用它的关联可以同批提交；正文中引用的其他机制必须已经登记或属于本批。

候选表例如：

```json
{
  "target_id": "F1",
  "mechanism_refs": [{"id": "M1", "reason": "适合平滑封闭轮廓"}, {"id": "M2", "reason": "便于独立调节局部曲率"}]
}
```

完成条件：准备进入草图的 F/R 已有明确候选；找不到方法的条目有具体 gaps。核对返回的候选表后，下一轮推进到草图阶段。

## 3. 每次组合一套草图

先依据候选表选择机制，再写组织说明。`default` 表示共同采用；`alternatives[].choices` 只替换默认中的指定目标，其余默认选择仍然生效。

```json
{
  "id": "S1",
  "element_id": "E1",
  "name": "轮廓遮罩方案",
  "default": {"F1": ["M1"]},
  "composition": "用 [[M1]] 构造 [[F1]] 的覆盖率。",
  "alternatives": [{
    "choices": {"F1": ["M2"]},
    "reason": "需要独立控制局部曲率时采用。",
    "composition": "用 [[M2]] 构造 [[F1]] 的覆盖率。"
  }]
}
```

上例仅展示引用结构，实际内容和 ID 来自本任务。选择值必须是该 F/R 候选表的非空子集；层名写在 composition，选择键使用 F/R ID。

composition 描述该方案实际采用的机制。讨论旧方案、未选机制或移除理由放在 alternatives.reason；备选改动了机制时，提供与生效选择一致的完整 composition。暂时无法覆盖的观察记入 gaps，空选择数组不表示“跳过”。草图数量由有依据的方案决定。

有 `save_sketch` 时每次只保存一套。需要更换候选时，先更新对应 binding，再保存草图；已有草图仍必须保持合法。读取 `read_exploration_draft` 可核对本任务现存正文和候选表。

## 4. 局部修复与完成

正文引用业务对象时使用 `[[F1]]`、`[[M1]]` 等显式标记；结构字段使用普通 ID。公式变量使用 `base_radius`、`amplitude`、`tooth_count` 等名称，使变量与 E/F/R/M/S 加数字的业务标识可区分。

收到拒绝回执后，按“字段路径 → 原因 → 依赖条目”定位问题：

- 标记或字段错误：只修改报错条目，保留其余分析。
- 选择不在候选表：确认该机制确实适用于该观察；适用时先更新 binding，否则改用已登记候选。
- 备选正文引用了未采用机制：按默认与替换后的实际组合重写该草图的 composition，比较解释留在 reason。
- 某个目标未覆盖：补充有依据的选择，或登记具体缺口。

分步工具按 ID 局部替换，未提交的条目保留，失败写入不改变上一份合法草稿。检查最新回执，保存完整 open_questions/gaps 清单后，在后续请求调用 `finish_exploration`。程序组装最终报告，不需要重新输出整份正文。

## 只有整份提交工具时

若当前仅提供 `submit_exploration`，仍按以上依赖顺序组织分析，但中间步骤尚不能持久保存。先建立 F/R 目录，再建立 M 和候选表，最后依据候选表组织草图并完整提交。根据反馈修复时保留此前有效内容。此模式用于对照 skill 指导本身的效果，不声称具有分步保存能力。
