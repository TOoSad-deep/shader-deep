# 整体优化工作流

`start_workflow` 固定参考 PNG、整图要求和预算，调用观察、规划与只看参考图的标准整理，停在门禁 A。调用方通过 `read_workflow` 读取 `workflow.json`，再用 `advance_workflow` 提交对应门禁的动作。UI 可传 `expected_revision`，防止过期操作覆盖其他决策。已完成或受阻运行可继续读取。

- 门禁 A 由人选定整图方案，并冻结 V2 标准。成对采样的参考图和候选图坐标必须先通过固定画布校验。可直接生成整图，也可用 `run_probe` 提交一至两个按顺序执行的规划试验。`probes` 每项包含零基 `probe_id`、目标矩形和相应上下文字段，单项仍支持旧顶层写法。每个局部独立评审，在门禁 B 晋升后才进入下一项。首项晋升时以实际评审帧固定同批后续试验及整图的渲染时刻，满足复用条件的片段可一并注入整图。工作流使用参考图的原始像素画布。
- 门禁 A 也可提交 `compare_plans`，用 `sketch_id`、可选 `alternative_index` 指定第一条路线，用 `comparison_plan` 指定第二条。两项共享冻结标准、预算和渲染条件，生成与评审并行。带 `probe_id` 时两项只切换方案，局部目标、上下文和区域相同。工作流保留两侧实际制品并返回门禁 A；人用 `select_comparison` 指定 `candidate_id` 后，将该已评审候选直接提交门禁 B。两侧均无正式报告时，界面保留失败原因与材料。
- 运行 `shader-deep-workflow panel RUN_DIR` 可读取当前门禁的决策材料。网页直接列出观察缺口、参考测量、评审像素差及回归项，并提供两侧对照预览。命令行的 `advance RUN_DIR DECISION.json` 与网页使用同一份门禁合同。
- 门禁 B 展示已评审候选、逐项回归、修订建议和剩余预算。局部通过后由人晋升为固定片段。整图由人接受后交付 `shader.glsl`、`uniforms.json`、`shader.baked.glsl` 和对应预览。
- 规划停止且没有定向复核申请时，工作流保留规划给出的原因，进入受阻状态。复核后仍有争议时，门禁 A 提供人工裁定。标准草拟在正式规划包发布后启动。
- 如果首次标准草拟因模型输出未通过校验而受阻，包括来源 ID 不存在或必查矩形超出画布，可运行 `shader-deep-workflow retry-criteria RUN_DIR`，或向 `advance` 提交 `{"action":"retry_criteria"}`。程序核对失败追踪、固定观察与规划身份，并从原剩余额度中再消耗一次逻辑调用。草案发布后返回门禁 A 由人冻结。
- 首轮门禁 A 已有草案时，人可以用 `retry-criteria RUN_DIR --reason "需要重拟的具体问题"` 请求重新整理。原因随固定参考材料进入整理模型；每次尝试计入原预算。成功时新增草案版本并记录新旧路径，仍停在门禁 A 等待人工冻结。失败时可继续查看原稿和错误原因。全局预算触顶则归档。
- 门禁 B 的「采纳建议修订」采用当前候选逐项生效的升级路线。调参遇到结构瓶颈或同项调参连续失败两次后转向结构修改，连续两轮结构修改仍未解决同一问题时转向重新规划。回滚恢复所选候选的修订来源，只计算该分支中已经发生的尝试。缺少来源的旧记录仅保留明确属于当前候选的既有升级提示。人工改派通过 `reroute` 明确给出路线及原因。结构修订将人工说明、诊断靶点及原候选需要保留的表现和像素保护区一并提供给生成 Agent。
- 自动处理有三个入口。规划报告的阻断性矛盾触发一次定向观察。所有未评项均可由现有原图取证时，同一候选最多扩窗或新增成对像素采样一次。缺背景、缺帧及无法定位的未评项保留给人工选择。全部重大问题均有外置参数可调，且已匹配检查具备保护矩形时，启动一次锁定结构的定向优化和复评。已匹配检查缺少保护矩形时，门禁 B 列出阻止自动调参的检查。原候选已达到数值目标时保留原视觉报告，连败次数保持原值。
- 大轮预算约束人工启动的生成或修订。逻辑调用在阶段启动前预留，实际模型请求另按输出 token 上限预留，同一工作流内的并行请求共用额度。服务商返回用量后退回差额，缺少回执或进程中断时保留预留。默认全局输出上限为 256,000。可另设总 token 上限，须同时给出部署中所有参与模型真实的上下文硬上界。每次预留完整上下文容量，余额不足就停止发请求。两种额度均以 token 计量。升级前已存在的运行从恢复后的首个请求开始记 token 账，历史回合沿用其已有记录。
- `workflow-trace.jsonl` 串起门禁操作、阶段开始和结束、剩余额度与关联制品。工作流把参考、候选、优化拐点的 PNG、固定 GLSL 与实参归入 `vista/`。评审、诊断、历史最佳与人工选择的版本保存在 `history/`。触及预算时先保存本阶段已返回的产物，再归档工作流。
- 候选、评审包和诊断分别保存在运行制品中。回滚和交付重读正式评审并核对原始参考、候选、冻结标准及参数记录。人工回滚点优先作为同一范围和冻结标准下的回归基线。自动排序依次看重大问题数、回归和评审完整性。仅在同分候选都使用同一次调参的目标和帧时比较误差。整图回滚点会在同一整图标准的局部试验期间保留。
- 已晋升片段按参考 PNG、要求、目标观察、逐目标的方法选择及机制正文核对依赖。只有画布、实际时间和局部标准也相符时才回流整图。没有局部必查项的维度可以更新整图排除理由。移除目标的全部必查项后，该片段会从本轮整图材料中跳过。整图基线补丁携带完整旧场景，另需同一规划和方案选择。

目标流程与阶段边界见[整体优化方案](../../../../docs/work-items/workflow-optimization-design-20261125.md)。

观察复核后，`observation_cascades` 记录变动影响到的观察来源、旧必查项和所依据的历史制品。定向规划从旧稿编辑，接受时保护无关目标和共享机制。门禁 A 人工选择 `replan` 后，即使期间需要自动复核观察，规划仍按人工要求重做。标准整理只更新受影响来源的检查，保留人工已批准的其他检查与区域。上下文备注的变更会影响整图。规划另比较测量锚点、观察缺口和开放问题。仅这些附属材料发生变化时，参考侧标准可沿用原稿。目标与输入均未变化且没有人工重规划要求时复用规划正文和标准。
