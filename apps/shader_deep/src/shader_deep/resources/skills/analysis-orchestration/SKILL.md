# 图像分析编排

完整读取本文件后, 依据实际工具回执推进下列步骤。每次请求只使用当前开放的工具。用户要求与原图是分析依据, 工具记录是执行进度依据。

## 1. 划分并登记元素

观察原图, 划分能单独定位和分析的视觉元素。使用具体名称和空间范围; 将重复实例、连续背景和独立主体按可见边界组织。每个元素提供唯一 `id`、`name`、`region`, 将 `feature_ids` 设为空。此步只登记元素, 后续探索产生 F/R/M/S。

调用 `submit_elements(elements=...)`。根据校验错误修正目录, 直到收到成功登记回执。读取回执中的已登记元素, 在后续模型响应中才选择目标并派发。

## 2. 派发一批独立探索

从已登记目录中选择一个与用户要求相关、范围清楚的目标。制定 `default_directions` 指定数量的独立探索方向。方向须描述可验证的分析问题, 各自允许完整观察目标; 避免把预设机制或共同结论当成已知事实。

调用 `dispatch_exploration(target_element_id=..., directions=...)`。目标正文与范围由程序从登记记录装配。该工具内部并行执行独立子 Agent, 完成有限恢复后返回最终任务状态、错误与结果引用。依据回执继续工作, 已登记的一批任务保持原身份和输入。

## 3. 读取结果并请求整合

通过 `read_analysis_result(result_id=...)` 读取回执提供的有效报告, 核对观察、候选机制、方案、未知项和失败原因。保留不同探索的分歧; 成功状态只表示提交通过程序校验。

探索和内部恢复已终结且存在有效产物时, 调用 `dispatch_integration()`。程序汇集已接受报告、更新引用并保存合法 V0, 然后启动独立整合 Agent。整合仅合并 F/R/M, 草图由程序汇集保留。根据整合回执读取所选版本, 保留失败、缺口及 V0 回退情况。

全部探索失败或工具明确表示无法形成合法基线时, 根据真实失败状态请求结束。工具返回尚未结束的任务时, 根据反馈继续处理当前步骤。

## 4. 请求交付

核对已返回的任务状态、有效结果和所选版本后, 调用 `finish_analysis()`。最终状态、缺失任务与交付文件由程序计算。中间操作成功后继续编排; 只有最终交付被接受才结束本轮。
