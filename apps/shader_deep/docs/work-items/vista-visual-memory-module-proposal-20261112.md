本文已被[VISTA 最小图片记录设计](vista-minimal-image-records-design-20261113.md)替代。下文仅保留历史讨论，不再作为下一步实施依据。

VISTA 保存、定位和读取视觉材料及其必要关联。分析、规划、生成和调参 Agent 复用同一个模块。

日期：2026-11-12。本文为当时提出的候选方案，现已被替代。它不覆盖旧版实施记录，也不表示这些接口已经可用。

## A 定位与职责

**已确认的方向：**以图片为核心，统一存储，记录来源 Agent。业务逻辑、观察判断和上下文策略由调用方负责。

| 责任 | 归属 |
| --- | --- |
| 保存材料、分配 ID、校验内容、管理来源与关联 | VISTA |
| 列目录、读取正文、读取整图或裁剪 | VISTA |
| 将读取结果转换成框架可用的图文消息 | 工具接入适配 |
| 选择登记时机、默认材料与保留轮数 | 业务模块或外层 harness |
| 分析图片、制定方案、渲染、调参、判断交付资格 | 对应业务模块与 Agent |

```flow LR
业务模块 -> VISTA: 登记产物
Agent -> 工具接入适配: 查找与读取
工具接入适配 -> VISTA: 调用存取接口
VISTA -> 材料文件与索引: 保存与回读
```

公共模块不导入黑板、候选模型或五库模型。接入适配负责把业务对象转换为材料与引用。

## B 材料范围

**本版提议：**保留 `image/code/text/json` 四种格式，登记范围围绕视觉任务。

| 内容 | 保存方式 |
| --- | --- |
| 参考图、渲染图、裁剪图 | 核心材料，保存确定版本 |
| 对应代码、参数快照 | 独立材料，通过 ID 与图片关联 |
| 针对图片的观察或比较记录 | 可选文本或 JSON 材料，引用所依据的图片 |
| 视觉迭代中的失败代码与渲染错误 | 由业务方显式登记，关联本次使用的参考图或基线图 |
| 完整任务状态、五库、执行计划、聊天历史 | 由原业务模块管理，不自动归档到 VISTA |

相关性由接入方决定。VISTA 校验格式和引用，不判断业务内容是否值得保存。

失败尝试没有预览图时，不创建虚假的图片材料。错误正文由生成侧产生，VISTA 只按普通材料读取。

材料原件默认保留。模型请求中是否继续携带这些内容，由外层决定。

## C 图片与关联资料

**新增提议：**每条材料可带 `related_to`，保存已存在的材料 ID。

关联只记录一次。查找某材料的关联项时，同时检查出向与入向引用。

| 示例 ID | 材料 | 新登记时记录的关系 |
| --- | --- | --- |
| m0001 | 参考图 | 无 |
| m0002 | 本次 GLSL | `related_to: [m0001]` |
| m0003 | 本次参数快照 | `related_to: [m0001]` |
| m0004 | 本次渲染图 | `related_to: [m0001, m0002, m0003]` |
| m0005 | 渲染后的观察记录 | `related_to: [m0004]` |
| m0006 | 渲染图的局部 | `derived_from: m0004 + region` |

这些 ID 仅为示意。m0005 可以在图片登记后追加，不必修改 m0004。一个比较记录也可以同时关联两张图片。

`related_to` 只表示相关，不表示因果、优劣或采用关系。`derived_from` 单独表示裁剪的直接来源与像素区域。

查询关联时，只返回直接邻居。来源图与直接裁剪也可作为邻居返回，并标明派生方向。反向索引从集中索引计算，不另存一份。

读取图片时只展开图片及必要元数据。相关代码、参数与观察正文，需要显式读取。裁剪也不会自动展开原图的所有资料。

后续若要给两份已有材料补关联，可登记一条说明材料并引用两者。首版不增加修改旧记录的关系编辑接口。

## D 索引与文件

沿用集中 `memory/index.json`。每条记录对应一份可独立读取的内容，不按来源 Agent 建子库。

```tree
run-xxx/
  inputs/ | 已有输入文件
  candidates/ | 已有代码、参数和预览文件，示意位置
  memory/
    index.json | 唯一材料索引
    contents/ | 由 VISTA 新保存或捕获的内容
    derived/ | 裁剪图
```

已有运行内的不可变文件可以复用原位置。外部文件或可能被覆盖的文件，应先捕获为独立副本。

| 字段 | 规则 |
| --- | --- |
| 外层 `version/run_id/materials` | 延续集中结构；新合同提议使用 version 2 |
| 材料 ID | 作为 materials 的键；当前运行内稳定唯一 |
| `kind/label/path/sha256` | 保留原含义；path 相对于运行目录 |
| `source.type` | input、output 或 derived |
| `source.agent` | 新增，可空；由程序记录实际产生材料的 Agent |
| `source.role/operation` | 记录输入用途或产生操作 |
| `source.refs` | 提议用于可选的业务标识，值为短字符串 |
| `source.origin` | 导入材料时保留原 run_id 与 material_id |
| `related_to` | 新增，可选；只引用同一索引中已有材料 |
| `derived_from` | 沿用直接来源材料、操作和整数像素区域 |

`source.refs` 可保存 task_id、candidate_id 等业务标识。VISTA 原样保存和返回，不查询业务状态。旧报告来源字段也必须保留，迁移时不可丢失。

来源 Agent 表示材料产生时的来源，不记录最近读取者。程序或用户输入可以没有 Agent。工具调用时，来源由运行时注入，模型无需自行声明身份。

导入材料保留原生产 Agent，未知时留空。导入者不能覆盖原生产者身份。新裁剪记录发起该操作的 Agent，并保留直接来源。

下面是一条新合同记录的示意片段，不是当前可加载的索引。哈希占位符在实际保存时替换为真实 SHA256。

```json title="材料记录 · 提案示意"
{
  "m0004": {
    "kind": "image",
    "label": "候选 2 的渲染图",
    "path": "candidates/candidate-002.png",
    "sha256": "<实际文件的 SHA256>",
    "source": {
      "type": "output",
      "agent": "generation",
      "operation": "render_shader",
      "refs": {"task_id": "task-001", "candidate_id": "c002"}
    },
    "related_to": ["m0001", "m0002", "m0003"]
  }
}
```

正文变更产生新材料；读取不改变原记录。相同裁剪可以复用，但不同来源的相同图片不自动合并。

首版在一个运行内统一存取，来源 Agent 和 task_id 不作为分库或筛选权限。不同运行继续使用不同索引。跨运行使用时显式捕获，并保留来源引用。

共享索引采用单个写入协调入口。原子替换不能避免多个独立写入者覆盖彼此，首版不承诺多进程并发写入。

## E 最小接口

下面的名称和参数是候选合同，尚未实施。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `save_material` | 内容或文件二选一；类型、名称、来源、可选关联 | 材料 ID 与简短描述 |
| `list_materials` | 可选类型、关联材料 ID、来源 Agent、分页参数 | 简短目录与下一页游标 |
| `read_materials` | 材料 ID 数组；每项可带图像 region | 逐项实际内容、必要来源或明确错误 |

保存通常由程序调用。Agent 首版只获得列出和读取工具。观察记录需要保存时，由现有业务工具调用保存接口。

**列目录提议：**默认列图片。显式 `kind: null` 列全部格式。沿用每页默认 20 条、最多 50 条。

查图片的关联资料时，调用 `list_materials(related_to="m0004", kind=null)`。返回 ID、类型、名称、来源 Agent 和关系说明，不展开正文。

读取图片返回实际图像内容；读取代码、文本或 JSON 返回正文。返回信息标明材料身份、图像尺寸及完整或局部视图。

读取可以同时请求多项。已知 ID 时直接读，无需先列目录。读图不隐式附带代码或观察记录。

裁剪沿用左上角整数像素坐标和半开区间。裁剪结果登记为派生材料；再次读取同一材料不产生新记录。

缺失、越界、内容变化或过大均明确报错。批量读取按项返回结果，不用占位内容冒充原件。

文件大小和解码限制由模块执行，具体阈值可配置。“每个模型轮次读几份”由接入方负责。

## F 接入与上下文

**本版提议：**公共模块返回与模型框架无关的材料结果。工具接入适配将其转换为图文消息。

```sequence num
生成模块 -> VISTA: 登记代码、参数和渲染图
VISTA --> 生成模块: 返回材料引用
生成模块 -> Agent: 提供本次图片 ID 和读取入口
Agent -> 工具接入适配: 读取图片及指定局部
工具接入适配 -> VISTA: 按引用读取
VISTA --> 工具接入适配: 返回图像内容和来源
工具接入适配 --> Agent: 在下一次请求提供真实图像
```

接入方启动时提供材料入口。新材料产生后，业务工具反馈返回对应 ID。完整目录由 Agent 按需查询。

参考图是否常驻、默认展示哪个候选、回看保留几轮，均由外层策略决定。VISTA 不维护 pending 轮次、模型历史或候选完成资格。

工具适配负责消息格式和调用响应配对。外层 harness 负责历史精简与重试生命周期，不能在失败请求后提前消耗临时内容。

“图片已经进入请求”只是一条呈现事实。模型是否理解正确、候选能否交付，由业务方判断。

## G 现状与迁移路线

以下现状根据本次读取的工作区源码核对。草案新增项仍待 review。

| 当前实现 | 迁移建议 |
| --- | --- |
| VisualMemory 已有索引、哈希回读、裁剪 | 复用存取实现，增加来源 Agent 与通用关联 |
| 存储对象按 task_id 限定访问 | 新接入按明确的运行索引使用；保留旧入口兼容 |
| 来源类型中列举候选与旧报告字段 | 将业务标识转为来源引用，保留原追溯信息 |
| GenerationMemory 同时包含业务映射和内容组装 | 候选映射留在生成侧；通用读取与格式适配提取复用 |
| history.py 识别 render_shader 并精简历史参数 | 保留生成侧业务投影，不直接移进公共 VISTA |
| 默认最新成功候选与一轮回看 | 保留为生成侧原策略，不变成模块规则 |

新合同另起 version 2，旧 version 1 索引保持可读。迁移必须保留已有 ID、哈希、来源和路径；不自动重写历史运行。旧材料缺少关联时保持未知，不凭字段猜测关系。

只有外层明确把 Agent 接入同一运行，才共享该索引。分析、规划和生成目前各自已有运行，不因使用同一模块就自动合并数据。

实施顺序提议：先实现公共合同，再保持生成接入行为，最后用分析 Agent 验证复用。调参 Agent 的业务实现另行推进。

验收应覆盖以下行为：

- 两个 Agent 在同一运行登记和读取材料，来源保留且不按 Agent 隔离。
- 后补观察能从关联图片找到；双图比较能从任一图片找到。
- 读取图片不附带未请求正文；裁剪像素和来源区域一致。
- 实际模型请求包含图像内容；工具调用和响应保持配对。
- 生成侧原有方案输入、错误回读和候选资格保持原行为。
- 旧索引可读；写入失败不发布悬空引用；同进程共享写入入口不丢记录。

## H 建议优先 review 的四处

| 编号 | 本版选择 | 需要判断的取舍 |
| --- | --- | --- |
| R1 | 图像和相关资料独立登记，允许视觉迭代的错误材料 | 是否符合“图片及其相关”的范围 |
| R2 | 用 related_to 记录一次关联，反向查找由索引计算 | 是否足够表达图片、代码、参数和观察之间的关系 |
| R3 | Agent 首版只有列出与读取，保存由程序接入 | 是否需要另加 Agent 主动保存观察的工具 |
| R4 | VISTA 负责存取，外层负责内容在请求中的保留策略 | 是否符合期望的模块职责 |

上述四项均为供 review 的选择，尚未作为实施决定。文件布局细节和实现拆分可在确认后进入实施方案。
