## 已明确的讨论方向

1. VISTA 相关能力面向整个 Shader Deep, 可以服务于分析、生成、整图组合及后续调参、视觉评审, 不限定为调参专用.
2. 希望模型聚焦当前问题, 其他视觉材料和实现细节在需要时读取; 历史原始图像仍应能够回看.
3. 调参可作为独立子 Agent 的工作: 默认围绕单参数试探及其视觉变化, 在内部完成多轮调整、渲染和观察.
4. VISTA 式视觉记忆与调参结合具有合理性, 实际视觉质量、效率及成本收益仍需验证.
5. 历史图像与资料需要可发现、可准确定位: 模型应能知道材料存在, 并识别需要回看的具体材料; 目录和查找方式待讨论.
6. 当前以构建多模态记忆/harness 为重点, 对任务涉及的输入、产物及过程材料先尽可能保留. 优先讨论组织、发现和回读, 保留期限、淘汰与清理策略后续再议; 保存完整不等于每轮全部提供给模型.

“共用视觉记忆模块 + 每个 Agent 独立的当前视图”是已提出的候选架构, 尚未定稿. 下列 Interface、存储方式和默认策略都是待讨论方案.

## 讨论顺序与推进方式

按依赖关系推进: **初步确定怎么存 → 初步确定怎么用 → 用场景检验 → 细化运行策略 → 确定实施和验证**.

| 阶段 | 对应议题 | 本阶段需要形成的结果 |
| --- | --- | --- |
| 初步确定怎么存 | 01 | 记忆的基本组成、关系和来源 |
| 初步确定怎么用 | 02 | Agent 查找、回看和使用记忆的基本流程 |
| 用场景检验 | 03 | 分析、生成和调参对公共能力的实际需求 |
| 继续细化 | 04–06 | 数据与工具契约、每轮上下文、隔离及生命周期规则 |
| 实施和验证 | 07–08 | 首版范围、接入顺序与验收方式 |

前两项先形成可调整的概念模型, 暂不锁定数据库、目录、完整字段或工具参数. 后续使用场景若暴露问题, 回到对应条目修正. 每轮看哪些图像属于后续运行策略, 在存储与基本使用方式明确后讨论.

### 01 — 初步确定视觉记忆保存什么、怎样组织

- [x] 讨论记忆的基本单位: 图像、一次观察、一次操作及其结果如何组织和关联.

- [x] 初步确定如何标识一份材料, 以及如何追溯它的来源和产生过程.
- [x] 确定用于发现与定位材料的索引信息, 让模型知道有哪些图像或资料, 并能区分、引用及回读具体原件.
- [x] 初步确定视觉材料与现有分析证据、候选、代码版本及参数试验记录的关联方式.

跨任务、跨模块复用通过第 03 项的交接场景继续检验, 具体隔离与生命周期留到第 06 项, 不作为本项概念模型推进的前置条件.

本项产出: 一个简单、可调整的记忆模型, 说明保存哪些内容以及它们之间的关系.

讨论结论 (2026-10-29, 概念模型初步确认):

- 采用渐进式披露: 简短目录和过程线索帮助发现材料, 按需展开具体记录, 再读取相关原图、代码或报告等原件. 具体工具调用方式留到第 02、04 项讨论.
- 材料目录提供稳定身份与原件定位; 过程索引组织输入、操作及结果, 引用已有分析证据、候选、代码版本和参数试验等业务记录.
- 同一份材料可被多次观察和引用, 保持同一身份; 一次观察围绕问题关联一组材料, 可产生裁剪、测量或文字笔记.
- 文字笔记关联具体材料, 保存当时的判断、疑问和计划; 程序能够确认的来源与操作事实和模型判断分别表达.
- 保存采用“先尽可能保留”的默认原则, 包括任务涉及的原始输入、实际产物、派生观察材料及关联记录. 当前重点是多模态记忆/harness 的组织、发现和回读能力, 保留期限、淘汰与清理策略后续再议.
- 第 01 项已有可继续推进的概念模型; 后续场景可以反馈修正. 跨任务复用规则、数据字段、保存技术、每轮上下文及工具参数尚未定稿. 完整保存不等于对所有角色开放或每轮全部发送.

### 02 — 初步确定 Agent 怎样使用记忆

- [x] 讨论 Agent 如何知道有哪些可用材料, 以及如何找到与当前问题有关的记录.
- [x] 确定回看整图、查看局部、多图对照和读取数值的基本操作.
- [x] 明确每种操作返回什么: 索引、实际图像、来源说明或测量数据.
- [x] 讨论新材料何时登记, Agent 的观察和笔记如何引用这些材料.
- [x] 用一个简单的“产生材料 → 找到材料 → 回看 → 继续判断”流程检查第 01 项是否够用.

本项产出: 基本使用流程与能力清单. `history`、`inspect`、`read_pixels` 是参考候选, 工具名称和参数暂不定稿.

讨论结论 (2026-10-29, 基本流程与分工确认):

- 程序负责自动登记材料和可确认的客观过程, 包括输入来源、实际改动及输出关联; 新材料产生后提供稳定引用回执.
- Agent 负责按当前问题选择和读取材料, 补充操作意图、观察、判断及疑问; 笔记引用对应材料, 支持后续回看和修正.
- 任务入口提供简短说明: 可用材料类别、当前任务关联记录及查询读取方式; 详细目录按需展开.
- 已知准确 ID 时直接读取; 只记得操作、参数改动或观察问题时, 先查过程索引, 再取得具体材料引用.
- 查询返回用于区分记录的简短线索与引用; 展开时按需提供实际整图、局部、多图对照、代码、参数、既有笔记或测量数据. 有新的数值疑问时可进一步测量, 结果保留来源说明.
- 使用流程为“产生并登记材料 → 回执或入口发现材料 → 查找或按 ID 直接读取 → 观察判断 → 记录关联笔记”. 同一问题所需的多份材料可一起请求, 不要求每次固定逐层调用.
- 以上是基本使用约定, 不代表已确定检索技术、工具名称、完整参数或每轮上下文策略. 第 03 项继续用具体场景检查其是否足够.
