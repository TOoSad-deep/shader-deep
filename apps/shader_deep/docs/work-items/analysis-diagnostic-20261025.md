# 多视角分析小范围诊断

诊断日期: 2026-10-25. 三张真实样本、历史回放与最小对照诊断已完成. 诊断阶段未修改应用源码; 用户随后授权的请求层修复与复测单独记录在文末.

## 当前结论

优先处理发送到当前 OpenRouter 模型的严格工具 Schema 与文本正则的兼容问题, 再复测任务完成率. 现有证据不足以把低成功率主要归因为缺少探索 skill.

五库的通用 `Text` 类型使用 `minLength: 1` 与 `pattern: "\\S"`, 请求适配层又将 OpenRouter 工具设为 `strict: true`. 本地校验允许完整的多字符文本, 但本轮真实请求多次返回只有一个非空字符的 ID、名称、描述和方法. 随后的重复 ID、引用缺失、关系端点重复和修复耗尽, 是这类内容退化在业务校验层的表现.

这里定位到的是当前模型、路由及严格 Schema 组合的可复现兼容问题. 未定位具体上游服务商或解码器内部实现, 不推广为所有模型或全部历史失败的原因.

## 最小 Schema 对照

使用相同配置的原生客户端直接调用 OpenRouter, `stream=False`, 不经过应用流式参数拼接. 请求要求工具原样返回 `alpha123` 和 `霓虹圆角边框`. 两种条件各重复两次, 唯一业务 Schema 差异为是否包含 `pattern: "\\S"`; 其他设置一致. 每次请求最多 4096 输出 token, 均正常以工具调用结束.

| 条件 | 完整返回指定文本 | 服务端原始参数 |
| --- | --- | --- |
| 当前正则, 第一次 | 否 | `label="a"`, description 只有“霓”及空白 |
| 去掉正则, 第一次 | 是 | `label="alpha123"`, `description="霓虹圆角边框"` |
| 当前正则, 第二次 | 否 | `label="虹"`, description 只有“霓”及空白 |
| 去掉正则, 第二次 | 是 | `label="alpha123"`, `description="霓虹圆角边框"` |

原始工具参数与服务端用量保存在 `schema-probe.json`. 四次对照合计 1060 token. 原始响应已呈现单字符问题, 所以该现象不依赖应用的流式拼接. 这是小型兼容性对照, 不是完整分析流程修复后的成功率验证.

本地 `TypeAdapter(Text)` 接受 `alpha123`、`霓虹圆角边框`, 拒绝纯空白和空字符串, 见 `schema-local-check.json`. 因而业务目标是“含非空白内容”, 不是“只能有一个非空白字符”.

## 修复顺序建议

1. 在模型请求边界处理不兼容的字符串正则, 同时保留本地完整非空白校验; 不通过降低引用完整性要求来消除报错. 需增加真实外发 Schema 的契约检查, 再按相同样本复测. 诊断结束时未修改代码; 后续实施见文末.
2. 修复后重新区分首次提交、修复后提交、报告内容可用和最终交付. 无草图、只有占位词的提交不能当作可用分析成果.
3. 对剩余的分析方法不足, 再设计共享探索 skill、完整示例及修复指引. 当前数据没有验证 skill 的增益.
