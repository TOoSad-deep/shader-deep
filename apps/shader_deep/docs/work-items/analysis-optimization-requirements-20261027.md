# 分析模块优化需求与方案

日期: 2026-10-27.

状态: 2026-10-27 review 后的实施方案. 用户已授权先优化方案, 再由 GPT-6.1 Sol 实施. 下文定义本轮范围与验收条件; 实际完成项和验证证据在第 10 节单独记录.

现有约束以[分析架构与 Agent 工作流设计](../analysis-architecture-design.md)和[五库与报告数据设计](../analysis-five-libraries.md)为准. 后续实施涉及契约调整时, 应同步相应主要设计文档. 已有分步试验及其验证边界见[探索 skill 试验记录](exploration-skill-20261026.md).

## 1. 优化目标

让子 agent 看清目标, 输出简洁、职责明确、有依据的分析, 并把可迭代的实现路线交给生成模块.

重点解决:

- 最终报告过重, 同一信息在多个层次重复出现.
- 目测估计、实现假设与已确认事实混杂, 部分输出存在实质错误.
- 覆盖要求和引用规则引入不必要的关联维护与修复负担.
- 子 agent 缺少聚焦目标和按需取证的能力.
- 分步运行虽然便于局部修复, 但多轮历史与推理块带来较高 token 成本.

## 2. 已明确的分析边界

1. 一次围绕一个目标元素分析, 周围内容作为理解目标的上下文.
2. 分析结果只保留必要语义, 减少重复描述、未经验证的精确数值和无关假设.
3. 机制层负责说明实现原理、操作方式和可调方向. 用户已明确希望它表达机制与思路, 而非固定代码; 后续生成模块仍需要迭代.
4. 生成模块负责将机制展开为公式、代码, 进行参数调整和渲染验证.
5. 沿用分步保存、局部修改的优化方向, 避免每次错误都要求重新输出整份报告. 这不等于已经决定将分步试验切换为默认流程.

## 3. 五层语义与内容收缩方向

下表定义本轮内容粒度. 五库对象保持现有字段; 辅助上下文、裁剪输入和测量溯源由任务材料及可选证据文件承载, 具体约定见第 4、5 节. 实施时同步主要设计文档.

| 层次 | 应当保留的内容 | 需要收缩的内容 |
| --- | --- | --- |
| 元素 E | 对象身份、分析范围 | 对目标的提前分析和实现结论 |
| 特征 F | 直接可见、影响复现的现象 | 大量目测数值、成因推测、旁观信息 |
| 关系 R | 必须保持的空间与视觉关系 | 对特征的复述、实现步骤、无独立价值的关系 |
| 机制 M | 原理、操作、可调因素、必要适用条件 | 固定代码、未经验证的公式和参数 |
| 草图 S | 本次选择哪些机制、如何组合 | 重写全部观察和机制、提前锁死实现细节 |

没有独立价值的关系或备选可以不写. 不要求为了填满层次而增加条目. 有依据且影响实现选择的细节仍可保留; 精简不等于丢弃必要约束.

机制层的示意粒度:

> **机制: 周期缺口差集**\
> 原理: 通过基础形状与重复切割形状的差集构造轮廓.\
> 操作: 建立圆盘, 沿圆周重复布置切割形状, 从圆盘中扣除它们.\
> 可调因素: 缺口数量、形状、深度和相位.\
> 适用边界: 适合近似周期分布的缺口.

该示例说明机制层需要的深度, 不代表已经确定齿轮样本必须采用此方案. 具体符号约定、距离函数、循环写法和参数值由生成与验证阶段展开.

## 4. 内容、引用与局部修改

| 优化项 | 建议方案 |
| --- | --- |
| 收紧输出要求 | 修改 skill 的说明与示例, 让 M 停留在原理和操作层; 同一信息只保留一个主要位置; 不确定数量、尺寸、色值集中记录为待确认项. |
| 调整覆盖义务 | F/R 只登记本目标需要复现的观察与关系; 辅助上下文放在独立任务备注. 每套草图继续覆盖本来源 F/R, 未覆盖项保留 gap. |
| 调整引用校验 | 区分普通变量与已登记对象. 采用机制由结构化选择确定; composition 说明有效组合, 比较或移除理由放在 reason 等说明字段. |
| 改善图像输入 | 提供可选的“全图概览 + 目标裁剪图”, 保留原图坐标映射, 支持按需扩大范围. |
| 补充观察工具 | 接入局部查看、区域统计, 复用已有确定性图像操作; 关键结论与具体证据记录关联. |
| 局部撤回 | 在同一次草稿变更内撤回错误对象并修复其依赖, 校验和持久化成功后发布新版本. |
| 控制分步执行成本 | 提供阶段所需目录, 正文按 ID 回读; 用确定性的请求上下文裁减替代重复历史回传, 保留完整审计日志. |

### 4.1 覆盖义务的判定边界

- 固定的用户要求与目标范围是语义依据. 主 agent 继续只定位与划范围, 不为 worker 预填共同 F/R 清单.
- worker 将影响本目标复现的直接观察登记为 F/R. 已登记 F/R 构成本来源的必要覆盖集合, 所有草图对它承担已有的候选与覆盖义务; 同一机制可以同时支持特征和关系, 无需为每条关系重复创建机制.
- 背景布局、旁边物体和帮助判断材质的上下文放在任务级 `context_notes`, 不登记为需要生成的 F/R, 不要求配机制, 不计入覆盖分母. 备注进入草稿和必要上下文, 不作为第六个业务库.
- 无法确认的数量、尺寸或成因写入关联的 `open_questions`; 必要观察无法形成方案时仍写入 `gaps`. 任务失败、必要整合未完成等执行缺口继续由程序汇总, 不因内容精简改成 completed.
- 纠正误登记的 F/R 必须通过第 4.3 节的显式变更, 保留理由. 不增加让模型将任意已登记目标标成可选以跳过覆盖的开关.

程序可以保证已声明目标没有被静默漏掉, 不能仅凭结构校验发现模型从未观察到的关键现象. 后者由第 8 节固定样本的视觉核对检查.

### 4.2 引用与执行说明

1. `[[ID]]` 继续表示五库对象引用, 必须存在、类型正确并参与合并重写. 已登记对象 ID 的裸写继续拒绝. 不再仅因未登记的普通变量形似 `R0`、`M2` 就要求其成为对象引用; 与实际对象同名的变量使用清晰变量名. 汇集分配全局 ID 时预留所有来源非标记正文中的普通符号, 避免后来的对象使合法变量变成裸引用.
2. `default` 与生效的 `alternatives[].choices` 是采用机制的权威选择, 候选适用范围和非空选择继续硬校验.
3. `composition` 只解释生效方案的组织方式; 比较、未选机制和移除理由可写入 `reason` 等说明字段. 不用自然语言关键词猜测某次机制提及是否表示采用.
4. 备选替换掉正文中的机制时, 必须同时给出兼容的 composition; 与机制无关、仅引用 F/R 的组织说明可以沿用. 保留“备选不能继承已移除机制的执行说明”的回归检查.
5. 报告读取和生成上下文统一采用上述含义, 明确参考材料不自动成为采用方案. M 的公式和参数细节由生成阶段展开, 不将通用方法当作已验证的实现.

### 4.3 草稿撤回与原子修改

分步流程补充一个受当前任务限制的草稿修改操作: 显式提交要撤回的 F/R/M/S ID、非空理由及相关替换项. 先在副本上应用全部变更, 再执行引用与草图选择校验, 成功后持久保存新修订. 未提交对象保留; 任一错误使整批回滚; 旧修订仍可审计.

不隐式级联删除关系、草图或未知项. 撤回仍被引用的对象时, 必须同批修正或撤回依赖者; 同时处理候选、默认/备选选择、正文标记、问题和证据关联. 将误记观察移入上下文备注也需要这条显式路径. 历史记录不删除, 终结任务和失效 attempt 不接受写入, 新修订须进入后续模型请求才能完成提交.

## 5. 图像聚焦与取证方案

本轮实现可选裁剪和受限观察工具, 通过显式试验入口验证. 增加工具不预设准确率提高或 token 降低, 分步流程继续保留为非默认方式.

输入与取证流程:

1. 主 agent 定位目标时可提供程序能执行的包围框; 独立 worker 试验从固定样本规格接收同样的包围框. 框属于任务输入, 不写进元素描述作为隐式协议.
2. 程序生成带适当余量的裁剪图, 保留原图与坐标映射.
3. 子 agent 结合全图概览和目标图进行分析; 有具体疑问时扩大查看范围或调用测量工具.
4. 最终报告保留关键结论, 可选证据文件保留相应记录与关联, 完整调用日志继续单独保存.

包围框、原图尺寸、裁剪范围和坐标映射属于任务输入信息, 无需扩写进五库正文.

裁剪范围需要包含理解元素所需的上下文:

- 齿轮圆片: 完整外轮廓、中心区域及少量周围留白.
- 霓虹边框: 包含外侧光晕, 不能只截取发光线芯.
- 磨砂玻璃: 包含与背景重叠的区域, 保留透明、模糊和遮挡的判断依据.

全图概览用于确认位置、尺度和邻近关系; 裁剪图用于观察局部细节. 放大不会增加原图没有的信息, 模糊区域仍可能无法确定. 测量结果也不能自动等同于语义结论.

### 5.1 坐标、隔离与图像回读

- 使用原图左上原点的整数像素, 右、下边界不包含. 包围框必须非空且位于固定原图内; 留白扩展由程序计算并裁到图像边界. 无框时保持全图输入, 非法框返回明确错误, 不猜测归一化坐标.
- 保存原图哈希、尺寸、目标框、实际裁剪区域及偏移映射. 所有测量以固定原图像素为准, 不对显示缩略图或插值放大图取色.
- 复用 `ReferenceMeasurements` 的 crop/region_stats 能力, 每个 worker 拥有独立记录与预算. 只允许操作绑定原图, 工具不接收任意文件路径, 不读取兄弟报告.
- 裁剪必须以真实图像内容进入后续模型请求. 只有工具返回路径或 JSON 不能算“已经查看”. 新图像与新证据进入请求后, 才能作为该 worker 的提交依据.
- 统计保留区域、聚合方式和透明度处理策略. 区域均值不能称为分割后的物体颜色, 白底合成值不能直接称为材质原色.

### 5.2 证据随报告交接

采用可选的版本化 `evidence.json` 与其引用的裁剪文件, 不向 F/R/M/S 增加必填字段. 证据文件包含原图身份、具体测量记录和 F/R 到证据 ID 的关联; 只把影响最终结论的依据打入交付包, 全量工具事件留在运行日志.

关联必须引用当前任务实际生成且已提供给模型的证据, 并能定位原图区域、方法版本、结果和限制. 不接受模型自行构造的“测量事实”. 来源命名空间转换及 F/R 合并时同步重写关联; 一条合并观察可以保留多个来源证据. 草稿撤回后不能留下失效的当前关联.

报告发布、按草图读取、移动后读取和生成输入固定都必须识别该可选文件及关联制品. 路径限定在包内, 校验原图哈希和制品身份; 生成输入摘要覆盖实际携带的证据内容. 旧包没有证据文件时沿用旧读取行为. 明确区分“无附带测量依据”和“证据文件损坏”, 损坏或缺失的已声明证据不能静默忽略.

## 6. 分析与生成的交接

生成模块需要保持已确认的视觉要求, 例如同心、周期排列和整体风格. 具体公式、实现细节和未确认参数可以在渲染中调整.

若发现选定机制不适用, 应反馈换方案的需求. 不将尚未验证的机制、公式或目测参数当作不可修改的事实.

分析报告提供方向和约束, 同时为后续迭代留下空间.

## 7. 实施顺序与完成条件

### 第一阶段: 内容要求与验收规则

一起调整 skill、默认角色说明与程序的验收规则, 落实第 4 节. 维持既有五库对象字段和默认单批调度, 不顺带修改上游 SDK、模型配置或网络重试策略.

完成条件: 背景备注无需机制; 必要 F/R 缺失仍被发现; 普通变量不误拒绝; 已登记引用和备选正文一致性仍被保护; 撤回及依赖修复能够原子成功或完整回滚. 老报告和已有公开入口继续兼容.

### 第二阶段: 目标裁剪与基础观察工具

完成第 5 节的固定框输入、图像回读、测量工具和证据交接. 新参数采用带默认值的 keyword-only 形式, 文档列出新增的可选入口; 保留原有调用方式.

完成条件: 能在真实发送的多模态请求中检查全图和裁剪; 越界、证据伪造、任务串用被拒绝; 移动报告包、按草图取材和生成固定输入后仍能回查依据. 工具按具体疑问调用, 不要求每条特征都执行测量.

### 第三阶段: 上下文成本与扩大验证

分步试验增加显式的紧凑上下文选项, 与保留完整历史的对照方式并存. 阶段请求携带权威草稿修订、必要观察、候选目录、当前问题和已选证据; 机制/草图正文可按 ID 读取. 每轮不再重复完整旧目录与已被草稿吸收的工具结果.

裁减按完整请求/响应单元进行, 保留继续执行所需的工具调用配对与服务方推理协议. 不用额外模型摘要调用压缩历史, 不截断尚未处理的响应, 不重放已执行工具. 完整过程仍记录在审计日志. 遇到无法安全裁减的历史时保留完整材料并记录原因.

完成条件: 离线多轮行为测试证明能回读旧正文、保留未知项与证据、维持修复和完成门禁; 可重跑的对照驱动记录请求量和质量指标. 真模型效果尚无数据时明确保留“未验证”, 不自动切换默认流程.

## 8. 验收与对照协议

同时检查:

1. 关键观察是否可靠, 未经确认的内容是否如实保留为未知.
2. 实现路线是否清楚, 是否给生成阶段留下合理迭代空间.
3. 引用是否完整, 局部修改是否保留已有有效成果.
4. 调用次数、token 和耗时是否可接受.

提交通过率只覆盖其中一部分, 不等于视觉分析正确或生成结果通过验收.

### 8.1 工程验收

- 补充保护第 4、5、7 节可观察行为的无网络测试, 包括原子撤回、失效引用、旧包兼容、证据移动/篡改、坐标回映和请求中的真实图像.
- 在应用目录执行 `make test`、`make lint`、`make repository_check`, 校验更新后的 skill. 修改实际图像反馈或生成交接时执行 `make integration_test`, 保留失败日志并区分环境问题.
- 至少验证一份精简报告和证据能被生成入口读取, 完成代码渲染与预览回读的契约链路. 模拟模型与浏览器结果不替代真实模型和用户视觉验收.

### 8.2 效果验收

预先固定三类样本: 重复缺口的轮廓、带外侧光晕的发光边框、与背景重叠的半透明表面. 每项保存原图哈希、目标、框、用户要求、方向和人工核对项; 不确定真值明确标为未知, 不把当前模型报告作为标准答案. 可用确定性合成图验证像素与输入契约, 与真实样本的视觉评估分别记录.

按两个独立对照比较, 每条件至少两次独立运行并交错顺序: 相同优化内容规则下比较“仅全图 / 全图加裁剪与按需工具”; 相同图像和工具条件下比较“完整历史 / 紧凑上下文”. 固定模型、配置、调用/修复预算, 失败和超时同样记录, 不覆盖旧制品.

记录首次及最终提交结果、关键观察错误/遗漏、无依据精确断言、必要条件丢失、F/R/M/S 数量、正文长度、请求/修复次数、输入/输出/reasoning token 与耗时. 缺失的 usage 记录为缺失. 成本只在质量与完成程度相当时比较; 失败早退出不算效率胜出.

少量配对运行只能支持逐例观察. 默认切换的前提是关键视觉要求无新增遗漏、无证据或引用回归, 且同质量产物的累计输入量下降; 不从工程测试推断准确率或普遍节省比例. 真实付费模型批量试验在驱动和样本准备完成后单独记录执行范围, 本轮不得为填满表格开展无上限调用.
