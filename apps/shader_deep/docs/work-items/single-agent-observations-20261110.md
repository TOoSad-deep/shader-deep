## 已确认的首版目标

使用一个原生 Deep Agents 分析角色, 对整张参考图提交上下文、元素 E、特征 F 和关系 R. 单视角不限制元素数量; 同一份报告需要支持多个 E 及跨元素关系.

先跑通读图、结构化提交、程序校验、文件保存与重新读取, 再依据五图校准结果改进. 多视角、M/S 机制与草图规划留待后续; 本轮不增加编排、探索、整合等多个业务角色, 不引入新的调度框架.

首版观察提交不要求模型维护证据关联、候选机制、草图选择或局部备选. 不删除已保存报告中的历史内容; 旧完整五库包与生成消费者的兼容需单独检查.

## 最小实施方案

1. **确定观察提交与归一化.** 模型在 E 下填写 F, 全图登记 R 及合法参与项; 程序生成保存格式中的 `feature_ids`. 同一批本地 ID 唯一, 结构引用可在本场景内解析. 上下文、未知项与缺口保持简短, 不复制模型历史.
2. **接入一个原生观察角色.** 复用模型适配、原图字节固定、请求级材料提供与 SDK 工具循环. 业务提交通过校验才成为产物; 普通文本结束不计成功. 使用有限模型调用预算, 业务错误在同一会话修正.
3. **提供短规则与按需样例.** 核心口径随角色提供, 五图文字样例按需读取. 显式预置到 SDK 文件状态, 不把本地文件存在当成模型已经能够读取, 也不默认向每次请求附送全部样例图.
4. **发布观察包.** 复用文件快照、固定原图与发布校验能力, 由程序生成树状 README. 观察完成与生成就绪分别表达, 无合法提交时保留失败诊断, 不发布伪造的空成功包.
5. **验证公开入口与兼容.** 保留 `run_analysis` / `run_analysis_task` 的公开入口及参数位置; 新参数按应用约定处理. 同步 CLI、运行配置和报告协议说明. 旧槽位/并发配置的迁移需要明确行为, 不静默改变含义.

建议新增的观察协议名为 `scene_observations_v1`; 这是实施命名建议, 具体字段在实现时结合消费者确定. 观察阶段正文可由 `elements.json`、`features.json`、`relations.json` 承载, 配合 manifest、原图和导航. M/S 后续规划时再形成完整五库产物, 不用空 M/S 假装已经可以按草图生成.

## 验证与完成条件

- [ ] 结构合同: 多元素 F 的主要归属在保存与读取后保持一致; 跨 E/F 的合法 R 可接受, 悬空及错误类型引用被拒绝.
- [ ] 原生角色: 模拟模型能通过真实提交工具交付; 无提交、非法提交、调用预算结束与中断保留真实状态.
- [ ] 材料: 原图和要求进入实际模型请求; 规则及示例文件在角色后端中可读取.
- [ ] 报告: 新观察包可重新读取, README 来自同一数据快照; 新阶段与旧完整五库包的读取语义清楚.
- [ ] 应用检查: 按改动范围运行 `make test`、`make lint`、`make repository_check` 与 diff 检查.
- [ ] 五图校准: 固定模型、输入、预算与规则版本, 分别记录遗漏、过拆、重复、关系错误、无依据成因以及调用、修复、耗时和 token.

五图评估按观察含义和已确认粒度边界人工核对, 不只比较 ID、条数或措辞. 结构校验、真实模型稳定产出与视觉分析正确性分别记录.
