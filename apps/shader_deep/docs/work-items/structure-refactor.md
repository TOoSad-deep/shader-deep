## 已知问题与边界

1. **锁文件漂移属于重构前问题.** 当前仓库 SDK 元数据为 `deepagents 0.7.14`, 应用锁文件仍包含 `0.7.13`. 使用起点提交中的应用 `pyproject.toml`、`uv.lock`, 对同一 SDK 源码执行 `uv lock --check --offline`, 同样要求更新锁文件. 本次恢复并保留原锁文件, 未升级依赖. 新环境的 `make sync` 不能被当作已验证成功; 后续需单独处理依赖同步并重新验证.
2. **真实模型质量尚未验证.** 无网络模型夹具和浏览器测试不能证明模型语义整合、视觉效果或 token 收益.
3. **完整日志没有全部进入 Git.** 本文件只保留必要的验证摘要与输入指纹; 大图、运行制品和完整模型 trace 继续按原有方式管理.
4. **兼容层尚未移除.** 保留是本次已接受的范围, 后续清理需先核对真实调用和历史数据需求.

## 本轮检查发现的问题

- 首次 `make check` 中, 同一模型响应先请求 `stop_analysis`, 再请求提交初稿, 仍偶发产生初稿. 检查已安装的工具节点实现发现默认会并行派发工具, 会话锁只能串行写入而不能保证声明顺序. 延迟停止工具 30ms 后可复现失败. `runtime/runner.py` 现对单个角色图设置 `max_concurrency=1`, 原断言保留并增加延迟条件; 探索工作流的外层线程池不受影响.
- 后续 lint 检出旧 `context/__init__.py` 转发文件的一行语法错误. 删除误留下的残行, 并补充旧包真实导入及导出身份测试. 这属于之前结构迁移的遗漏, 不能用此前某轮测试通过覆盖.
- 最初的检查失败和延迟复现结果一并保存在证据附件中. 最终通过表示修复后的具体工作区通过, 不抹去失败历史.
