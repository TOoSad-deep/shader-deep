# 01 输入绑定与上下文实施方案

日期: 2026-10-03.

## 状态与目标

状态: 待实施. 本文只规定第一个分支的工作, 不代表分支、类型或代码已经创建.

目标: 将调用方明确选择的五库草图及可选局部备选, 固定为一个新生成任务和可逐轮复用的模型材料. 本阶段交付的准备入口只装配输入与上下文, 不调用模型或浏览器.

共同契约以[生成整体架构](../generation-architecture.md)为准; 五库字段沿用[五库数据设计](../analysis-five-libraries.md). 本文不另建一份执行状态或机制选择模型.

## 关键接口与结果

准备输入包括报告目录、草图 ID、可选备选索引、本次执行要求、可选基线和渲染配置. 单元素任务明确背景语义与输出尺寸; 报告模式默认采用固定原图尺寸, 显式尺寸可覆盖. `region` 继续作为文字范围, 不推导裁剪框.

`TaskRecord.generation_binding` 默认 `None`, 保持旧任务构造方式. 绑定只记录报告快照引用、内容身份、元素与草图 ID、可选备选索引; 有效方案从快照派生. 实施时说明公开记录字段的兼容性扩展, 核对现有调用与序列化.

`PreparedGeneration` 是工作流私有结果, 持有本轮目录、黑板、任务 ID、固定文本与图像材料、配置. 准备阶段分配唯一 `run-*`, 02 在该目录写候选及 `run.json`; 不能在接入执行时再创建第二个运行目录.

内容身份覆盖 manifest、五库正文和原图, 只计算一次并注明范围; 原图 hash 单独保留. 报告副本位于 `inputs/report/`, 可选基线代码与已有预览位于 `inputs/baseline/`. 固定材料在模型启动前加载进内存, 每轮不再回读原始用户路径.

执行方案明确采用 `selected.choices` 与 `selected.composition`, 带上选中备选的条件和理由. 全部公共 gaps 与 open_questions 保持可见, 必要正文按引用补齐. 原始默认方案、未选备选和作为条件依据的机制不自动变成本次采用方案.

目标要求来自调用方, 不从外部报告猜测原始用户要求. 已有目标、任务和候选按原身份保留; 固定文件映射由本轮材料解析, 不通过覆盖旧记录来替换路径.

## 按顺序实施步骤

### 1. 落实任务绑定

在领域层定义绑定记录, 给任务增加默认空绑定, 并将必要校验接入既有登记边界. 领域层不读取文件, 不依赖模型框架.

完成条件: 旧任务仍能按原参数构造和登记; 新任务可序列化其方案来源, 同名草图 ID 由报告身份区分.

### 2. 捕获本轮输入

复用运行目录创建和报告包校验, 保存本轮副本后在副本上解析显式选择. 一次加载固定原图、方案正文以及存在时的基线代码与预览. 重新读取持久副本时沿用相应校验.

完成条件: 本轮材料可以追溯到副本与内容身份; 修改原报告或原基线文件不会改变已经准备好的材料. 缺少草图、有效引用或必需文件时在执行前明确失败.

### 3. 装配目标、任务和准备结果

先确定执行要求、背景、尺寸、目标与基线, 再登记新任务. 使用既有黑板函数接收返回的新状态, 将绑定和固定材料汇入私有准备结果.

完成条件: 调用方可检查任务和待执行材料, 原目标与基线记录保持原身份; 准备过程没有创建模型客户端、渲染线程或浏览器.

### 4. 接入逐轮上下文

让 Context Builder 复用准备结果中的固定要求、原图和方案, 从当前黑板刷新候选与错误. Middleware 继续通过请求级 `override` 注入, 保留有效历史与工具调用配对.

优先用私有装配 helper 保留 `build_generation_context` 的公开签名; 若确需新增材料参数, 仅作带默认值的关键字参数扩展, 在交付说明中明确告知签名变化并核对调用方.

完成条件: 连续两轮请求都含同一固定方案和真实图像内容, 第二轮能看到新增候选; 固定报告不重复累加到持久消息历史. 无绑定任务继续使用现有路径.

### 5. 收口交接说明

说明准备结果如何交给 02, 标明目录、材料与状态各自的归属. 仅更新实际落地部分的维护文档, 不提前宣称报告到生成已经贯通.

完成条件: 02 可以接入已准备目录和材料, 无需再设计一套输入协议; 分支改动与验证记录可单独审查.

## 最小必要验证

优先扩展现有报告与上下文测试, 用少量组合场景保护可观察行为:

| 场景 | 必须观察到的结果 |
| --- | --- |
| 默认草图及一项显式备选 | 实际请求采用正确的 selected 内容, 保留条件、引用正文和公共未知项 |
| 准备后改动原文件, 再装配两轮上下文 | 固定材料不变, 新候选正常进入请求, 历史不累积报告副本 |
| 无效选择或缺失必需输入; 旧任务无绑定 | 前者在准备时失败, 后者保持原有构造和上下文行为 |

复用原报告引用校验与旧任务测试, 不为每个字段新增镜像断言. `partial` 不作为统一拒绝条件, 有效引用与所需材料才是入口检查对象.

实现中先运行改动相关的无网络测试, 分支收口在应用目录执行 `make test`、`make lint`、`make repository_check`. 单纯新增准备与材料装配 helper 无需浏览器; 若实际改动了既有图像反馈链路, 按应用约定运行现有 `make integration_test`. 本阶段不安排真实模型实测或新增集成测试平台.

## 完成与明确不纳入

完成是固定方案已经成为可检查的生成请求材料, 且旧任务兼容. 单方案生成闭环要等 02 完成后才能宣称交付.

不纳入模型执行、工具新增、自动草图选择、ROI 标注、视觉评分、持续文件监控、崩溃恢复和独立状态账本. 保留现有引用规则, 不为简化实施取消正常校验.
