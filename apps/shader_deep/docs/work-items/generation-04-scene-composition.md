# 04 多元素整图组合实施方案

日期: 2026-10-03.

## 状态与目标

状态: 待实施. 本文只规定第四个实施分支, 未创建分支或调用模型. 开始前按 03 的实际来源记录、选中候选与输入捕获接口复核, 不提前泛化整图系统.

目标: 将两个已明确选定方案和代码的元素, 按用户组合目标交给现有生成 Agent 整合为一份完整单 Pass GLSL, 渲染后交付整图候选. 默认按原图保持布局与遮挡, 用户有明确调整要求时覆盖该约定.

共同边界以[生成整体架构](../generation-architecture.md)为准. 两份元素代码是模型整合的输入材料, 整图成功与视觉验收均需要新的运行证据.

## 分支与依赖

- 分支: `TOoSad-deep/repo/generation-scene-composition`.
- 前置: [03 多方案比较](generation-03-plan-comparison.md)完成并合并, 用户能够明确选定元素方案及其候选.
- 从前序已合并代码建立分支, 核对当前工作区、候选格式和来源记录, 保留其他未提交工作.
- 首轮只做两个元素的简单组合; 元素输入可来自两次独立生成或比较, 但必须来自同一完整参考图并有明确选择.

## 范围与文件

下列源码路径相对于 `apps/shader_deep/`, 尚未存在的文件是拟新增项.

| 路径 | 本阶段职责 |
| --- | --- |
| `src/shader_deep/domain/scene.py` | 定义精简组合计划和元素来源, 无文件读取或渲染逻辑 |
| `src/shader_deep/workflows/scene_generation.py` | 捕获组合输入、登记整图任务并复用既有生成闭环 |
| `src/shader_deep/agents/generation/context.py` | 将组合要求、两个元素的选中方案与代码装配进请求 |
| `src/shader_deep/infrastructure/storage/generation_inputs.py` | 复用捕获规则固定选中代码、已有预览及必要报告材料 |
| `src/shader_deep/api.py` | 导出整图组合入口, 保留原有单方案入口 |
| `tests/unit_tests/`、`tests/integration_tests/test_generation.py`、`README.md` | 最小组合行为覆盖、浏览器验证与调用说明 |

不新增角色、渲染工具或 shader 拼接器. 组合计划随整图 `run.json` 保存, 来源材料置于该运行的 `inputs/` 下, 候选文件继续沿用现有布局.

## 最小输入与输出

组合输入包含完整原图、用户整图目标、两个元素输入、布局和前后遮挡约定、背景要求及固定渲染条件. “保持原图布局与遮挡”就是有效约定, 不要求用户先给每个元素标注坐标和层级. 工作流只装配约定, 由模型结合原图落实代码; 原图和用户要求存在影响结果的冲突时再澄清.

每个元素输入包含报告身份与元素/草图/备选来源、源运行与候选引用、选中 GLSL 及可用预览. 来源通过前序记录解析, 不只提供两个失去来源的文件路径. 输入选择指向实际已选代码, 不能用模型最后输出的另一段代码代替.

`ScenePlan` 只保存本轮组合所需的目标、布局、遮挡与元素引用; 必要时增加一个小型元素输入记录. 不预建场景树、材质系统、通用图层协议或未来多 Pass 类型.

原图及所需元素材料在模型启动前固定. 两个源运行保持原样, 其候选作为输入引用, 不能直接成为新整图会话的可选择候选. 多元素来源由组合计划承载, 不强塞进单方案的 `generation_binding`.

输出沿用 `GenerationOutcome` 和整图运行目录: 完整 GLSL、真实预览、组合来源、模型自检、偏离与停止原因. 最终代码必须来自整图会话实际渲染并选中的候选.

## 顺序实施步骤与完成条件

### 1. 接收并固定两个元素的组合计划

从用户明确选定的来源记录解析输入, 复用报告和候选读取能力, 检查两个元素对应同一完整原图, 并捕获本轮所需代码、预览与方案材料. 未指定布局改动时采用保持原图的约定, 不增加专门的标注或场景规划步骤.

完成条件: 模型调用前已有可追溯的组合计划和完整原图, 两个元素各自的实际代码与有效方案可读, 不依赖运行期间重读用户原始路径.

### 2. 建立整图任务并装配请求

登记新的整图目标和生成任务, 明确需要保留的元素特征、位置、遮挡及背景. Context Builder 注入完整原图、组合说明、两份选中代码和必要方案正文; 有来源预览时一并提供以解释代码效果.

完成条件: 捕获的模型请求同时包含两个元素的有效方案、实际代码与整图要求. 使用请求级装配, 不把材料重复追加到持久历史, 不自动加载各源运行所有候选.

### 3. 复用同一个生成角色整合和渲染

生成 Agent 负责协调函数命名、坐标、颜色、遮挡和背景, 产出一个完整 `mainImage`. 它可以重写元素实现来满足组合要求, 但需在自检中说明关键偏离; 程序不通过字符串拼接独立 shader 来形成结果.

沿 02 的受限工具和会话闭环渲染、回读、修正或结束. 不增加元素级子 Agent, 不将两个元素分别渲染后交给新的 layer compositor, 不改变现有 GLSL ES 3.00 单 Pass 契约.

完成条件: 至少一次实际整图候选经过渲染和后续预览回读; 成功选择、主动受阻、预算耗尽或运行异常均按既有结束语义交付, 不把单元素成功当作整图成功.

### 4. 交付整图结果并记录人工反馈

在整图运行记录中保存组合来源与已选整图候选, 提供代码、预览和自检入口. 检查布局、遮挡和保留特征是否符合用户要求, 明确尚未实现或偏离的部分.

完成条件: 一个两个元素的简单样例能够从已选输入走到完整整图产物. 用户视觉反馈单独记录; 用户要求修改组合目标或输入选择时创建新任务, 不覆盖源元素运行.

## 最小必要验证

- 复用报告和生成夹具, 用一个双元素案例检查来源解析、两份实际代码及组合说明进入请求, 整图输出关联到新会话的选中候选.
- 对新增输入边界补一个缺少选中代码或来源不匹配的失败案例, 确认模型未开始且错误可定位. 已有报告引用、工具权限和额度测试继续复用.
- 在现有真实浏览器测试中增加或复用一个简单重叠图形案例, 检查完整单 Pass 代码可渲染、预览回读与最终代码交付成立; 不以该案例声称真实模型已理解复杂遮挡.
- 分支收口在应用目录执行 `make test`、`make lint`、`make repository_check` 和 `make integration_test`. 组合会改变图像与代码上下文, 保留浏览器链路验证.
- 明确图片、模型和使用条件后, 用两个已选元素完成一次真实组合, 记录布局与遮挡的人工查看结果. 不建立通用视觉评分基准或全参数矩阵.

## 完成与不纳入

本分支完成意味着明确的两个元素输入可被整合为可追溯、可渲染的完整 GLSL, 失败也能如实交付. 模型自检和程序完成不能代替用户视觉接受.

不纳入自动拆分原图、全场景规划、自动挑选元素方案、跨图素材组合、图层合成器、多 Pass、纹理/反馈缓冲、复杂全局光照和像素级背景锁定. 单 Pass 无法满足具体效果时保留受阻原因, 另行讨论能力扩展.
