## 问题与范围

[前一轮 Schema 修复](analysis-diagnostic-20261025.md)恢复了完整文本, 但仍有引用标记、候选选择、方案说明及有限修复失败. 用户提出让单个子 agent 分步维护成果, 要求写对应 skill 并单独测试.

本次使用原探索角色执行器、模型传输、两次修复额度、TaskStore 与最终领域校验, 增加随包 skill 和显式分步试验入口. 不启动主 Agent、兄弟 worker 或整合. 原默认 `run_exploration` 签名和行为保留.

## 已实现

- 探索 skill（历史路径 `src/shader_deep/resources/worker_skills/independent-exploration/SKILL.md`, 已删除）: 观察、机制关联、草图、检查与局部修复. 包含结构示例, 变量与引用的命名区分, 备选生效选择和正文的一致性规则. 文件完整注入试验 worker 的系统请求, 保存内容指纹; 不是仅传一个路径.
- 试验入口（历史路径 `src/shader_deep/experiments/exploration_skill/runner.py`, 已删除）: `baseline` 使用现有角色; `skill` 追加完整 skill、保留整份提交工具; `staged` 加载同一 skill 并提供分步工具. 正的调用上限是试验前置条件.
- 草稿（历史路径 `src/shader_deep/experiments/exploration_skill/draft.py`, 已删除）: 特征/关系与机制每批最多四项, 一次保存一套草图. 同 ID 修正保留其他对象, 未改变内容不增加进展; 校验与持久化成功后才更新内存. 缺口清单显式替换.
- 分阶段草稿允许暂时没有候选或未覆盖全部观察; 不允许悬空引用、错误参与者和非法草图选择. 完成时重新执行原来的完整 `validate_exploration`, 不降低最终标准.
- `TaskStore.publish_draft` 在同一锁内核对活跃 attempt 并发布不可变草稿版本. 草稿不设置成功状态或结果路径; 已终结任务不能继续写入. 最终报告由程序从草稿组装, 模型无需重新输出全文.
- 修订号和阶段在实际发送前登记. 当前响应内刚写入的草稿不能立即越过检查推进阶段或结束, 后续请求须收到最新回执.

本实现仍让模型提出本任务内的 ID, 程序校验、登记并返回目录; 没有声称已实现自动分配 ID. 草稿版本支持审计和当前实例的局部修复, 不支持崩溃后恢复模型历史或从旧 attempt 自动继续. 工具只读当前草稿, 没有任意文件或兄弟报告读取能力. 保留现有正文引用规则, 包括对公式变量命名的限制, 以隔离 skill 的作用.

## 真实对照协议

制品目录: [runs/exploration-skill-20261026](../../../../runs/exploration-skill-20261026/). `run_trials.py` 是本轮可重跑的独立 worker 驱动脚本, 遇到已有试验目录会拒绝覆盖.

- 使用已授权的齿轮 PNG, 固定最左上绿色圆片、范围、用户要求和探索方向, 各组输入哈希一致. 不用主 Agent 重新选目标或方向.
- 模型沿用当前 OpenRouter 配置, 三组共用相同输出/请求预算, 每任务最多 24 次逻辑调用、两次修复. 每个试验一个新进程、新 TaskStore 和上下文, 不自动重派.
- 顺序为 `baseline → skill → staged → staged → skill → baseline`, 每组两次; 第二轮反序, 减少单一顺序与时段的混淆. 每任务 600 秒外部观察上限, 超时单独记录.
- 本轮进程内关闭 LangSmith. 不修改 `.env`, 不上传其他图片或私人资料.
- 记录首次提交、最终提交、拒绝原因、调用/修复次数、token、耗时、F/R/M/S 数量及正文. 程序接受不代表视觉分析正确, 未执行 Shader 生成或渲染.
- 三组均基于已修复的 OpenRouter Schema. 这批单 worker 数据不与之前主 Agent 自动生成方向的 5/9 直接合并.

## 初版结果与针对性修订

| 条件 | 通过数 | 两轮逻辑调用 | 两轮总 token | 两轮耗时 |
| --- | --- | --- | --- | --- |
| baseline | 0/2 | 3、3 | 26469、21658 | 164.164、118.587 秒 |
| 初版 skill, 整份提交 | 1/2 | 3、3 | 30542、27242 | 173.965、137.338 秒 |
| 初版 skill + 分步工具 | 0/2 | 7、5 | 260602、98162 | 278.903、96.234 秒 |

baseline 重现了 R0 变量误判、关系参与者引用错误、方案正文与采用机制不一致、候选选择越界. 初版 skill 避开了 R0, 仍在完整报告里出现机制正文绑定本图观察、备选替换非默认目标、裸 ID 和未覆盖关系的问题; 一轮经过两次修复后提交成功, 有 5 个特征、4 个关系、7 个机制和 2 套草图.

分步组两轮都已成功保存观察, 但随后多次调用 `save_mechanisms` 时只提供 bindings、mechanisms 为空. 被引用的 M 根本没有登记, 所以原子校验拒绝保存. 有效观察仍保存在草稿版本中, 任务最终失败并如实保留, 没有因分步工具而跳过引用校验.

根据这项重复失败, 修订 skill 的机制步骤: 先核对机制目录, 用包含 id/name/method 的完整参数示例登记机制, 再依据回执使用 ID; 明确关联失败时该批定义也没有保存. 这是对已有方法的具体澄清. Python 实现、工具、校验、预算与输入均保持不变, 两轮复测与初版的 Python 文件哈希完全相同. 初版 skill 原文保留在第一批的 `skill-snapshot.md`, 不覆盖先前证据.

## 结论与未覆盖项

- 目前 skill 与分步工具已经可执行, 修订版在本样本两次成功提交. 两份报告有完整观察、候选机制及各一套草图, 没有单字符占位问题.
- 一张图、每组两次不能证明普遍成功率. 修订版只追加了 staged 条件, 未重新跑最新 skill-only 条件, 不能把初版 1/2 与修订版 2/2 当作严格的同版本效果比较.
- 没有进行主 Agent + 三视角 + 整合的整体接入验收; 默认流程仍沿用原探索角色. 先控制阶段上下文和推理成本, 再增加样本及集成验证.
- 未生成或渲染 Shader, 未做用户视觉验收. 两份接受报告对凹槽/齿数的判断仍有分歧 (约 8 与约 6), 结构提交成功不能解释为分析准确性已提高.
- R0 裸 ID 误判等原有校验规则仍存在; skill 提供了命名规避方法, 没有声称修复这些规则. 默认任务级两次修复额度也未改变.

最终资源文件为修订版, 初版与修订版的摘要、skill 原文、源文件哈希、运行回执和 wheel 分别保存在两个制品目录. 全部 8 轮的固定输入、模型和配置已核对一致. 568 项离线测试、lint、skill 格式检查与安装包内容检查均通过.
