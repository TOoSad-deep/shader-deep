# PNG 转 Shader 流程优化实施

实施依据为[流程优化设计](workflow-optimization-design-20261125.md)。分支从 `18571fbe` 起步。

## 运行与制品

1. `start_workflow` 捕获参考 PNG，依次执行分析、规划与参考侧标准草拟。规划报告阻断性观察矛盾时，程序从固定旧观察发起一次定向复核。门禁 A 确认方案和标准，待选局部试验给出明确目标区域和上下文。
2. 生成角色输出 GLSL，并可为连续量提供 `ParameterSpec`。优化器固定代码、尺寸及时间，复用同一个 WebGL2 程序读取像素。保护区域相对基线逐像素限制漂移。正式胜出候选回到生成角色的下一次实际请求，随后才可选择。
3. 工作流评审采用冻结的 V2 成对证据与独立视觉角色。图外角色栏用于送模，底层 PNG 用于原始测量和身份校验。诊断读取正式评审、观察、规划、参数与历史记录，按 `source_ref` 返回问题和修订靶点。
4. 控制面执行有界重采和定向调参，将状态及历史保存在 `workflow.json`。门禁 B 审核本轮候选、历史最佳、回归和诊断，可以晋升局部片段、接受整图、修订、改派、回滚或归档。CLI 和本地网页共用同一工作流入口。

每轮的参考、成功渲染及关键拐点登记在独立的 `vista/` 图库中，按内容哈希复用 PNG 和 GLSL，并保存实际生效的 `render.uniforms`。生成角色可按记录回看；已用独立项目的 `VistaStore` 验证 PNG、GLSL 和参数可回读。业务侧的评审、诊断、历史选择与最优候选通过不可变版本关联到这些记录。记录格式见 [VISTA 设计](vista-minimal-image-records-design-20261113.md)。

门禁 A 可以直接生成、依次批准最多两个局部试验，或在同一标准下并行比较两条路线。每个局部都需人工晋升；对照可直接选择已有正式评审的候选。CLI 和网页均可看参考测量及候选的成对像素差。观察修订追踪所影响的来源、旧必查项及方案依赖，保留适用的目标、机制、标准与已验证片段。

评审明确区分同一张图上能补取的证据，以及需要新时间帧或新上下文的证据。前者每个候选自动扩窗或新增成对采样一次，后者交门禁 B 处理。全局同时约束大轮、逻辑请求与累计输出 token，支持按部署真实上下文上界额外约束输入与输出总量。门禁、阶段、产物和预算通过 `workflow-trace.jsonl` 关联。操作合同见[运行说明](../../src/shader_deep/workflows/optimization_workflow/README.md)。

## 局部数值对照

本地 Chromium 使用仓库中的两张 PNG、相同 GLSL 和相同指定区域，比较人工指定基线参数与优化结果。磨砂图使用历史修订 GLSL 的前圆亮度参数。发光图用固定圆与衰减公式检验中央光晕。保护区零容差，计算在 1280 × 720 原图坐标中进行。

| 参考图 | 起始误差 | 优化后误差 | 实际试验次数 | 数值优化用时 |
| --- | ---: | ---: | ---: | ---: |
| 磨砂叠圆 | 0.039746 | 0.005369 | 25 | 0.184 秒 |
| 发光图的中央光晕 | 0.234452 | 0.019781 | 48 | 0.371 秒 |

本地记录位于 `runs/workflow-optimization-local-benchmark-20261125/`。时间包含本次优化会话与正式 PNG 导出，取单次运行。对照调用模型次数为零，无法用该次实验估计真实生成 token 节省量。磨砂叠圆离线回放中，两个前圆区域的实测亮度均为 219，空背景为 229，差值均为 −10。测试替身收到真实的测量工具结果并按预设提交观察。

真实生成的成对评测入口为[生成对照脚本](../../scripts/benchmark_generation_optimizer.py)。在应用目录运行以下命令，两个 `--case` 分别提供正式规划包、草图 ID 与原图 ROI（也可填 `full`）。脚本分别从同一规划生成两次，记录各自的最终候选、ROI 误差、耗时、服务端 token 回执和优化器的实际使用情况。

```sh
uv run --no-sync --env-file .env python -m scripts.benchmark_generation_optimizer \
  --case /path/to/frost/planning S1 500,250,575,310 \
  --case /path/to/glow/planning S1 full
```

### 第二轮代码审查修复

- 定向观察沿用固定原图的既有测量锚点。版本级联按测量内容比较，规划保留无关目标的选择与机制，同时允许删除失效备选及更新组合引用。标准合并保留无关检查，纳入新容差。首次整理因非法观察来源或越界矩形受阻时，可在原预算内重试。
- 门禁 B 从落盘评审读取重大问题与待补证项。共用同一预览图的候选仍按各自 ID 展示评审，验收前须切回当前候选。诊断可读取备选机制正文，结构修订同时收到人工备注、诊断靶点和保护信息。已匹配检查缺少保护矩形时，自动调参交人工门禁并显示原因。回滚优先级和回归比较按当前标准及范围确定。
- 参数合同会提前拒绝带非法限定符或保留标识符的声明。优化器单独记录起始误差已达阈值的情况。渲染会话保留首个失败原因，并读尽当次 WebGL2 错误。VISTA 在硬链不可用时可原子发布，旧报告的参数化基线随运行固化。
- 已验证片段按评审帧回流。同一批连续局部试验沿用首项晋升时的评审帧。独立对照新增可选关键字 `verified_snippets` 与 `model`，两侧共用兼容片段，评审复用有原图身份的测量锚点。生成会话可显式关闭锚点继承，并在工具上限内调整单次搜索预算。

新增跨阶段用例通过真实 Chromium，从诊断指定未绑定观察 ID 的已声明参数，自动修正候选左半区颜色，并核对右半保护区像素逐字节一致。改良候选在复评后进入门禁 B，由人决定是否交付。各模型回复均由本地测试替身提供。

本次 `make check` 通过全部 567 项离线单测、仓库检查、Ruff 规则与格式检查及 ty。用本机 Chromium 执行的 `make integration_test` 通过最小渲染检查及全部 33 项集成测试。真实模型效果和用户视觉验收仍待单独验证。

### 分支对照审查后的补修

- 并行生成或评审遇到暂被在途请求预留的 token 时，等待其结束再判断可用额度。有效回执返还差额。无回执或传输失败仍保留已预留额度。
- 门禁 A 冻结前校验每个成对采样框。参考图或候选图一侧越界时，操作者可以留在同一门禁修正坐标。回归测试核对了冻结文件、状态和生成调用，并验证贴齐画布边缘的合法坐标能完成正式评审。
- 门禁 B 从所选候选恢复修订分支，连败升级沿这条分支累计。默认回滚在原比较范围内优先考虑评审证据已补齐的候选。数值误差仅用于同一次优化且同一帧内的并列候选。
- 带角色栏的全图和局部视图保留原图适用的颜色块及透明效果，供模型按原色彩空间查看。原始 PNG 和归档复核仍使用各自固定的文件字节。

本次 `make check` 通过 576 项离线单测、仓库检查、Ruff 规则与格式检查及 ty。`make integration_test` 通过本机 Chromium 冒烟检查和全部 33 项集成测试，模型调用使用本地测试替身。

## 2026-11-25 真实模型端到端验证

通过正式 CLI 及 OpenRouter 的 `z-ai/glm-5.3-flash`，在真实 Chromium/WebGL2 完成一张 128 × 96 深蓝底橙圆的观察、规划、六维标准整理、生成、独立盲评与双产物交付。测试操作者在门禁 A 拒绝单字草稿，重拟后选定 S1，冻结六维八项可从单帧评价的要求。门禁 B 对照开跑前保存的像素、几何标准接受该测试样例。跨帧条件另在交付后以同一渲染入口核对。

实测暴露并修复了两处服务适配问题。OpenRouter 会在带结束标记的最后一个 choice 内同帧回传累计用量；每条流现在独立保留并在正常结束时结算。OpenRouter 的严格工具解码会把非空校验模式 `\S` 解释为整个字段只能填一个字符；普通模型和预算客户端现与原生观察客户端共用外发 Schema 适配，保留本地原有校验。标准整理要求逐维提交完整检查及来源，未冻结阶段可用 `retry-criteria` 复用正式上游制品。失败与被拒的草案均保留在运行记录。

完成运行 `run-ndouxonn` 含修复期间的标准重拟，共取得 19 次真实请求的用量回执，输入 166,189 token，输出 26,751 token。首次失败运行另计。候选首轮盲评无重大问题；全图 RGB 平均绝对误差为 0.07053（0–255），圆心为 (64, 48)，实测半径 23.9631 像素。两份交付 GLSL 在固定帧均逐像素匹配送审预览，另测 t=1 的像素也一致。本次正常生成选用常量，未触发诊断或数值优化。以上结果限于这一张合成图。

另外将已交付圆的红通道单独参数化，在隔离副本中把圆心红色从 244 改为 96，并由测试操作者指定调节目标。确定性优化器在本机 WebGL2 评估 16 次，圆心恢复至 RGB(244,144,64)，指定背景保护区逐像素不变。针对这份额外错色副本的真实模型诊断未运行，自动审批拒绝向外部模型发送该副本、代码及评审材料。数值恢复只验证了指定靶点后的寻优。本次本地运行材料位于 `runs/live-workflow-20261125-PfiHry/`，包括 `run-summary.json`、`delivery-check.json`、`local-numeric/result.json` 和正式工作流的 `delivery/`。

### 粉色圆盘真实样例

505 × 527 的 `pink_circle.png` 使用同一真实模型完成观察、规划、门禁 A、生成、盲评和诊断。测试操作者选定 S1，并在冻结前用原图测量区分左上小亮芯与右下较大的反光。首轮选中的第二个候选经本机 WebGL2 复绘，与正式送审 PNG 的 RGBA 像素完全一致。相对参考白底合成后的全图 RGB 平均绝对误差为 9.33（0–255）。11 项盲评给出 3 个重大问题及 4 个轻微问题，归因建议改写高光和缘带公式。

第二轮在产出新 Shader 前触及全局输出预算，状态为 `blocked`。21 次请求中有 20 次取得有效用量回执，已报告输入 368,693、输出 57,232 token；另外一次未确认请求保留了 32,768 个输出 token 的预留。两者合计达到 90,000 的上限。首轮最佳候选可独立运行，未进入人工验收交付。本地对照、正式盲评和复绘核验位于 `runs/pink-circle-live-20261125-oRFZti/`。

收到提高上限并续跑的指令后，在同一运行将输出上限从 90,000 调为 150,000，保留原来的 32,768 未确认预留。首先复用上次修订指令：右下反光改善，主体渐变却明显过浅，全图 RGB 平均绝对误差升至 15.52。回滚至首轮候选后，为补足曾耗尽预算且没有成功渲染的第二轮，仅将此运行的大轮次从 3 调为 4。观察、规划及冻结标准均沿用。

最后一轮的修订反馈包含在本机通过原图像素拟合的无纹理解析 GLSL，涵盖主体底色、双高光、缘带及软投影。真实生成角色采用了这些公式，正式候选与本机种子预览像素一致。误差降至 1.04/255，11 项独立盲评报告 0 项重大问题和 1 项轻微差异（左上高光略宽、略亮）。测试操作者在门禁 B 确认交付，`run-nfpsol7c` 的最终状态为 `completed`。两份 GLSL 在真实 WebGL2 上复绘，均逐像素匹配送审和交付 PNG。左上、右下亮芯面积分别为 403 和 1,689 像素，参考为 401 和 1,662。此次续跑新增 8 次请求，已确认输出增量为 11,948 token，最终尚余 48,052 个可用输出 token。续跑后的原图对照、交付文件与复绘校验分别位于本地实验目录的 `final-result/comparison.png`、`workflows/run-nfpsol7c/delivery/` 和 `delivery-verification-run-nfpsol7c.json`。

### 粉色圆盘的纯视觉、模型独立编写对照

另建独立 PNG 直生会话，参考文件逐字节复制为中性名称 `reference.png`。首次仅输入用户的通用复现要求与原图；目视复核只沿用本次模型自己提交的 GLSL 和该 GLSL 的 WebGL2 预览。最后一次复核额外说明标准 Shadertoy 的坐标方向与颜色合成约定。没有将此前工作的草案、代码、颜色、坐标锚点、图片测量或拟合结果交给模型。未计算相对原图的像素误差。

客户端在发送前逐次核对工具白名单（`render_shader`、`finish_shader`、`stop_generation`）与图像来源。只对图片文件原始字节计算摘要，确认每张发出的图是原图或本次生成的预览。8 次真实请求中一共产生 5 个渲染版本；全部落盘 GLSL 的正文与服务端工具调用参数匹配。最后选择的着色器来自第 7 次模型回复，第 8 次请求展示了新预览，随后由模型选定。模型复现了粉色圆形和主要渐变，但左上反光偏宽，右下亮边与主体下方的粉色投影明显不足。本地材料位于 `runs/visual-only-20261125-HpWIMp/`，可查看 `requests.jsonl`、`responses.jsonl`、`provenance.json` 和实际选定候选。前一节使用像素拟合得到的 1.04/255 仅属于那次受指导实验。

纯视觉续跑将该单图的累计上限提高至 32 次真实请求、16 次渲染和 90,000 个输出 token。保留原来的 8 次请求、5 次渲染与 7,418 个确认输出 token。生成器的 `finish_shader` 作为提交候选的动作。独立上下文中，同一模型只看参考和候选图评审；两个未过关版本可做匿名 A/B 择优。5 个新修订回合均未取代原来保留的版本。总计 32 次真实请求，确认输出 26,449 token。应用正式尝试渲染 13 次，其中 11 份源码成功渲染，独立目视评审仍要求修订。

第 31 次模型回复提供了重新实现的完整 GLSL，并因向量类型不匹配编译失败。第 32 次回复在正文中明确写出应取 `iResolution.xy`，并给出更正渐变方向的 `0.5 - 0.5*g`，但工具参数仅含占位函数，仍编译失败。另在本地把这两处明确改动应用到同一模型第 31 次的源码，进行第 14 次渲染并得到独立可运行版本。其左上高光仍偏椭圆，右下反光不足。这份本机复绘没有经过新的 OpenRouter 独立盲评。实验未使用参考图像素测量、参考纹理或拟合制品。正式的请求与来源证明在该运行的 `extended/proof.json`；最后两处改动、独立源码及其来源在 `extended/replayed-model-edits/`，三图目视对照见 `extended/comparison.html`。
