# 单观察 Skill 分层重构与回归记录

- 日期: 2026-11-10.
- 目标: 优化 skill 的通用性、可执行性与可控性, 用既有十图检查改动; 保持一个分析 Agent 和轻量 E/F/R 合同.
- 范围: 运行 skill、条件式参考、资源装配与版本/读取诊断、相邻文档和行为测试.
- 版本口径: 第 1–8 节保留 R2/R3 的改造与真实回归; 第 9 节记录后续 skill 文字修订. 历史结果不作为新规则的实测结果, 不覆盖既有报告.

## 1. 原版的问题

旧 SKILL.md 把字段说明、工作步骤、粒度定义、复查清单和具体图片的拆分结论混在一起. 同一条主要归属规则反复出现, “何时读哪段材料”的判断不够明确. 旧版虽有按需读取 examples.md, 主文件仍常驻全部规则与局部答案.

十图暴露的错误主要是关系覆盖、F/R 重复、缺口尺度和局部事实. 这说明需要改判断方法与执行顺序; 仅把原段落搬进多个文件, 无法证明语义质量改善.

## 2. 最终文件与加载方式

```text
resources/skills/scene-observer/
├── SKILL.md
└── references/
    ├── grouping.md
    ├── relations.md
    └── uncertainty.md
```

| 文件 | 加载条件 | 完成的判断 |
| --- | --- | --- |
| SKILL.md | 专用观察角色启动时直接应用 | 确定范围 → 识别关键配合并分配归属 → 回看原图 → 提交 |
| grouping.md | 重复单元、复合对象或拆合犹豫 | 对象或群体边界、F 拆合、保留内部变化 |
| relations.md | 重要布局、随形/对应、覆盖、透显或跨区域效果 | 配合的主要归属、R 合并边界、参与项完整性 |
| uncertainty.md | 歧义影响判断, 或准备填问题/缺口 | 可描述精度、待确认判断、必要遗漏与任务外问题 |

主文件从 2261 字符缩至 1432 字符, 减少约 36.7%; 这是字符统计, 不是 token 或成本降幅. 细则预置在 SDK StateBackend, 在 read_file 返回后进入模型消息. 多个必要文件可以同批读, 已在上下文中的内容直接使用.

由于这是单一用途的观察角色, 运行时直接激活主流程. 取消 SDK 对同一 skill 的重复发现提示, 保留 SDK 文件读取、摘要、消息和工具循环. 这并非把所有参考一次性注入 system prompt.

原五图完整答案保存在[离线校准文档](../analysis-observation-examples.md), 新五图 Codex 参考答案保留在既有实验制品中. 两者均不进入新版运行资源. 短例子用于解释边界, 不包含十图的输出配额或专属识别规则.

## 3. 从案例问题提炼的通用判断

| 已见问题 | 通用修正 | 保留的边界 |
| --- | --- | --- |
| 交互文字全部塞进 F | 先识别重要配合及参与项, 将交互区域的具体外观集中于 R | 自身纹理仍可以是 F; 无关键配合时 R 可为空 |
| 完整对象与组成部分重复建 E | E 使用平铺清单, 不另建只概括已列 E 的“整体”元素 | 不强制每图的 E 数量, 允许完整对象或合理分组 |
| 同一变化在 F/R 重复 | 用“合并后是否丢失独立目标”判断分项, 每个现象保留一个主要归属 | 合并仍需保留颜色、形态、分布差异 |
| 关系参与项遗漏 | 逐条把关系描述的必要参与对象对应到 ID | 可以引用 E/F, 无需把所有父 E 与子 F 一并填入 |
| 普通精度不足变成 gaps | 按任务必要性区分定性描述、open_questions 和 gaps | 用户明确要求的精确数量仍可能构成真实缺口 |
| 名称或因果猜测替代事实 | 回看全图方位、轮廓和边界, 只采用图像支持的精度 | 不禁止合理物体命名, 但名称不证明运动或实现方法 |

主流程明确背景、主体、局部效果与关键配合的覆盖检查. 主体附着的亮边、柔影和色场保留在 F, 全局环境放上下文. 这些原则适用于新图, 不依赖原 case 的文件名、坐标或答案条数.

## 4. 运行侧配套

- [native.py](../../src/shader_deep/agents/analysis/native.py) 显式装载四份资源, 只将主文件作为固定指令.
- 包配置包含 references 下的 Markdown, 已核对实际 wheel 内容与冻结资源哈希.
- rule_sha256 标识主文件; resource_sha256 标识每份资源; skill_bundle_sha256 标识整组资源.
- resource_read_results 仅记录受控路径及工具返回状态. 它能区别“文件可读”与“实际调用过”, 不能证明全文阅读或理解.
- E/F/R 提交字段、权限白名单、终态独占响应及有限调用预算沿用现有合同. 本次没有增加结构合法后的第二次模型评审.

## 5. 验证口径

无网络测试验证按需文件在首个请求中未展开, read_file 后进入下个实际请求; 检查成功/失败读取的诊断, 保留权限、原图注入、修正和终态行为验证. 当前 `make check` 通过 261 项测试、Ruff 与 ty, repository_check 为 0 findings. skill 格式验证通过.

构建环境最初缺少 setuptools, 离线无隔离构建失败; 使用项目已声明的构建依赖完成隔离构建后, 最终 R3 可离线构建. 未增加运行依赖. 最终 wheel 中四份资源与冻结文本逐字节哈希一致.

真实测试固定既有模型、输入字节、通用要求和预算: z-ai/glm-5.3-flash, max_model_calls=8, max_output_tokens=163840, request_timeout_seconds=45, max_request_retries=0, 并发 3, 关闭额外追踪. 所有图沿用已授权目的地. 结构合法与 completed 不用作语义质量分数.

十图已用于开发, 本轮属于回归检查. 采用固定的现象覆盖、关系覆盖、归属重复、参与项、视觉事实和必要缺口判据; 不按 E/F/R 条数或原编号评分. 未进行随机化重复 A/B, 不能将单次差异归因于某一句提示.

## 8. 可控性的实际边界

程序继续保证工具权限、终态约束、有限逻辑调用和资源身份记录. 条件参考的选择、视觉事实与语义归属仍依赖模型; 当前不会因为声明了 R/gaps 而强制检查是否读过对应参考, 也没有自动语义验收. 本轮没有用硬编码目标条数、清空 gaps 或人工改写报告制造通过.

后续应单独验证“提交前必要参考读取约束”能否减少漏执行, 再评估一次同 Agent 有限复查的收益. 视觉误读需要独立的视觉能力或取材实验. 十图继续作为回归集; 泛化验证另留未参与规则设计的新图. 这些后续措施尚未实施, 不用继续堆叠单图专属规则替代验证.


## 9. 侧聊确认后的 Skill 文字修订

2026-11-10, 根据本轮确认调整运行规则, 未修改 Python 执行、提交 schema 或读取门禁:

- 可见背景统一作为 E, 已由天空/地面/水面覆盖时不再另建重复背景; context_notes 仅补充全图要求或条件.
- E.name/region 简短识别与定位, F/R.description 只保留识别、主要外观与关键配合所需信息, 关键方向/形态仍需核对. 不主动展开无必要的坐标、角度、尺寸倍数或计数.
- 主文件直接包含 F/R 基本归属、问题与必要缺口的分类及交付条件, 普通提交不再依赖先读取参考才能知道要求.
- 三份参考仅解决主流程仍无法确定的拆合、归属或必要性问题. 不因出现 R、群体或问题列表就一律读取, 因而读取次数不作为执行正确或质量的替代指标.
