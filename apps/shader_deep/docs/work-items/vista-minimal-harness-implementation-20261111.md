## 1. 首版交付与范围

交付一个可以保存材料、列出目录、按 ID 回读整图或局部、继续生成并选择候选的单任务闭环. 同一次运行中, 旧候选退出默认请求后仍能找回原图、代码及失败原因.

首批接入普通 PNG/既有生成任务入口和现有 `five_libraries_v1` 单方案报告入口. 复用 `RenderSession`、Deep Agents 循环、真实 WebGL2 渲染及既有文件布局. 新增两个受限工具, 不开放通用文件读写或另建 Agent 循环.

实施期通过显式选项开启记忆模式, 保留原模式供兼容回归和对照. 方案比较、整图组合先保持原行为; 它们虽然共用生成循环, 也不因此自动启用新选材策略. 新 E/F/R 到 M/S 的合同及生成适配、分析角色接入、调参子 Agent、跨任务自动检索、笔记整理和会话恢复均不在本次实现范围.

现有报告入口持续保留 `generation_scheme`. 最新五库设计中的上下游缺口合同列为后续适配的验证要求, 不让首版记忆依赖尚不存在的新读取器.

## 3. 文件、身份与来源接线

运行目录保留既有文件, 只增加索引、派生图和单次结果文件:

```text
run-xxx/
  inputs/                       # 现有报告/基线副本; 普通输入在此固定
  candidate-001.glsl
  candidate-001.png              # 成功时才有
  candidate-001-render.json      # 生成侧发布的单次结果投影
  run.json                      # 继续作为可更新的业务快照
  memory/
    index.json
    derived/
      m0006.png
```

### 3.1 材料模块

- 按最小设计解析 `version/run_id/materials`, 拒绝重复 JSON 键、未知格式版本、无效路径和坏引用. `m0001` 等 ID 由程序单调分配; 不依赖 JSON 对象键顺序表达分页顺序.
- 索引采用现有 [write_snapshot](../../src/shader_deep/infrastructure/storage/snapshots.py) 的同目录临时文件替换方式. 只有发布成功的记录进入可读取目录; 不承诺跨文件事务或崩溃恢复.
- 登记与派生写入经当前会话串行路径执行. 回读重新验证文件字节哈希, 解码及裁剪使用同一份已验证字节, 避免校验后另读一份变化内容.
- 首版当前会话是唯一写入者. 重新打开索引可以供检查或读取, 不恢复模型循环. 实施不引入分布式锁或跨运行合并.
- 分页游标绑定运行、过滤条件和最后已返回的登记序号; 新增条目追加, 错误游标明确报错. 稳定 ID 不复用; 相同裁剪复用只限同任务、同直接来源和同参数.
- 路径解析包含符号链接解析, 结果必须位于本轮目录内. 索引只登记显式绑定材料与已知产物, 不扫描整个运行目录或项目目录充当授权列表.

### 3.2 输入捕获与 origin

- 报告模式使用现有捕获副本及 `scheme_json`, 不再次复制整包. 首次登记发生在准备输入和任务身份确定后、第一次模型请求前.
- 普通 PNG/任务模式将参考图、基线和显式输入候选文件捕获到本轮 `inputs/`, 保持原任务和候选记录不被改写; 新建本轮材料映射. 后续默认展示与按需读取均使用捕获文件, 不再回读外部源路径.
- 新材料的 `source.task_id` 表示接收它的本轮任务. `source.origin` 只保存可核验的原运行/材料/候选身份或已有报告绑定信息. 未提供原运行或材料身份时省略, 不从目录名字猜测、不编造历史材料 ID.
- 原候选身份、报告内容摘要、草图/备选选择沿用现有记录; 跨运行短 ID 不直接相互覆盖. 外部文件路径仅为来源说明, 不能作为读取工具的任意文件入口.
- 当前选定方案和必要正文仍由生成输入适配负责装配. 不把全部报告正文改为强制让模型先自行检索, 不把未选备选悄悄变成采用方案.

### 3.3 产物与错误

- 保存 GLSL 后登记代码. 成功渲染后登记 PNG; 生成侧建立已有 `CandidateRecord/ResultRecord`, 保存业务结果, 再发布固定结果 JSON 并登记.
- 结果 JSON 明确区分渲染执行状态与业务提交状态, 保留既有结果 ID、候选 ID、代码材料 ID、实际错误及成功时的预览材料 ID. `partial` 不等于渲染失败, 渲染成功也不等于用户验收.
- 工具反馈返回这些材料 ID. 中间件依据真实工具调用 ID 关联本次结果, 不靠代码内容或候选序号猜测调用归属.
- 结果文件仅为已发生尝试的不可变投影. 后续选择结果及 `run.json` 更新不会改写它. 公共读取层按普通 JSON 读取, 不查询生成状态或解释错误.
- 保存/登记失败应留下已有制品并进入可解释错误路径, 不返回不存在的材料 ID、不静默回退为全量上下文. 工具参数被拒绝且未产生文件时只返回工具错误, 不伪造渲染候选.

## 4. 工具与请求装配

### 4.1 工具接入

记忆模式的可见与可执行工具都限定为 `render_shader`、`finish_shader`、`stop_generation`、`list_materials`、`read_materials`. 保留运行时白名单, 更新提示词中“只使用三个工具”的旧说明. 列举、回读和裁剪同样检查终态, 终态后的同批调用不得再创建派生文件.

沿用已确认参数: `list_materials(kind?, limit?, cursor?)`; `read_materials(items=[{id, region?}])`. 两者绑定本轮允许材料. 按输入顺序处理批量读取, 单项错误不阻止其余合法项. 错误包括未知或不可访问 ID、缺失/变更文件、无效区域、大小超限和读取额度耗尽; 不将访问范围外材料是否存在泄露为目录信息.

列表中的名称和来源由程序产生; 如展示已有观察摘要, 由生成适配层提供并标注为观察, 公共存储不生成判断.

### 4.2 一轮回看如何进入模型请求

采用“SDK 历史保存简短回执, 请求副本展开实际内容”的接线方式:

1. 读工具校验并读取材料; 裁剪时先发布派生文件. 持久 ToolMessage 内容保留请求 ID、返回 ID、区域与逐项状态.
2. 实际图像/正文暂存为本会话下一逻辑轮次的读取结果, 按工具调用 ID 关联. 可用 `ToolMessage.artifact` 携带非模型引用元信息; 不依赖 artifact 自动变成模型可见内容, 也不在历史 artifact 内长期堆积图片字节.
3. 下一次模型调用构建请求副本, 在对应工具响应位置展开有标签的真实图像或正文. 同批读取保留顺序; 与固定材料重复时只展开一次, 回执保留可识别的对应说明.
4. 模型成功返回后消费该批临时内容; 之后请求只保留回执. 逻辑轮次内的网络重试复用同一份请求材料, 不提前清空或重复扣读取额度.

已归档的 `render_shader` 响应也参与请求历史投影: 保留调用配对、执行状态、候选及代码/结果/预览材料 ID, 不持续携带完整 `error` 或代码正文. 最近一次失败的错误全文只由默认失败反馈在紧接着的一轮提供; 之后需要时读取固定结果 JSON. 回看结果与默认失败反馈重合时仍只展开一次. 仅投影已有可回读结果材料的响应, 未归档的工具参数错误不能替换成虚构材料引用.

会话只新增工具调用到材料的映射、待呈现材料和本轮额度; SDK 继续管理原消息和循环. 不维护另一份对话日志或独立调度状态机.

实际实现使用会话内临时读取结果, 没有依赖 `ToolMessage.artifact` 自动注入图像. 第 0 步已通过真实 ChatOpenAI 序列化配合模拟传输验证, 包含多模态响应及重试内容一致性; 这不自动证明任意远端模型服务都接受该协议.

### 4.3 历史 GLSL 退出请求

- 每个已执行且代码材料成功登记的 `render_shader` 调用, 在请求副本中始终将 `glsl_code` 换成明确的代码材料引用说明字符串, 不因该代码属于当前默认或回看材料而恢复历史参数正文. 原工具名、调用 ID 和响应仍成对保留; 引用字符串不能被重新执行.
- 代码正文只从默认材料或当轮回看展开, 同一材料在完整请求中至多展开一次; 同时被默认和回看选中时共用一次展示. 退出两种选材后仅保留引用, 再次回读也不恢复历史参数中的正文.
- 只投影已有执行结果且材料成功登记的历史调用, 不改即将执行的模型参数. 原 SDK 消息、磁盘代码及原始执行事实保持原样.
- 同步检查适配器可能使用的原始 tool_calls 参数副本, 避免只改标准字段而序列化仍发送原 GLSL; 不盲目删除推理块或其元数据. 若目标适配器拒绝此投影, 必须解决协议兼容后再接通, 不通过破坏工具配对或无声保留全历史冒充通过.
- 展开及精简是确定性的请求变换, 不额外请求模型摘要. 验证最终发出的完整请求, 包括 AI 工具参数和 ToolMessage, 而非只查看 Context Builder 的输出.

### 4.4 默认材料与完成资格

固定方案、约束、参考图、最新成功候选及最近失败反馈按最小设计选材. 记忆概览只提供数量、工具使用入口和当前材料 ID, 历史目录按需查询. 原有 `GenerationContext.candidate_ids` 不得继续被含糊地当作“已展示完整预览”清单; 内部请求构建结果需另有准确的整图、局部和正文引用信息, 保持现有公开构造兼容.

`presented` 根据本轮实际携带的完整候选预览登记, 删除记忆模式下对全部 `successful` 的批量赋值. 请求构建时先形成 `full_preview_candidate_ids`, 只包含最终请求实际携带的完整候选预览, 不包含目录、代码或派生视图. 模型可见的 `finishable_candidates` 使用 `successful ∩ (presented ∪ full_preview_candidate_ids)`, 使模型第一次看到整图时就知道可在本轮响应中选择它.

会话中的 `presented` 仍在携带材料的逻辑模型调用成功返回后、执行该响应中的任何工具前, 合入本轮 `successful ∩ full_preview_candidate_ids`. 失败请求不提交新资格, 保留此前已确认集合; 网络重试复用同一清单. 局部视图即使覆盖了来源全尺寸也仍是派生视图, 不能冒充直接展示候选预览. 原基线和外部输入永远不因此进入本轮 successful 集合.

同批 render + finish 仍被拒绝; 多次 render 同批产生的中间版本若未被整图呈现, 只能通过后续回看获得资格. 已呈现整图退出默认上下文后仍可选择. 结束时保持读取已选真实代码, 并核对其材料身份, 防止选择与交付使用不同内容.

## 5. 配置与兼容策略

以下是首轮实验配置, 并非提供方硬限制. 在同模型对照中显式记录并使用一致的渲染与模型调用预算.

| 配置 | 实施初值与含义 |
| --- | --- |
| `GenerationOptions.visual_memory` | 新增 keyword-only、默认 false; 开启后才使用本方案. CLI 增加 `--visual-memory` |
| `GenerationOptions.max_model_calls` | 新增 keyword-only、默认 None; 显式值优先. 记忆模式未指定时初值 12; 原模式未指定时保持 max_attempts + 2 |
| 列表页大小 | 默认 20, 上限 50; 非正数或超上限明确拒绝 |
| 每轮额外材料 | 默认 4, 同一模型输出触发的多个读取调用共享. 首版按请求项计数, 失败及重复项也占本轮名额, 防止重复尝试绕过边界 |
| 单份文本正文 | 初值 32,768 个字符, 完整 UTF-8 解码后计数, 不称为 token 上限; 超限明示, 不截断 |
| PNG 读取 | 初值文件 8 MiB、像素总数 16,777,216; 使用来源尺寸做裁剪校验, 解码上限与展示上限分开检查 |

材料限制集中为一个有类型的内部配置, 可在会话装配和测试时调整, 首版不为每个值扩展公共 CLI. 四份上限只限制额外回看; 固定输入也需验证实际请求可被当前服务接受. 必需输入超限应在启动前明确拒绝, 不自动丢弃方案、参考图或条件. 避免把像素限制当成实际视觉 token 的精确估算.

`run_generation_from_report` 的新选项只能作为有默认值的 keyword-only 参数追加, 同步转入 GenerationOptions; CLI 的两种输入模式都支持 `--max-model-calls`. **这是公开配置和报告入口的签名扩展**, 实施交付需明确说明, 检查 api 导出、旧调用及测试. 其他公开函数继续接收原 options, 不增改位置参数.

模型预算采用会话累计的已开始逻辑调用次数; 单轮底层网络重试不另外计数. `run.json`、剩余额度反馈、追踪元信息、终止原因和 `agent.py` 的 `recursion_limit` 一起使用解析后的模型预算, 图步数应留足模型/工具节点余量, 不再按渲染次数错误截断回看. 保持自动摘要关闭, 禁止以模型纯文本回复或重复工具调用无限延长会话.

新模式首版只接受已明确支持的单任务输入; 对尚未适配的 scene inputs 显式拒绝开启, 不静默采用错误选材. 原模式及比较/组合的已有默认行为保持兼容. 后续默认启用是单独决策, 不在本次实验中自动切换.
