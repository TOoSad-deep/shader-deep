# 轻量五库业务结构与规划语义

- 日期: 2026-11-11.
- 状态: 已确认业务决定的汇总, 加上本轮分析形成的细化建议. 新合同、读取器与生成交接已按[实施记录](scene-planning-agent-plan-20261111.md#13-实施记录)落地, 真实内容的语义问题另行记录.
- 范围: 五库对象、相互引用、候选与方案语义、覆盖及缺口. Agent 调度、工具、运行预算和物理文件格式另行设计.
- 阅读关系: 本文承接[接入路线](observation-planning-multiview-roadmap-20261110.md). [旧五库设计](../analysis-five-libraries.md)继续解释历史协议; 本文不宣称旧读取器已经支持新结构.

## 1. 已确认决定与本轮补充

用户已逐项确认:

1. 同一次规划的所有 S 针对同一份完整 E/F/R, 分别表达实现方案. 范围由规划任务固定, S 不填写 element_id 或 element_ids.
2. M 保存可复用构造方法. 具体位置、应用次数和参数安排属于 S.
3. 候选索引主要从 S 的默认选择与局部备选派生. 模型仅补充尚未被方案表达的必要候选.
4. S 核心字段为 id、name、default、composition.
5. 每个 S 独立记录可选 gaps. 缺口必须说明必要目标及原因, 已有机制引用也可以存在未解决缺口.
6. alternatives 可选; 每项包含 choices、reason, 按需提供 conditions、composition. 以默认方案为基准, 首版一次选择一项, 不自动组合多个备选.
7. 局部备选仅替换已有选择. 补齐原缺口或改变整体路线时, 提交新的完整 S.

以下各节对机制粒度、直接贡献、候选组合、条件、引用和边界情况作出细化建议. 这些补充是在本轮“分析并完善”的授权下形成, 不冒充此前逐项确认的结论.

## 2. 对象与提交职责

| 对象 | 字段 | 主要责任 |
| --- | --- | --- |
| E | id、name、region、feature_ids | 对象定位与 F 主归属; 保存用 feature_ids 由嵌套观察派生 |
| F | id、description | 一项必要可见外观 |
| R | id、participants、description | 同元素或跨元素的重要配合 |
| M | id、name、method、可选 conditions | 可复用构造方法与内在前提 |
| S | id、name、default、composition、可选 gaps、alternatives | 同一完整观察范围内的一套实现方案 |

观察阶段沿用[轻量观察合同](../../src/shader_deep/domain/scene_observations.py): E 下嵌套 F, 场景级 R 引用 E/F. 规划只读已发布的观察版本, 不重交 E/F/R 或重新分配其身份.

建议规划提交只包含 mechanisms、sketches 和可选 extra_candidates. 其中 mechanisms 允许为空以支持纯背景场景; 一次正常方案提交至少包含一套 S. 无法形成方案时的停止合同由工作流另行定义.

新规划的名称、方法、组织说明和原因均为非空字符串. conditions 是字符串数组, gaps、alternatives、extra_candidates 是对象数组; 可选数组省略与空数组等价, 不使用 null 表达第三种状态. 未定义的字段不作为自由扩展入口. 具体 Python 类型与工具 schema 留到实施阶段, 不直接套用旧五库模型.

context_notes、观察 open_questions/gaps、原图与用户要求作为共同输入保留. 五库合并展示是程序视图, 不意味着模型要一次维护五份正文. 原图、完整观察快照及生成约束由程序绑定; 不能仅用原图哈希代替观察版本身份.

## 3. M 的边界、复用与依赖

### 3.1 粒度判据

一个 M 应能说明构造动作、必要输入、输出性质和主要可调因素. 这些内容先保留在 method 文本中, 不单独增加参数表或输入输出 schema.

| 情况 | 处理 |
| --- | --- |
| 同一方法换位置、颜色、尺度或调用次数 | 复用 M, 具体安排写 S |
| 同一输出具有自然相连的构造步骤 | 可合为一个 M, 例如圆形距离同时提供内部遮罩与窄边沿 |
| 某一部分具有独立复用或替换价值, 且构造方法能独立说明 | 可以拆成不同 M |
| 仅写“做玻璃效果”或“生成整张图” | 信息不足, 应补具体方法或合理拆分 |
| 把每次乘法、插值和参数变化都单独登记 | 缺少独立业务价值, 应合回所服务的方法 |

不规定一个 F 必须对应一个 M. 一个 M 可以服务多个 F/R, 多个 M 也可以共同实现一个目标. 同名不证明方法相同; 方法和内在前提不同的记录不能仅凭名称合并.

### 3.2 首版机制自包含

M 的 method/conditions 用“轮廓距离”“可求值的底层颜色”等概念描述输入, 不引用本轮 E/F/R/S, 也不建立本轮 M 到 M 的引用链. 具体由哪个方法提供输入, 写在 S.composition 中.

这使方法可以在别的图中使用, 并避免隐藏的机制依赖图. 引入 M 不等于引入已实现函数, 名称相同也不代表不同运行中的短 ID 指向同一实现.

## 4. default 与 composition 的准确分工

default 是“目标 ID → 共同采用的机制 ID 数组”. 目标只允许本轮 F/R; 数组非空、无重复. 多个 M 表示共同作用, 对象键顺序和数组顺序都不表达计算顺序.

### 4.1 直接贡献与间接依赖

default 登记直接承担某目标的方法, 不要求将全部传递依赖重复展开到每个目标下. composition 说明输入来自哪里、怎样组合以及哪些结果共享.

当前方案使用的每个已登记 M, 至少在一处生效选择中出现. 独立的中间结果机制可以作为其服务目标的共同采用机制登记; 其他消费目标无需重复展开它. 普通内部步骤保留在 method 中, 不因为缺少独立 F/R 就强行创造新观察目标.

例如弧形亮带方法使用轮廓中心和半径:

- F3/F4 直接使用亮带方法; 提供坐标的轮廓方法无需重复登记在每个亮带目标下.
- R1 要求亮带与轮廓共同保持配合, 可以显式选择轮廓方法与亮带方法的组合.
- 多个目标引用同一 M, 不决定应用次数. 两处独立应用还是共享一个结果, 由 composition 说明.

R 不必有单独的“关系机制”. 布局、裁切、透显等关系可以由已有机制的共同安排满足. 同时, 给 R 填入参与机制 ID 只声明了安排, 不证明关系已经实现.

### 4.2 文字组织说明的约束

composition 只交代对本方案有实际影响的定位、应用次数、输入依赖、共享结果、混合及裁切. 不重复机制 method, 不逐个展开普通算术操作.

实际采用的具名 M 必须出现在当前生效的选择中. 只存在于其他 S、补充候选或未选备选中的 M, 不因正文提到就成为当前采用方法. 比较或不采用的理由放在 reason, 不混入执行说明.

首版由生成模型理解这些文字并实现. 引用校验可以检查明显冲突, 不能自动证明自然语言里的依赖完整、计算无环或实现兼容.

## 5. 候选以组合为单位保存

### 5.1 程序派生

对每个 S 生成默认选择视图; 对每个局部备选, 用其 choices 覆盖 default 中对应目标的整组机制, 得到独立的生效视图. 其他目标继承 default.

候选索引保留目标、共同采用的 M 集合以及来源 S/默认或备选位置. 不能将组合拆成可任选的独立 M, 也不能丢掉来源的 conditions、composition 和 gaps. 可以合并相同集合的展示行, 但必须保留所有来源.

该索引用于发现和取材. 从不同来源各挑一个方法拼在一起, 并不会自动形成合法方案; 真正采用时仍需形成完整 S 并复核其组织方式与缺口.

### 5.2 尚未进入 S 的补充候选

建议 extra_candidates 为可选数组, 每项固定为:

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| target | F/R ID | 本次候选拟作用的观察目标 |
| mechanisms | 非空 M ID 数组 | 一起使用的方法, 不表示互斥选项 |
| reason | 非空文本 | 值得保留的理由、尚未进入方案的原因, 以及必要的组合限制 |

不为补充关联另建 ID. 同一正式版本不重复登记已经由 S 表达的相同目标与组合; 已采用方案的局部备选理由放在 alternative.reason. 这里的去重必须发生在候选语义已迁移之后, 不能仅按目标和机制 ID 集合相同就删除 reason.

所有候选 M 正文仍位于机制库. 条件不足的候选可以保留, 但候选存在不计入任何 S 的覆盖, 也不因未采用候选的条件不足而给可行的 S 增加缺口. 未被任何方案、备选或补充关联使用的 M 暂不进入正式交付.

### 5.3 补充候选转入方案时保留限制

规划者需同时读取候选的 reason 和相关 M.conditions, 区分仍有效的组合限制与已经过时的未入选原因. 目标和机制集合相同, 只能证明选择对应相同, 不能证明组合语义已经迁移.

| 候选中的信息 | 转入 S 时的处理 |
| --- | --- |
| 仍有效且本方案能够满足的组合限制 | 落实到 composition, 说明如何满足; 局部备选的适用前提也保留在其 conditions 中 |
| 仍有效但本方案尚未解决的必要限制 | 在对应 S.gaps 引用受影响 F/R 并说明原因, 不因有 default 映射而省略 |
| 已经满足或不再适用的旧未入选原因 | 不机械复制为新缺口; 新方案说明实际安排, 原说明留在源版本 |

例如候选要求“两种方法使用同一坐标范围”: 正式方案应说明统一坐标或转换安排; 若范围尚未确定, 就对相应关系保留 gap. 只把机制 ID 加入 default 而不处理这一限制, 不构成完整迁移.

完成上述语义核对后, 在新版本中移除重复的 extra_candidates 项, 以 S 为主要表达位置并重新派生索引; 源版本保持可追溯. 程序可以发现组合重复并提示核对, 不能自动判断自然语言限制已经满足或自动丢弃它. 未完成核对时保留源版本, 不发布声称已完成迁移的新版本. 若转入局部备选会改变缺口语义, 仍遵循第 7 节, 提交新的完整 S.

## 6. conditions、gaps 与覆盖

| 内容 | 归属 | 例子 |
| --- | --- | --- |
| 方法成立所需的内在前提 | M.conditions | 模糊方法需要能在邻近坐标获取底层颜色 |
| 本次局部替换成立的组合前提 | alternative.conditions | 简化方法只对当前解析圆形背景适用 |
| 当前 S 尚未解决的必要实现问题 | S.gaps | 已选模糊方法, 但没有安排底层颜色的来源 |
| 已知方法与组合中的具体数值调优 | 生成阶段 | 半径、透明度或色值尚未调准 |

声明条件不等于满足条件. 若必要条件在当前方案和已知环境中未得到解决, 对受影响目标记录 gap; 不因为 default 已有 M 引用就省略它.

建议 S.gaps 每项只包含 refs 和 description. refs 是非空、不重复的本轮 F/R ID 数组; description 说明缺失内容和原因. 这一限制仅适用于新规划的方案缺口, 不改变旧观察合同中空 refs 的含义.

设全部观察目标为 T, 当前方案 default 键为 D, gaps.refs 的并集为 G:

```text
D 必须包含于 T
G 必须包含于 T
T - D 必须包含于 G
```

D 与 G 可以相交: 已声明实现安排, 仍可能有关键依赖未解决. 空的全局问题说明不能替代具体缺失目标的登记. 对全部目标仅填写缺口, 也不能据此宣称存在可执行的完整方案.

这些规则只检查已经登记为 F/R 的目标, 不是完整规划的全部条件. 无 S.gaps 不代表视觉正确、条件已被程序证明, 也不代表用户验收通过.

### 6.1 上游必要观察缺口共同约束完整性

完整范围内的上游观察 gaps 原样保留在固定输入中, 作为所有 S 共同继承的必要缺口来源. 它们可以引用 E 或没有 refs, 不受 S.gaps 的 F/R 引用限制; 无需复制到每个 S, 也不能强挂到无关 F/R 或虚构 F0.

设上游尚未解决的必要观察缺口集合为 U. 声明“整图规划没有已知必要缺口”至少要求:

```text
U 为空
S.gaps 为空
T - D 为空
```

其中 U 的清空只能依据修订后重新发布的观察版本. 规划者不能通过改写 S 或忽略输入来清除它. 上游 open_questions 不自动作为阻断; 若问题实际影响必要观察覆盖, 应先在观察层正确表达为 gap.

当必要对象尚未辨认、还没有 F/R 身份时, 可以保留对已知部分的暂定规划, 但整图规划仍带上游阻断, 不能因为 default 覆盖了所有现有 ID 就标为完整. 若缺口使可靠规划无法继续, 先补观察. 上游缺口已经能对应现有 F/R, 且对具体 S 另有实现影响时, 才在该 S.gaps 中说明对应影响.

程序计算交付完整性和提供方案材料时, 必须同时保留 U 与所选 S 的 gaps; 不因来源不同而漏掉其中一类. 上述规则不新增五库业务对象或模型必填的全局缺口列表, 也不把“无已知必要缺口”升级为视觉验收.

## 7. 局部备选的联动与缺口继承

alternative.choices 必须非空, 键只来自当前 S.default. 每个值替换该目标的整组机制; 未列出的目标继承默认选择. 首版只选择一个备选, 不做备选的笛卡尔积.

composition 省略时继承原文; 提供时替换整段组织说明. 替换后原文仍引用已移除方法时, 必须补充有效的新 composition.

修改 F 时要复核相关 R, 包括经 E.feature_ids 找到的元素级关系. 需要联动改变选择的目标放入同一 choices. 相关 R 不一定都要改变方法, 但须确认原来的配合仍成立; 程序只能发现受影响范围, 不能替模型确认语义保持.

备选不另设 gaps, 继承当前 S 的必要缺口. 因此局部替换应保持缺口语义: 解决原缺口、新增必要缺口, 或使缺口原因发生实质变化时, 都提交新的完整 S. 不通过挑选备选自动清空缺口.

## 8. 正文引用、上下文与身份

### 8.1 新规划正文引用

建议新规划中引用本轮业务对象时采用 [[ID]], 结构字段仍直接写 ID 字符串. S.composition 可引用本轮 E/F/R 及当前生效选择中的 M; 不引用其他 S 作为隐式父方案. reason 与 gaps.description 可解释相关本轮对象, 但不改变实际选择.

M.method/conditions 自包含, 不引用本轮业务 ID. 普通坐标和变量不会仅因形似 ID 被解释为对象引用. 既有 E/F/R 原文保持原样, 不要求为新增规划反向改写观察包.

正文与结构选择冲突时拒绝该规划版本, 不静默以正文替换 default. 即使标记有效, 也不能用标记解析证明自然语言含义正确.

### 8.2 上下文仍是整图要求

所有 S 继承同一 context_notes 与用户要求. 普通底色通过 composition 落实, 不为覆盖检查虚构 F0 或背景机制关联. 背景具有独立结构或参与关键交互时, 在观察阶段登记必要 E/F/R, 再规划.

纯背景观察允许 E/F/R 全为空而 context_notes 非空. 此时 S.default 可以为空, composition 直接说明背景处理, mechanisms 也可为空. 只有上游没有尚未解决的必要观察缺口, 才能按无已知缺口的纯背景方案交付. 若空 E/F/R 是因为主体或纹理尚未辨认, 则仍受第 6.1 节约束, 不能借空目标集合宣称完整. 结构覆盖为空不能代替对上下文的语义核对.

### 8.3 身份约定

沿用本轮 E/F/R 身份; 新 M/S 使用 M1、S1 形式的正整数短 ID, 在同一快照内唯一. 不覆盖已有 ID 的含义; 修订形成新版本. 跨运行相同短 ID 不表达同一对象, 未来多来源汇集由程序处理命名空间与来源.

具体快照摘要、物理文件路径、派生索引格式和新协议名称由实现阶段确定. 本文不使 scene_observations_v1 或 five_libraries_v1 自动接受新字段.

## 9. 磨砂叠圆的完整业务样例

观察沿用[五图校准基线](../analysis-observation-examples.md). 以下是合并展示, 不是模型一次提交的工具参数. M/S 是用于检验结构的候选构想, 未通过生成或渲染验证.

S1 将底层图像组织为可重复求值的颜色函数, 在前圆区域内计算模糊与着色. 这条路线不假定当前渲染环境有额外纹理输入. 预滤波纹理路线只作为补充候选保留.

### 9.1 样例说明了什么

- 两个 E 与跨元素 R 共享一个 S, 不把交叠区另建对象.
- M1 用于两个圆, R1 引用一次 M1 不等于只生成一个圆; 应用次数和位置写在 composition.
- F3 的固有外观与 R2 的交互分别记录, M4 可同时参与它们, 不重复观察目标.
- R2 默认组合为 M3 + M4, 局部备选为 M5 + M4, 补充候选为 M6 + M4. 三者不能拆成可以任意替换的单个方法.
- M3 的底层输入由整套方案安排, 没有仅写“需要背景”就算条件满足. 处理当前前景之前的底层避免自我采样依赖.
- M6 条件尚未满足, 但它未被 S1 采用, 所以不构成 S1 的缺口.
- 未经渲染的近似方法仍是候选; gaps 不用于泛泛记录“还没测试”, 而用于已知的必要实现问题.
