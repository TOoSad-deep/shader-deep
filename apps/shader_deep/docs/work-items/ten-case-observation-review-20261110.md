# 十个观察 Case 综合审阅与 Agent 优化建议

- 日期: 2026-11-10.
- 性质: 基于实际报告的分析与优化建议, 本轮未改运行规则或业务代码, 未启动新的模型测试.
- 结论: 轻量单 Agent 的文件交付链路已跑通; 当前主要短板是观察归属、关系覆盖、必要缺口尺度和局部事实准确性. 优先优化单角色的判断与复查流程, 暂不扩展数据模型或角色数量.

## 3. 共性问题及对应原因判断

### 3.1 关系内容已经看见, 却没有正确归入 R

暖色水面 F9 已写“太阳倒影亮带”, 发光图形 F4/F6 已描述光晕彼此相接, 但两份报告 R 都为空. 面板小件也有大段布局文字, 却缺少面板与群体之间的布局 R. 这证明问题至少部分位于组织与归属, 不能一概解释成没有看见交互.

粉色圆则是另一类问题: 有 R, 但参与项没有覆盖 R 描述的轮廓. 当前程序只验证 ID 存在和类型合法, 无法证明参与项在语义上完整.

### 3.2 合并与分拆没有稳定的观察目标

磨砂图覆盖后的外观同时分布于 F3/F6 和 R2/R3, 会形成重复复现目标. 面板图的颜色与颜色分布也分散描述. S 图与极光的更多分项不一定全部错误, 但目前缺少一致的“独立目标才拆出”判断.

这里应校准主要归属和删除某项后的信息损失, 而非规定每图最多几项 F 或强行对齐参考编号.

### 3.3 gaps 混入本阶段不需要完成的精度

三份 partial 分别要求逐枚遮挡顺序、亮圆确切直径、像素级颜色与软硬程度. 这些不是当前粗粒度观察必须完成的工作. 同时, 三份报告确实又存在关系漏报或事实问题, 所以不能简单清空 gaps 让它们变 completed.

当前 completed 只反映合法提交及模型声明的缺口. 只靠模型有没有填 gaps, 不能判断真实观察覆盖是否足够.

### 3.4 局部视觉事实仍会被猜错

小件群的数量/簇分布、发光图形的排列方向、双链节点的裁切范围均有误读. 增加更多 E/F/R 字段不能自动解决这些错误; 需要有针对性地重看原图, 并限制无依据的精确数字与因果描述.

### 3.5 当前工具循环主要修合同, 不修语义

6 次校验拒绝说明错误反馈能促成合法提交. 但水面、发光图形和磨砂叠圆都在一次主模型判断后即合法接受, 随后不再调用模型; 这些案例仍有显著语义问题.

这与[会话接受](../../src/shader_deep/workflows/analysis/session.py)、[原生角色](../../src/shader_deep/agents/analysis/native.py)的当前合同一致. 结构合法即结束是目前语义复查的空档, 不是领域校验器实现错误.

现有 SKILL 已包含关系、去重和 gaps 规则, 所以再次重复同样段落不应被当作有证据的改进. 本次只能确认规则尚未稳定贯彻, 不能据此认定唯一原因是提示词、模型或图像输入.

## 4. 优化优先级与具体做法

| 优先级 | 优化 | 实施范围 | 验证重点 |
| --- | --- | --- | --- |
| P0 | 明确语义评价表 | 程序外评测记录, 不加模型必填字段 | 关键现象/关系覆盖、主归属、参与项、重复、事实、缺口分别记录 |
| P1 | 将提示改为“观察目标 -> 主归属 -> 提交” | 同一份 SKILL, 合并重复说明 | 关系文字不再被整体塞入 F, 不以增加 R 数量作为目标 |
| P1 | 用少量错/对片段校准边界 | 既有样例资源, 不建立新知识库 | 交互归 R、概括不重复、gaps 限必要可见目标 |
| P1 实验 | 一次同 Agent 的提交前复查 | 可选实验路径, 至多一轮, 保留现有单次提交作对照 | 能否减少漏 R/重复/误报 gaps, 是否抵偿额外时间和 token |
| P2 | 诊断实际工具使用和模型调用成本 | 复用日志/SDK 回调, 不存第二份历史 | 读了什么示例、失败在哪一字段、耗时和 token 在何阶段 |
| P2 | 做输出预算与整体时限实验 | 程序预算配置 | 在不增加截断/遗漏的前提下降低慢例成本; 超限不能算成功 |
| P2 按需 | 局部视觉回看与模型能力对照 | 复用图像工具, 保持角色单一 | 区分看错和分错, 证明收益后再默认启用 |

### 优先改观察组织, 保留轻量模型

先辨认必要主体与关键布局/交互, 再决定各现象主要存入 F 还是 R. 例如自身波纹属于 F, 与亮源位置对应的碎亮反光属于 R. 定位短语可以留在 F, 重要布局才单列 R, 不生成所有对象对的关系.

提交前复查固定三问: 是否有需要比较多个参与项才能说清的现象却只写在 F? 同一现象是否在 F/R 重复? gaps 是否遗漏必要可见目标而非未测精确数值? 这三问作为工作方法, 不增加新的 JSON 字段、置信度或解释链.

将 SKILL 中重复的归属和提交前检查合成一个规则入口; 正例保留少量关键片段, 增加相应错/对对照. 不要求逐字背出十张图的整份答案. 提示压缩是否改善遵循度仍需实验, 不能因文字更短就宣称效果更好.

### 同 Agent 复查只做有限实验

候选稿经过结构校验后, 将原图、候选稿及三项复查问题交给同一个 Agent 再判断一次, 然后才正式提交. 候选不发布成正式报告, 全程至多一次复查. 不新增独立评审 Agent, 不扩展 E/F/R 或补 M/S.

这是对当前“首次合法提交即结束”的合同调整建议, 尚未实现. 它会增加请求和可能的自我确认偏差; 不把复查回复当作自动质量证明. 建议先在代表性失败样例上 A/B, 无净收益则撤回, 不扩展成无限自审循环.

### 视觉回看先限定真实需要

先对照整图重查布局方向与裁切. 只有节点边界、局部细节确实难辨时, 再试一个返回真实像素和来源坐标的只读裁剪入口. 程序负责材料与坐标, 模型不维护 evidence_links 或证据图. 不让局部裁剪替代全图布局检查.

所有结果目前来自一个模型, 不能判断事实误读究竟主要由模型视觉能力还是当前输入/提示造成. 先固定模型测流程变化, 再固定流程做模型能力对照, 不同时更改两者.

## 5. 性能优化不能只看报告长短

新五图中 S 和双链共占 SDK 已报告 token 的约 75.6%, 分别耗时 228.64、344.07 秒, 但只用了 3、2 次主模型逻辑判断. 十图实际均为 1–3 轮, 因此扩大 8 轮上限不是现有首要方向.

目前只累计 SDK 报告的输入/输出/总 token, 没有完整区分主判断、摘要、推理 token 和底层请求. 不能把大量输出 token 都解释成报告正文, 也不能直接断言是 schema 过重导致慢例.

建议先复用日志记录工具名、受控文件路径、错误字段、调用阶段、耗时和可用 usage 细分, 缺失值保留未知, 不记录密钥、图片 Base64 或完整第二份对话. 文件预置可读不等于实际读过; 当前记录不足以确认示例读取对每图的作用.

随后固定规则与模型, 分别比较 8192、16384 与当前 163840 的输出上限. 数值是实验候选, 不是立即替换默认值的决定. 同时记录截断率和语义遗漏, 不能通过压短输出使它只报告更少目标.

45 秒请求尝试超时未形成单 case 总时长限制. 建议在运行层另设整体截止时间并保留中断产物; 超时明确记录超限, 不改成 completed. 总时限解决可控性, 本身不提高图像分析质量.

## 6. 最小实验顺序

1. 固定当前十份报告为可回归基线, 用固定语义评价项重审, 接受等价拆法, 不按编号和条数判分.
2. 仅改一处归属流程和小型错/对片段, 保持模型与预算, 对照水面、磨砂叠圆、发光图形等明确失败模式, 并检查网格/Windows 是否退化.
3. 在相同规则下单独实验一次同 Agent 复查, 比较改善与额外成本; 每种设置重复运行以区分波动, 不以一次成功认定因果.
4. 固定质量方案后再单独测预算; 视觉回看和模型对照按剩余错误类型安排.
5. 十图都已被用于开发审阅, 后续应作为开发/回归集. 泛化评估另留未用于规则设计的新图, 不将十图整份答案喂入后再宣称泛化通过.

整体优先级是语义覆盖与归属、缺口尺度、受控复查、可观测性和预算. 保持一个分析角色, 保持 E/F/R 合同简洁, 不用强制 R 数量、自动清 gaps 或批量改写报告来制造通过率.
