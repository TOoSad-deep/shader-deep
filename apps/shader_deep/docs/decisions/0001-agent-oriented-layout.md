# ADR 0001: 按角色、工作流和领域职责组织 Shader Deep

- 状态: 已接受, 2026-10-28 更新为原生分析并删除旧执行支持.
- 初始决策日期: 2026-09-24.
- 范围: `apps/shader_deep/`; 上游 SDK 不在本次改动范围内.

## 背景

原分析目录混合角色、调度、业务契约、网络恢复、材料读取与持久化. 多层循环继承及并存的四库/固定五库执行器使修改角色前必须理解过多历史机制. 用户明确选择优先采用 Deep Agents 原生能力, 并授权退出全部旧分析执行和回放支持, 以减少维护和阅读成本.

## 决策

1. `agents/analysis/native.py` 直接定义主 Deep Agent、两个或三个探索槽位及整合角色, 使用 SDK `task`、skills、backend、历史与摘要. `CompiledSubAgent` 外侧仅投影固定输入和权威回执.
2. `workflows/analysis/` 维护固定输入、冻结计划、槽位状态、合法产物与交付. 程序负责准入和领域提交, SDK 负责模型与子任务循环. 自然语言完成声明和 scratch 文件不构成业务结果.
3. `domain/five_libraries/` 集中维护字段、引用和合并保义; `infrastructure/` 负责模型传输、配置、文件存储和追踪. `imaging/`、`rendering/` 保持确定性图像操作职责.
4. 生成角色和工作流保持既有渲染、预览回读、选择与受阻结束能力, 分析到生成由用户显式选择.
5. 删除旧四库和固定五库执行、自建生命周期/恢复、回放、探索实验及仅服务它们的转发. 只保留当前公开分析/生成入口、五库消费者和仍被数据引用的历史模型与纯校验. 已保存 runs 与报告文件保持原样.

## 取舍

原生流程让新增工具与修改角色从直接角色定义开始, 无需维护另一套循环、线程池、恢复角色、持久共享额度或 skill 已读门禁. 对应代价是退出旧执行/回放支持, 再次分析创建新运行; 不能等价映射的旧高级参数明确拒绝.

数据读取与执行支持分别界定: 保留历史类型不承诺续跑旧会话, 合法五库包可继续读取及用于生成, 四库报告不自动转换或被五库读取器接受. 不为旧目录保留虚假占位实现. 初始目录整理与原生切换的历史验证保留在任务记录, 不作为本次删除后的新验证结果.

## 保持的边界

- 当前公开函数、核心参数、CLI 输出和五库契约保持. 高级配置变化明确记录.
- 探索材料隔离、实际图像呈现、合法提交及合并保义由程序保证. 整合失败保留合法 V0 和缺口, 无合法基线为 failed.
- 各图调用限制遵循框架语义; 不等同于所有子图和摘要请求的总费用额度.
- `completed` 不证明视觉正确, 文件快照不等于完整模型会话检查点.
