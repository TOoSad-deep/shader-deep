# ADR 0001: 按 Agent、工作流和公共职责组织 Shader Deep

- 状态: 已接受; 实现与交付状态见[重构任务记录](../work-items/structure-refactor.md).
- 决策日期: 2026-09-24.
- 范围: `apps/shader_deep/`; 上游 `libs/` 不在本次结构重构范围内.

## 背景

原 `analysis/` 同时承载角色、调度、业务契约、网络恢复、材料读取与持久化. 整合成为独立子 Agent 后, 仍通过多层继承使用整个探索会话. 理解一个角色需要跨越多种职责, 旧流程和当前流程也难以区分.

用户已确认以角色为主要阅读入口, 将分析保留为业务工作流, 并单独组织公共组件. 本记录保存选择理由; 当前代码地图见[架构说明](../architecture.md).

## 决策

1. `agents/` 聚合初稿、探索、整合和生成角色的入口、上下文、提示词与工具. 角色只开放本任务需要的操作.
2. `workflows/` 负责输入装配、阶段推进、探索并发、进度汇总和最终交付. 默认流程不继承旧探索会话.
3. `domain/` 维护任务、黑板、证据、四库和引用规则. 业务库通过持久化契约发布更新, 不直接操作文件或解析框架消息.
4. `runtime/` 管理角色执行、调用预算、历史、提交和修复. 每个角色拥有独立运行状态, 共享机制不等于共享历史或重置额度.
   同一角色响应内的工具按声明顺序执行, 独立探索批次的并发由工作流单独控制.
5. `infrastructure/` 适配模型传输、配置读取、文件存储和追踪. `imaging/`、`rendering/` 保持确定性图像操作职责.
6. 当前主快照由工作流更新. 子 Agent 报告复制后的进度, 协调器替换上次子任务进度, 避免重复追加缺口.
7. 保留四库统一校验和发布入口. 拆出查询、合并和存储代码, 不拆散一次业务提交的完整性边界.
8. 旧公开导入路径保留薄转发; 旧执行协议隔离到 `compatibility/`, 固定样本实验放在 `experiments/`. 默认实现不反向依赖兼容层.

## 取舍

- 继续按 `analysis/` 聚合全部相关代码, 可以减少迁移工作, 但无法解决跨角色共享机制与业务规则混杂的问题.
- 全部放进 `agents/` 会使四库校验和存储过度依赖某个角色, 不利于回放和非模型调用.
- 给每个组件增加基类、工厂或注册系统会扩大维护成本. 本次只在实际需要处保留接口, 例如存储替换和冻结回放装配.
- 兼容转发增加文件数, 历史实现也仍有维护成本. 保留它们是为了维持现有调用和数据读取; 后续删除需要单独核对调用方与迁移范围.

## 必须保持的行为

- 分析与生成继续独立, 不自动增加交接、评审或模型调用.
- 现有公开入口、CLI 输出及退出码保持兼容.
- 材料实际呈现、来源、引用、版本、修改范围和幂等规则继续由程序校验.
- 初稿与整合累计使用既有总调用预算; 失败和中断保留可追溯的部分结果.
- `completed` 不代表机制已证实或视觉效果已验收. 单文件快照替换不代表跨文件事务或完整模型会话恢复.

## 如何防止偏离

[仓库检查脚本](../../scripts/check_repository.py)覆盖以下直接依赖约束:

- `domain/` 不导入模型框架及其他应用层.
- `runtime/` 不导入具体角色、工作流或兼容会话.
- `rendering/` 不导入模型框架及其他应用层.
- 当前实现不通过旧转发路径或 `compatibility/` 回到旧流程.

这些静态检查不证明业务正确性, 仍需[开发指南](../development.md)规定的行为测试. 如果需要改变边界, 先记录新的决策及理由, 再同时调整实现与检查; 不通过临时豁免隐藏越界.

本决策被替代时保留本文件, 标明替代记录. 执行进度和测试次数只更新任务记录, 不复制到本决策中.
