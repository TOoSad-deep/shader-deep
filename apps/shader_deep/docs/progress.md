# Shader Deep 项目进度与思路

最后更新为 2026-11-25。

本页用于恢复项目全局: 先看当前阶段和下一步, 再按链接阅读任务细节. 首版依据当前入口、架构与已有工作记录整理; 历史验证不代表本次重新实测, 未记录的进展仍需补充.

## 总目标

从 PNG 参考图和文字要求出发, 分析可观察特征与候选机制, 生成可控制的过程式 Shader, 通过真实渲染、对照和人工反馈逐步改进结果. 保留输入、方案、代码与图像的来源, 便于继续试验和解释选择.

## 当前阶段

已有独立分析和生成流程, 以及报告到生成、方案比较、两元素整图组合和本地网页入口. 当前仍由用户显式选择方案, 尚未形成独立视觉评审与持续优化的自动闭环.

2026-11-25 完成整体流程 Review 并确认[整体流程优化设计方案](work-items/workflow-optimization-design-20261125.md)（设计定稿）：确立“整图主干优先 + 高风险局部隔离试验”、以 `uniforms` + 像素测量驱动的受控数值优化器替代对话式调参 Agent、将主控拆为跨制品诊断 Agent 与确定性控制面，并在执行内环自治与三条有界自动微回路之外保留门禁 A/B 人工拍板。

2026-11-18 已接通独立视觉评审首版. 同一个角色通过 feature/element/scene 模板和固定任务标准比较显式 PNG, 发布六维差异与派生结论. API、CLI 与正式报告读取已实现, 工程检查和待校准范围见[评审实施记录](work-items/independent-visual-review-implementation-20261117.md#10-2026-11-18-工程实施记录).

2026-11-11，用户已认可现有 E/F/R 输出为可用基线。[单个全图规划 Agent](work-items/scene-planning-agent-plan-20261111.md)的领域合同、固定输入、草稿 harness、正式规划包、API/CLI 与整图生成接线已实现。十个 case 最终交付为 8 completed、2 partial，两图均有真实生成与预览。M 自包含、备选独立正文和视觉偏差集中写入实施记录。

2026-11-10 [单 Agent 全图 E/F/R 观察](work-items/single-agent-observations-20261110.md)阶段 1–3 已接入: 一个分析角色输出上下文、多元素 E/F/R, 提交、校验、文件包、公开入口、配置及网页已迁移, 保留旧完整五库包读取. 260 项单测与 lint/type/仓库检查通过, HTTP 集成 4 项通过. 授权的五图实测均能合法交付, 第二轮为 4 completed / 1 partial, 另保留一次连接失败. 粒度尚有偏差, 阶段 4 未通过, 不能据程序完成宣称视觉验收完成.

2026-11-04 累计提出七个方向: 独立 Watchdog Session 作为守护 Agent, 及时发现问题并修复; 构建 VISTA 多模态记忆系统; 完善租约系统; 优化子 Agent 系统并推进子 Agent 专精化; 维护工具池并探索工具自适应、自优化; 搭建评测系统; 构建达标与停止条件. 当前记录方向, 实施范围、优先级及相互依赖尚待细化, 列举顺序不表示排期.

VISTA 方向延续公共视觉记忆的已有讨论: 怎样保留、发现和回看多模态材料, 再支持后续调参. 2026-11-09 已确认[最小 harness 首版设计](work-items/vista-minimal-harness-todo-20261109.md), 当前待实施; [原讨论清单](work-items/vista-discussion-todo-20261028.md)已留档, 不再作为逐项定稿的前置流程.

VISTA 后续实施按最小 TODO 推进, 复杂检索和更广的公共能力在真实需求出现后细化. 本轮先做单 Agent 分析, 不扩大 VISTA 的实施范围. Watchdog 与租约方向分别需要明确守护及修复边界、现有租约机制与待完善问题.

## 当前重点与下一步

- 磨砂叠圆实验验证了测量证据可用于一次局部亮度修订。元素与整图校准检出了明确缺项，也发现外轮廓证据不足时的一次误拒。[评审实施记录](work-items/independent-visual-review-implementation-20261117.md#16-元素与整图的小样本校准)
- 此前 M/S 规划交付验证通过 377 项无网络测试、22 项浏览器集成、安装包及轨迹核对. 运行结果、预算收口、语义和视觉偏差集中记录到[规划实施记录](work-items/scene-planning-agent-plan-20261111.md).
- 新五图独立测试: 修订后的 Codex 分析仅作对照, 未送入 Agent. 原规则下五图均合法交付, 3 completed / 2 partial; 水面/发光图形漏 R、精度缺口和局部事实误读仍需处理. 逐图指标见同一[实测记录](work-items/single-agent-observations-20261110.md).
- 十图综合审阅: 同规则最终十份报告为 7 completed / 3 partial, 不作为准确率. 下一轮优先验证观察归属流程、少量错/对片段和受控同 Agent 复查, 再测预算与视觉回看; 建议尚未实施, 见[综合分析](work-items/ten-case-observation-review-20261110.md).
- 其余方向: 继续保留候选与各自的设计状态, 不因本次开发准备自动扩大实施范围.
- Watchdog 续接点: 选一个需要及时发现并修复的问题, 明确监测信号、触发条件、可执行修复动作和修复成功依据.
- VISTA 续接点: 按[最小 TODO](work-items/vista-minimal-harness-todo-20261109.md#todo)准备生成会话接入, 复用已确认的材料索引、列目录、读取与上下文保留约定.
- 租约续接点: 定位现有设计或实现, 明确租约管理的对象及实际问题; 领取、续租、到期与回收可作为盘点项, 不预设现有系统缺少这些能力.
- 子 Agent 续接点: 从一类具体子任务出发, 明确需要的专长、输入材料、可用工具和交付结果, 再与现有角色配置比较质量、可靠性与成本.
- 工具池续接点: 盘点现有工具及使用反馈, 明确自适应、自优化针对工具选择、配置、说明还是实现, 再选一个工具或任务场景做最小验证.
- 评测续接点: 先选定一个评测对象和一组固定样本, 明确评价维度、人工判断与自动指标的分工, 固定版本、模型及预算等比较条件, 保留结果与失败证据.
- 达标与停止条件续接点: 从一个具体任务定义可检查的达标依据, 再明确何时继续迭代、何时停止; 区分质量达标、预算或时间耗尽、受阻及人工停止, 阈值与判断方式待讨论.
- VISTA 后续: 先完成最小闭环并记录实际效果, 更广场景、跨任务复用和复杂检索按真实问题展开; 历史讨论仅供按需参考.
- 待补充: 若已有晚于上述记录的实现、实测或方向调整, 更新对应任务记录及本页摘要.
