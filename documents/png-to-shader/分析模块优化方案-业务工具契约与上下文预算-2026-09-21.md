# 分析模块优化方案：业务工具契约与上下文预算

日期：2026-09-21

修订：2026-09-22，补齐读取原子性、工作分页、修复额度归属及分步验收。

状态：方案主体已实施，当前验证状态见第 12 节。第 1～10 节保留设计契约与实验起点，不将计划中的后续拆分能力视为已实现。

范围：主 Agent 的查询、读取、增量编辑、比较组管理、输出预算、上下文驻留和局部修复。

## 1. 核心结论

**预设清楚的业务工具与输入输出契约，让主 Agent 选择对象、比较材料并提交增量；完整四库、来源、版本和事务由后端维护。**

当前已经有工具调用能力，不需要重新搭建一套通用 CRUD，也不需要先封装 MCP。本次优化以现有 `list_library`、`read_library`、`submit_integration`、`repair_analysis_submission`、测量与结束工具为基础。

预设的是允许执行的操作和检查规则，不是预设图像分析结论、候选机制或固定的材料分包。竞争机制继续保留，是否正确需要后续编码与渲染验证。

本方案承接[四库按需读取与批量整合方案](分析模块优化方案-四库按需读取与批量整合-2026-09-21.md)。旧文档中的实施状态和历史描述需结合当前源码核对；本文以本次读取的源码和实测记录为依据，不把方案条目写成已实现能力。

本轮收紧五项契约：目标范围变更整体接受或回滚；辅助正文允许按完整条目部分读取；判断材料之外保留交互与修复空间；必要工作完整保存、分页发现；格式修复额度绑定阶段或工作身份。先修复已确认的退出缺陷并建立整合基线，再分别评估预算和上下文优化。

## 2. 已观察到的问题与证据边界

本次参考实测使用 `2d-physics-balls.png`，模型配置名与源码指纹保存在实测清单中。6 个探索任务均完成；主 Agent 的首个比较组最终为暂缓，整次结果为 `partial`。

| 已确认事实 | 对本次优化的意义 |
| --- | --- |
| YAML 的 `max_output_tokens` 为 163,840，Python 内置通用默认值为 16,384 | 实际运行采用较大的 YAML 值；不能用内置默认值解释本次预算 |
| 主、子 Agent 共用输出上限，完整请求估算也全额预留该值 | 增量整合和完整探索报告没有分开配置 |
| 主调用第 10 次报告输出 30,852 tokens，其中推理 27,664，非推理部分 3,188 | 大输出主要包含推理；不能把工具 JSON 长度当成全部输出量 |
| 探索任务的单次输出峰值为 33,418 tokens，其中推理 26,708 | 子任务预算也应根据实际总输出选择，不能只按报告字符数决定 |
| 第 10 次主请求消息文本为 69,466 字符，其中工具历史为 31,248 字符 | 目录、调用参数和错误反馈占用上下文；仅控制候选正文不够 |
| 首组最终扩展到 78 个目标 ID，实际选取正文仅 6 条 | 目标范围扩展与实际材料容量失配，需要约束并原子接受范围变化 |
| 最终退出原因为 `Analysis format-repair budget exhausted; no valid report was fabricated`，累计格式修复计数为 2 | 最终退出不能归因于服务端上下文窗口超限；需处理格式修复计数跨阶段沿用的问题 |

第 10 次主请求的应用估算为 257,251 / 262,144，其中包括 163,840 的输出预留；服务报告的实际输入为 32,201 tokens。这是两套口径，不能混称为模型真实上下文已用满。

## 3. 实施边界

保留独立探索、冻结初稿、四库业务 Schema、候选归属、来源追溯、别名映射、局部修复和整批最终校验。公开 `run_analysis` / `run_analysis_task` 入口保持兼容。

本次不增加 Agent、数据库、通用文件系统编辑工具或任意 JSON 执行能力；不开放直接删除候选的接口；不通过丢弃必要工作、候选或失败记录获得 `completed`。

工具接入继续使用本地适配层，复用 `LibraryStore` 和现有测量能力。只有出现其他独立 MCP 客户端复用需求时，再评估增加薄的 MCP 适配层。MCP 不负责替宿主管理这些上下文预算和业务状态，不能作为本次问题的直接修复。

## 4. 固定业务工具契约

### 4.1 按业务操作定义工具

首轮保留现有工具名和主要业务字段，先减少误用和无关输出。必要工作分页补充只读的 `list_comparison_work`，初稿问题及其他完成缺口由 `list_analysis_context` 分页读取；两者只投影现有台账，不增加存储层。

| 能力 | 工具或字段 | 前置条件 | 成功后的变化 |
| --- | --- | --- | --- |
| 查目录 | `list_library` | 库、筛选条件和游标有效 | 更新当前发现视图，不标记正文已读或比较完成 |
| 查必要工作 | `list_comparison_work` | 工作筛选条件和游标有效 | 分页返回工作索引，不修改完成状态；详见第 6.5 节 |
| 查其他完成缺口 | `list_analysis_context` | 类别、游标及页大小有效 | 分页返回初稿问题、失败任务或未覆盖元素；未完整呈现的问题不能被关闭 |
| 读正文 | `read_library` | 范围变化、目标必要正文、回执和修复预留通过准入；辅助正文按第 5.1 节部分接受 | 原子发布本次范围与选材；下一请求实际包含正文后才登记呈现 |
| 新增 | `submit_integration.additions` | 现有引用及必要判断材料合法 | 校验后新增条目，由后端分配正式 ID 并保存来源 |
| 改引用 | `submit_integration.reference_updates` | 草图处于比较目标内，相关材料版本已呈现 | 调整引用与局部顺序；保留未修改组成和库中候选 |
| 合并重复项 | `submit_integration.merges` | 成员、归属、适用范围和必要前提满足条件 | 合并身份、保留必要候选并集、机械改写引用和别名 |
| 原样保留 | `submit_integration.preserve` | 当前目标的必要正文已呈现，无未处置冲突 | 关闭本次目标比较，不把辅助材料或未展开候选标成完成 |
| 后续复核或暂缓 | `review_ids` / `deferred_work` | 有明确范围或原因 | 保存必要工作；不能以保留声明消除它 |
| 局部修复 | `repair_analysis_submission` | 草稿 ID、版本、JSON Pointer 有效 | 修改草稿并重新执行相同校验，不直接修改正式库 |
| 测量与复用 | `measure_reference` / `read_measurements` | 属于当前运行，满足测量及上下文额度 | 保存证据，按预算选入完整文本及真实裁剪图 |
| 结束 | `finish_analysis` / `stop_analysis` | 满足各自终态规则 | 后端导出实际结果；已终结状态不被后续调用覆盖 |

“删”分两种处理：重复库项只通过合并退役旧 ID，保留别名与来源；从某个草图撤销引用，走受校验的引用修改，不删除底层候选。删除任意业务对象不属于本轮工具能力。

### 4.2 简化模型可见的参数

- 每个工具说明写清允许范围、最小参数、成功结果和常见拒绝条件，不要求模型复制后端台账。
- `run_id`、当前组身份、提交身份、实际呈现版本等可由后端绑定的字段，继续由后端维护。
- 未使用的可选字段按实际 Schema 支持省略；需要空值时使用 JSON `null`，不自动把字符串 `"null"` 猜成空值。
- 新建比较、接续必要工作和同组补读是不同使用场景。先提供各自最小示例；如仍频繁混用，再验证按当前状态收窄可见字段，执行白名单与服务端校验同步收窄。
- 不为简化提示词而降低身份、类型、版本、范围和呈现校验。

### 4.3 最小调用示例

以下 `E3`、`F1` 等为说明用途；运行时必须使用目录返回的完整 ID。

发现同一元素的特征：

```json
{
  "library": "feature_library",
  "element_ids": ["E3"],
  "limit": 8
}
```

围绕一个现象建立比较并读取拥有者正文：

```json
{
  "comparison": {
    "question": "F1 与 F2 是否描述同一种齿轮外轮廓？",
    "target_ids": ["F1", "F2"]
  },
  "requests": [
    {
      "library": "feature_library",
      "ids": ["F1", "F2"],
      "include_candidates": false
    }
  ]
}
```

明确重复时，只提交合并参数，不重写四库：

```json
{
  "merges": [
    {"kind": "feature", "members": ["F1", "F2"]}
  ]
}
```

确认需要保留差异时：

```json
{"preserve": true}
```

这些示例不表示所有工具输出都很短。当前 `reference_updates` 仍提交完整的被修改草图，`additions` 也可能较大。首轮先保留此兼容形状；若实测证明它们仍占主要开销，再单独设计按草图引用定位的领域补丁。领域补丁仍经 `submit_integration` 批量提交和最终校验，不开放任意对象路径写入，也不在本轮同时替换整套提交协议。

## 5. 缩小比较范围，防止整组膨胀

一组应围绕一个能够明确处置的问题，例如“几个报告中的中心孔外观是否重复”，或“本次合并引起的某张草图引用冲突如何修复”。不把整个图的组成、形状、配色和层叠全部放进同一问题。

### 5.1 范围变化与辅助读取分别准入

拟定规则：

1. 提示主 Agent 优先从 2～6 个目标开始；辅助材料不计为待完成目标。
2. 增加可配置的目标数量上限，首轮实验值可取 12。该数仅限制一次工作的规模，不代表语义质量标准；必要跨库比较仍允许。
3. 新建、接续或扩展目标时，在临时状态中同时检查目标数量、目标必要正文、完整请求、回执和修复预留。通过后一次发布范围、版本与选材；失败不创建活动组、不推进工作版本、不改变已有目标与正文，失败事件单独保留。
4. 扩展请求被拒绝，不撤销此前已经登记的必要冲突或复核。剩余工作仍可独立登记，不能隐藏在“未展开保留”中。
5. 本组判断材料齐备后及时提交。接受或明确暂缓后释放本组正文，再处理下一问题；不为了填满窗口持续扩展目标。

目标数量上限只是程序约束；是否属于同一问题仍由主 Agent 判断，不增加另一模型来给比较组打分或自动分包。

| 调用类型 | 必须整体满足的部分 | 允许部分接受的部分 |
| --- | --- | --- |
| 新建比较 | 全部目标的完整正文及直接必要材料可进入当前组 | 同次显式请求中其余辅助条目 |
| 接续 `work_id` | 保持原工作身份与完整范围；重新选入全部目标必要正文 | 其余辅助条目；不得用接续隐式缩小原工作 |
| 扩展 `extend_target_ids` | 新增目标必要正文可进入当前组，已有目标材料仍完整且版本有效 | 其余辅助条目；新增目标有一项不满足则本次范围与选材均回滚 |
| 仅补读辅助材料 | 当前范围不变，已有正文完整，回执可容纳 | 按请求顺序、以完整条目为单位选入；返回未提供 ID |

这里的“目标必要正文”是可机械检查的最低条件：目标对象本身；候选目标还需拥有者及现有业务校验要求的直接前提。读取拥有者不自动展开全部候选，不递归展开全部引用；模型仍需为具体决定补齐其他判断依据，最终提交继续执行现有呈现校验。缺少显式读取项时返回具体缺失 ID，不暗中扩大读取或修改范围。

所有调用先校验全部 ID、类型与归属，再选材；非法参数不产生部分成功。目标必要正文优先于辅助条目占用预算。回执整体无法容纳时，不发布本次任何变化；辅助读取全部放不下时返回明确拒绝，不能仅以 `status=selected` 表示取得进展。已选材料可去重，但选中或缓存命中均不等于已呈现。

例如，将目标从 `F1/F2` 扩展为 `F1/F2/F3/F4` 时，若只能装入 `F3`，目标和正文均维持调用前状态；如果目标不变，只补读 `F3/F4` 作为辅助材料，则可以完整选入 `F3` 并明确报告 `F4` 未提供。

### 5.2 数量上限之外，还要给交互和修复留空间

目标数量合格不代表当前组能完成。准入同时满足：当前完整输入（包含实际历史、工具、原图和测量）＋本阶段输出预留＋尚未被实际历史占用的交互及修复预留＋编码余量，不超过配置窗口。复用并明确现有 `integration_history_tokens` 的预留语义，避免把已计入的历史重复当成空闲预留；字符估算仍与真实 token 用量分列。

该预留用于下一轮决定、短错误回执和局部修复，不承诺任意大小的未来草稿都能容纳。草稿产生后按实际大小重新检查；无法容纳的处置见第 6.3 节。不能为了接受更多目标而挪用预留，或在出错后静默减少必要正文。

### 5.3 超大必要工作的处置与拆分边界

首轮不新增拆分工具。超过目标上限或最低材料预算的已有必要工作保留原身份、范围、原因和可查询入口，标明本轮无法接续；当前运行可继续其他工作，最终仍须报告该项暂缓及 `partial`。正常调用拒绝本身不把工作改成完成，也不能通过另外新建几个小组自动冲销原工作。

若后续确需增加显式拆分能力，应作为独立增量实施，并满足以下契约：

- 主 Agent 提出子问题及目标分组；后端校验全部子范围的并集覆盖原范围，允许因共同判断材料产生交叠，但不允许遗漏目标或凭空增加范围。
- 父工作保留原判断义务及子工作链接。仅覆盖 ID 不证明语义义务已完成；跨子组冲突、重复判断等保留为独立的必要协调工作。
- 全部子工作及协调工作完成后才可关闭父工作；任一暂缓或材料变化触发复核时，父工作继续阻止完整交付。
- 拆分登记原子完成；子工作计入全运行组数与调用边界，并共享原工作剩余的格式修复额度，不能借拆分刷新额度。

在这项能力实施并验收之前，首轮只能准确交付此类工作为暂缓，不宣称支持超大工作的自动完成。

## 6. 上下文按用途管理

### 6.1 三类信息分开保存

| 信息 | 后端保存 | 默认送入模型 |
| --- | --- | --- |
| 四库、原始报告、来源、历史版本、完整调用记录 | 完整保存 | 仅本轮实际需要的部分 |
| 当前比较目标、正文、判断依据、测量和待修复草稿 | 按工作身份及版本保存 | 当前组所需的完整判断材料 |
| 目录页、读取回执、已消费错误、历史成功决定 | 保存可追溯记录 | 有界索引或简短状态，不长期携带完整历史副本 |

### 6.2 控制目录和回执驻留

目前 `list_library` 的完整返回会进入工具历史；新请求又注入默认目录页。首轮优化应优先处理这部分，而不是继续缩减候选机制正文。

- 无活动比较组时，提供一页当前目录及必要工作入口。
- 已进入比较组时，默认提供当前目标与辅助材料的必要索引，不每轮重复无关目录首页。其他条目仍可主动查询。
- 目录页按返回字符预算和条目数量双重分页；超大页在返回前拆小，保留可继续查询的位置，不截断条目正文或谎称遍历结束。
- 若单个目录索引也超过页预算，返回有界的身份、类型、计数和超限标志，并保留可查询的完整详情；索引投影可以缩短，判断正文不能截断。不得反复返回相同的空页游标，也不得把超限条目视为不存在。
- 当前目录视图保存最近需要使用的查询页；已消费的旧目录回执在下一次请求中可替换为查询条件、返回范围、剩余数和游标等简短信息。
- 处理工具历史时必须保留合法的调用与响应配对。不能只删 ToolMessage 而留下悬空调用，也不能把尚未呈现的读取结果登记为已读。
- 查询大目录后的第一次正文读取不应继承所有已消费目录页全文；可在同一次下一轮请求构造中整理发现历史，不增加专门的模型总结调用。

### 6.3 保留修复所需材料

历史整理不能让局部修复失去依据。当前未解决错误、有效草稿及必要正文必须仍可见。

若需要移除包含大段旧提交参数的历史调用，应先由后端提供当前有效草稿及错误位置，并确认下一请求可完整容纳；不依靠模型自行复述草稿。已解决的旧错误保留简短处理记录，原始错误和旧草稿留在制品中。

新草稿及每次修复版本先保存；校验未通过、需要继续修复时，再检验下一次修复请求能否容纳完整草稿、错误和必要判断材料。已经通过全部校验的提交按正常事务发布，不额外要求预留一份假想的修复草稿。优先移除已消费目录、旧成功决定及重复草稿副本，保留工具调用配对；实际预检使用与正式请求相同的构造器。若仍放不下，保存草稿与明确的 `repair_context_exceeded` 原因，暂缓当前工作并退出该组，可继续其他工作。不得截断草稿、发布其中部分操作、要求模型凭记忆重写，或将该工作计为完成。此处置无需额外模型调用，也不扣除格式修复额度。

### 6.4 预算准入的一致性

目录返回、正文补读、测量、裁剪和状态回执都应计入即将形成的实际请求。回执同时出现在工具历史和控制上下文时，必须计算两份开销，或明确只保留一个完整呈现位置。

拒绝时区分原因：正文放不下、回执放不下、历史占用过多、目标范围过大。若连最小补读都无法容纳，反馈应指向提交或暂缓当前组，不反复建议无效的“再缩小一点”。

拒绝路径也需预留有界反馈空间；缺失 ID 很多时返回数量、有限示例和可查询的完整记录。若整理后的最小控制请求仍无法通过预算检查，由后端保存准确的暂停或结束原因，不发送超预算请求，不承诺模型必然能再收到一轮反馈。

最终执行顺序保持为：构造候选请求 → 完整预算检查 → 登记实际呈现的字段与版本 → 发送模型请求。缓存存在、文件已保存或读取回执成功，都不替代呈现检查。

### 6.5 必要工作完整保存、分页发现

当前 `ComparisonManager.summary()` 无条件展开全部必要工作，只裁剪已完成工作。拟调整为：默认上下文提供全局状态计数、当前工作及一页必要工作索引；后端仍保存完整台账。必要工作包括待处理、比较中和暂缓项；初稿问题、失败任务等阻止结束的信息也应纳入有界控制视图，不能成为另一份无限增长的默认列表。

拟新增 `list_comparison_work`，最小参数为状态筛选、可选 `work_id`、`cursor` 和 `limit`；返回工作身份、问题摘要、状态、目标数、目标索引或其分页入口、原因、总数、剩余数和游标。查询指定工作也遵守字符预算；超长问题与原因保存完整详情，详情无法整体呈现时明确报告，不能根据摘要宣告工作完成。

页大小同时受条目数和字符预算约束。游标绑定筛选条件及台账版本；工作状态变化导致失效时明确要求重新查询，不能静默跳过条目。旧页按第 6.2 节整理，不把连续分页重新累积成完整历史。

`finish_analysis` 始终检查完整后端台账、未决初稿问题、失败任务及其他既有结束条件，与当前页面是否为空、某条工作是否被呈现无关。分页隐藏的是本轮未用的索引副本，不是完成义务；暂缓项目始终可查询并计入未完成统计。

## 7. 分阶段设置输出预算

### 7.1 拆开参数用途

拟增加阶段输出参数，由单一解析函数产生本阶段的有效输出上限：

| 拟新增参数 | 用途 | 首轮实验起点 |
| --- | --- | --- |
| `outline_max_output_tokens` | 主 Agent 的初稿与探索方向 | 8,192 |
| `integration_max_output_tokens` | 主 Agent 的推理与增量工具参数 | 32,768 |
| `worker_max_output_tokens` | 子 Agent 的推理与完整三库报告 | 65,536 |

以上仅是根据本次观测峰值选择的实验起点，不是提供方能力声明或已验证最优值。尤其主整合峰值 30,852 已接近所列实验值，必须检查截断率和修复情况；不能为了降低数字强迫模型丢弃必要内容。

保留旧 `max_output_tokens` 作为兼容回退。阶段字段未设置时不注入实验值；若增加阶段 CLI 参数，优先级明确为：阶段 CLI > 通用 CLI > 阶段 YAML > 通用 YAML > 现有通用内置默认。已有显式通用 CLI 覆盖仍作用于全流程，避免迁移后失效。上述实验值只通过显式阶段配置启用，验收前不替换正式默认值；有效配置同时记录值及其来源，区分用户输入与解析后的回退值。

### 7.2 请求与预留使用同一个有效值

模型请求中实际发送的输出上限、本地请求预算的输出预留，以及运行记录中的有效配置必须一致。不能本地只预留 32,768，却继续向服务声明可输出 163,840。

阶段切换时同步更新模型绑定参数和 Context Builder 使用的预算；不重置主 Agent 累计调用数。原图和工具 Schema 仍按实际请求计入。

输出额度按提供方返回的口径观察，明确区分推理 token 与其他输出 token。当前记录表明输出包含大量推理，不能只根据工具 JSON 很短就把总输出上限设为几百。是否能单独限制推理强度，需核验实际服务能力后另行处理，本版不依赖未经验证的模型参数。

文本字符估算与服务用量继续分列记录。首轮不引入未验证的 tokenizer，也不把缩小预留解释为已经降低实际成本。

## 8. 修复计数与错误契约

当前 `AnalysisExecution.format_repair_calls` 被主 Agent 多个阶段共用，而循环使用固定的格式修复阈值。初稿消耗修复机会后，整合阶段可能没有新的格式修复机会。这次实测最终计数为 2，触发的正是这个出口。

### 8.1 额度绑定业务身份

拟将“当前初稿阶段或当前比较工作的格式修复额度”与“全运行累计修复统计”分开。额度由会话或工作台账持有，不以 `AnalysisLoop` 对象的生命周期为边界；首轮沿用每个作用域两次的阈值，优先修复归属，不同时改变容忍次数。

| 场景 | 额度归属与变化 |
| --- | --- |
| 初稿提交及其局部修复 | 使用本次运行的初稿额度 |
| 尚未建立比较的发现阶段 | 使用本次运行的发现额度；翻页或重建循环不重置 |
| 成功建立新的比较工作 | 按 `work_id` 建立独立额度；初稿和发现阶段消耗不挤占它 |
| 同组补读、材料刷新、工作版本变化、循环重建 | 沿用同一 `work_id` 的已用额度 |
| 暂缓后接续，或已完成工作因材料变化重新复核 | 原工作身份沿用原额度；不能通过重新打开清零 |
| 未来拆分同一必要工作 | 子工作共享父工作剩余额度，不分别领取新额度 |
| 全运行诊断 | `format_repair_calls` 保留累计统计，不作为单组阈值 |

同一失败提交的归属以产生该提交时的阶段或工作身份为准，不能在下一轮因为状态切换扣到另一组。一次逻辑修复请求只扣一次；发送前预算拒绝不扣次数，网络重试不重复扣次数。总模型调用、组数、无进展和网络重试边界独立生效；不能通过反复新建组绕过全运行边界。

### 8.2 错误分类决定恢复动作

错误回执统一提供真实参数路径、错误类别、具体原因和必要的缺失 ID。非法 `review_ids` 应定位到 `/review_ids/索引`，不能退化为空路径。区分格式错误、业务引用错误、材料未呈现和预算拒绝，给出可执行的下一步，不让模型把所有拒绝都当作需要重写整个提交。

| 类别 | 典型恢复动作 | 是否消耗局部格式修复额度 |
| --- | --- | --- |
| JSON 语法或 Schema 结构错误 | 提供解析位置；存在有效草稿时按真实 Pointer 修复 | 实际发起下一次格式修复请求时消耗 |
| 业务引用、类型归属或范围冲突 | 改正局部业务参数，或显式调整范围 | 否；仍受调用和无进展限制 |
| 材料未呈现或版本过期 | 补读并实际呈现，或刷新后重新判断 | 否 |
| 输入、回执、目标数或修复上下文超限 | 整理历史、缩小尚未接受的请求，或暂缓当前工作 | 否 |
| 输出截断 | 保留旧有效草稿，记录截断；仅在剩余调用与无进展边界内重试 | 否，不混记为 JSON 格式修复 |

路径必须来自真实参数或草稿；无法解析成 JSON 时报告解析位置，不伪造 JSON Pointer。完整错误保存在制品中，模型侧反馈按预算有界呈现。上述分类和恢复动作需要同步反映在工具说明与日志中。

完整合法 JSON 草稿先保存，再做校验；修复后仍执行相同的范围、版本、呈现和事务检查。推理或输出被截断时不执行残缺工具调用。结束、停止及重复调用均不得覆盖已经终结的状态。

## 10. 验收与对照

| 场景 | 必须验证 |
| --- | --- |
| 最小增量提交 | 合并只需成员 ID 等业务参数；没有重写整库要求 |
| 删除边界 | 没有任意删候选入口；撤销草图引用不删除底层候选 |
| 目标与辅助材料 | 辅助读取不自动授权修改、不自动标为比较完成 |
| 新建、接续或扩展失败 | 必要正文有一项放不下则不发布本次范围与选材；已有目标、正文、版本和必要状态不变，新建失败不留下活动组 |
| 辅助部分读取 | 目标不变，能容纳的条目完整接受；未提供项明确返回，零新增不冒充进展 |
| 超大必要工作 | 原身份及义务仍可查询、继续阻止完整交付；首轮准确暂缓，新建小组不能冲销原工作 |
| 大目录和连续分页 | 返回与历史均受预算约束；剩余内容可发现；不存在悬空工具调用 |
| 工作分页与失效游标 | 多页必要工作不全部驻留；遗漏页仍影响后端结束判断；台账变化明确使游标失效 |
| 单个索引超大 | 有界索引仍保留身份和详情入口，不循环空页、不静默遗漏 |
| 大回执或正文超预算 | 预留的短反馈可以进入下一请求；若最小请求也不可容纳则准确停止并保存原因，不发送超预算请求；未呈现内容不能参与修改 |
| 主子阶段预算 | 无网络模拟请求验证实际输出参数与预算预留一致；旧 CLI/YAML 优先级正确 |
| 输出截断 | 不执行残缺调用、不丢失旧有效草稿，终态准确 |
| 跨阶段修复 | 初稿耗用两次格式修复后，整合组仍有自己的额度；累计调用限制保持有效 |
| 修复额度不能刷新 | 同 `work_id` 刷新、重建、暂缓接续均沿用消耗；发送前拒绝和网络重试不重复扣次 |
| 错误类别与修复归属 | 格式错误定位至原阶段或工作；业务、材料、预算拒绝不挤占格式修复额度，仍受其他边界限制 |
| 同组修复与历史整理 | 整理后仍可按真实 Pointer 修改同一份草稿，不要求重新规划整组 |
| 修复草稿超大 | 完整版本已保存；整理后仍无法容纳则暂缓，不截断、不局部发布、不额外调用模型 |
| 原子发布与终态 | 合并和引用修复可同批成功；失败无半成品；重复停止不改写已有终态 |
| 成功组间过渡 | 第一组事务成功后释放正文，下一组可重新发现、选材并提交；已完成义务不被错误重开 |
| 显式结束 | 未展开内容保留，必要复核未完成时不能用 `preserve` 伪装全部完成 |

先做无网络回归和真实请求形状检查，再使用本次已保存的同一组探索报告比较整合行为，减少重复探索和随机性。真实服务对照应显式限次，并保存输入、有效配置、源码指纹、退出原因和所有失败尝试。

回放输入须包括原图、用户要求、冻结初稿、全部探索报告、初稿问题及失败任务状态，不能只复制四库而遗漏完成义务。每次从独立输出目录和同一初始库状态开始，不带入旧运行的接受决定、呈现记录或修复计数；该测试不再次运行探索。它只能证明固定输入下的整合行为，不能替代后续完整单图运行，也不能以一次样本声明稳定的成本收益。

对照指标包括：完整/部分交付及退出原因、接受事务与成功组间过渡次数、必要工作完成情况、候选保留与来源、主子模型轮次、工具成功/部分接受/拒绝次数、组目标数、实际呈现正文量、目录与工作索引历史峰值、请求估算峰值、输入/输出/推理 token、截断和各作用域修复次数、总耗时。没有提供方用量的字段标为不可用，不以字符数填充真实 token 指标。

只有在内容保留、引用合法及必要任务完成情况没有退化的前提下，才讨论调用量或成本收益。不用提高上下文窗口、删除候选、隐藏失败或降低完成标准替代优化。
