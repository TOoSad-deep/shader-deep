# 独立多视角分析

当前实现范围：输入 PNG、用户要求与分析目标，输出原始视角报告、按需取得的程序证据和综合结果。主 Agent 负责分析范围内的规划、检查、统一取证、补充与综合；后续持续决策、生成调度和独立视觉评审不在本模块内。

已有测试暴露的问题、验证缺口与后续优先级见[问题与优化方向（2026-09-15）](/Users/douwen/Documents/HUAWEl/Shader-Agent/shader-deep/documents/问题与优化/多视角分析-问题与优化方向-2026-09-15.md)。该轮测试已经停止，未完成的运行不计为成功。

## 执行关系

```text
目标记录 + 主分析任务
    ↓
主 Agent 选择预置视角 / 创建新视角配置
    ↓ run_analysis_batch
程序登记父子任务、绑定配置快照、固定图像输入
    ↓
多个独立 Deep Agent（受并发和次数上限约束）
    ↓ submit_analysis_report
程序集中登记报告或失败记录
    ↓
主 Agent 检查覆盖、关键判断和子报告中的取证需求
    ↓ 按需 measure_reference（每批结束后统一测量、复用证据）
主 Agent 按需驱动补充/复核任务，显式选择报告与证据
    ↓ finish_analysis
程序校验证据引用并保存 AnalysisSummary
```

同一模板承载 2D 图形、3D 空间、美学、物理组成四个预置视角，也承载主 Agent 创建的新配置。首轮实例分别获得原始图像和本任务要求；只向补充任务展开明确指定的 `related_result_ids`。整个过程不共享其他实例的完整聊天。

## 数据结构

| 记录 | 当前实现 |
| --- | --- |
| 目标 | 复用 `TargetRecord`，保存原始要求、参考路径、目标约束和用户保护项 |
| 主分析任务 | 复用 `TaskRecord`，`role="analysis"`，没有父任务和视角配置 |
| 视角配置 | `LensConfig`：`id`、`name`、`focus`、`method_notes`、`default_questions`、`origin` |
| 子任务 | `TaskRecord` 增加可选 `parent_task_id` 和 `lens_config`，每次绑定完整不可变配置 |
| 原始报告 | `ResultRecord.analysis_detail` 中保存 `LensReport` |
| 综合结果 | 同一可选字段中保存 `AnalysisSummary`；两种详情通过 `kind` 区分 |

`TaskRecord` 的分析字段均为 keyword-only 并带默认值，包含父任务、视角配置、任务目的、分析缺口、预期新依据和 `evidence_ids`。`ResultRecord.analysis_detail` 默认 `None`；旧生成调用和旧分析报告保持可读取。

模型创建新视角时提供 `LensDraft`（名称、关注点、方法和默认问题）。程序分配配置标识并设置 `origin="generated"`。每个 `AnalysisTaskRequest` 提供 `objective`，并在 `preset_id` 与 `lens` 中选一个。首批 `purpose="initial"` 且至少两个任务，不能选入报告或测量。后续请求必须注明 `purpose="supplement"` 或 `"verify"`、`gap` 和 `expected_evidence`，显式选择报告和证据。无效批次在登记任何任务前被拒绝。

### 原始报告

`LensReport` 包含 `scope`、`observations`、`interpretations`、`uncertainties`、`suggestions`、`evidence_requests`。取证需求说明问题及其对实现的影响，可以附建议测量区域；报告提交不自动执行测量。

- `Observation`：报告内唯一 `id`、可见现象 `text`、位置描述 `region`，可选原图区域 `region_box`，以及 `basis`、`evidence_ids`。
- `Interpretation`：报告内唯一 `id`、解释 `text`、支持和反对观察编号、不确定性及可选验证问题。
- 同一编号不能同时用于观察和解释；解释引用必须指向本报告内存在的观察。
- 报告可以保留竞争解释；至少提供一条观察。编号有效不代表视觉判断必然正确。

### 综合结果

`AnalysisSummary` 保存 `source_result_ids`、`key_observations`、`relationships`、`hypotheses`、`disagreements`、`open_questions`、`implementation_hints`、`missing_task_ids`。

综合条目使用 `SourcedStatement(text, source_refs)`；`SourceRef` 指向 `result_id` 与可选 `item_id`。关键观察必须引用具体 `Observation`；其他类别可引用观察、解释或整份报告。程序检查来源声明、条目存在性和同一父分析归属。

观察及综合条目默认 `basis="visual"`。只有引用有效数值证据时才能标为 `measurement_supported`；局部图像仍是目测。验证引用合法不代表取样位置或结论语义一定正确，多视角一致也不升级为测量事实。汇总通过现有字段区分关键视觉约束、实现候选和待验证问题，避免重复创建另一份下游结构。

### 批次间统一取证

`MeasurementSpec` 描述 `crop`、`region_stats` 或 `line_profile`，使用原图像素 `left/top/right/bottom`（右、下边界排除）。`line_profile.axis` 是逐像素变化的轴，对另一个轴取平均。统计值是白底合成后的编码 RGB 及加权亮度，不能当作物理亮度或整体材料属性。

程序同时生成 `ProfileDigest`，包含带原图坐标的均匀采样点、局部暗谷与亮峰候选。候选采用半径 3 像素和编码亮度对比阈值 1，每种保留最显著的最多 16 个；这只是数值候选，不直接推断网格、光晕或物体边界。模型上下文省略超过 128 点的原始数组，保留概览和适用限制；完整数值仍存储在 `MeasurementRecord.profile` 中。

候选须满足窗口内实际极值条件，且相对左右两侧邻点的方向差均达到阈值，避免把暗线两侧的平坦背景或轻微噪声误列为强亮峰。`contrast` 为两侧方向差的较小值，`neighbor_level` 为选用的保守邻点值；它不估计未遮挡背景，解释亮肩或阴影时仍要选择合适对照区域。

子 Agent 提出需求；主 Agent 收到一批报告后合并需求、判断优先级并调用工具；程序执行并保存 `MeasurementRecord`，包括原图 SHA-256、方法版本、区域、数值或裁剪路径。相同操作及有效参数在本次冻结图像中复用证据 ID，不同取样区域保持不同结果。结果存于可选的 `BlackboardState.measurements` 表，旧黑板仍可使用。

主 Agent 必须在后续上下文收到测量结果后，才能引用它进行综合或派发复核。子任务只收到明确选入的 `evidence_ids`，裁剪会以真实图片进入消息。共享证据后的复核报告属于补充分析，不能作为多份独立投票。不可由当前图片解决的机制问题可以保留未知并结束，不要求强制测量或追加到满额。

综合结果必须声明本轮全部有效报告。主 Agent 必须在一次后续模型请求中收到报告，才能提交综合结果；同批派发与结束不能绕过这个条件。至少派发两个分析任务才可结束多视角分析。缺失任务由执行器根据执行状态填入，模型不能通过修改该字段隐藏失败。

分析详情是详细内容的唯一来源；该结果的旧版 `observations`、`hypotheses`、`limitations`、`recommendation` 字段留空，通用 `summary` 保留简短说明。

## 程序与模型职责

程序分配标识、验证字段和引用、控制工具范围、计算次数、串行提交黑板更新。模型负责视角内容、分析问题、报告与综合判断。

`run_analysis_batch` 调用一个受限线程池。每个 worker 得到固定输入快照并返回自身结果；它不覆盖共享黑板。主协调器依次提交完成结果，失败的任务产生 `blocked` 结果和单独执行错误，其他有效报告继续保留。

主 Agent 只可调用批次、测量和结束工具；子 Agent 只可提交报告。可见工具和执行阶段都做范围限制，框架内置文件操作及递归委派不能绕过它。分析和测量使用同一份固定图像字节，并保存为本次 `reference.png`。

每轮注入时，`AnalysisLoop` 将最新资料合并到结尾的用户消息；若历史以 assistant/tool 交互结束，则在完整交互之后追加多模态用户消息。临时资料仅作用于该次请求，不写入历史，也不拆开工具调用与反馈。2026-09-14 的当前服务对照发现：两条连续用户消息会导致模型无法识图，调换顺序也无效；合并消息或保持正常交替后可以识别。修复没有修改视角提示词或报告结构，原始图片字节也保持一致。

批次及测量工具返回简短回执，完整材料由下一轮 Context Builder 统一提供，避免报告和数值重复进入历史。模型传输默认使用 SSE，收到完整输出和正常结束标记后才执行工具；这不会让子任务中途请求主 Agent，统一测量仍只发生在批次之间。流中断及缺少结束标记时有限重试，不执行部分解析的参数。简短校验反馈保存在执行记录的 `tool_feedback` 中。

默认总任务数 6、并发数 3、子 Agent 逻辑调用上限 3、主 Agent 逻辑调用上限 8、唯一测量上限 8。格式修正和纯文本回复消耗逻辑调用次数。连接恢复保持原任务身份，客户端内部重试关闭；程序在每次逻辑调用中最多额外尝试 2 次，记录每次耗时、错误类型和异常链类型。可恢复连接、超时、限流和服务端错误才重试，工具执行不在重试范围。单次网络超时默认 120 秒；当前没有 token 总额或整个分析的硬墙钟截止时间。
