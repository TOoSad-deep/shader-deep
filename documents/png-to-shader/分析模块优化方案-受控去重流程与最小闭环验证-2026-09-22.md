# 分析模块优化方案：受控去重流程与最小闭环验证

日期：2026-09-22。修订：精简首轮范围，移除提前泛化的调度和验证设计。

状态：首轮实验路径已实施；后续修复已将受控主整合接入默认图片入口和标准回放。第 1—7 节保留首轮实验范围，第 8 节记录首轮验证，第 9 节记录默认入口的后续实施及验证边界。本版不要求跨页组合矩阵或暂缓工作的自动重入。

## 1. 要解决的问题

**先让主 Agent 完成一个小范围去重，再考虑通用调度。** 主整合默认整理已有结论、去重和维护引用；不同机制继续保留，不要求在这一阶段选出原图的真实实现。

前三次实测的主整合均停留在第一个比较组，接受事务均为 0。最新一次先选满 12 个草图目标，随后又提交特征、关系和元素未决问题，反复卡在范围及字段约束上。它在初稿 2 次调用之后耗尽单个整合阶段的 12 次额度；不是已经用完 40 次主调用总额度。

这支持优先收窄工作和提交内容，但不能据此承诺新流程一定成功或成本一定下降。依据见[最新调用记录](../../apps/shader_deep/runs/real-business-budget-balls-20260922-54CxRg/run-avu0ozrm/tools.jsonl)和[前一次冻结回放记录](../../apps/shader_deep/runs/business-budget-replay-20260922-cY01sa/实施验证记录.md)。

当前 26 个特征的 `id`、`name`、`element_ids`、`appearance` 合计序列化为 **4507 个字符**。这是发现视图的文本长度，不含工具、候选和历史，也不是 token 用量。尚无必要为了这批数据先实现所有页面之间的组合扫描。

## 2. 哪些设计收回，哪些必须保留

| 原设计 | 精简决定 |
| --- | --- |
| 所有发现块内部及块间两两扫描、覆盖账本 | 首轮人工指定真实小组；扩大到 26 个特征时先检查完整发现视图能否一次容纳，再决定是否需要分页算法 |
| 另建 `ready/running/done/deferred` 状态机和事件唤醒 | 使用固定工作清单与现有业务状态；本轮每项只安排一次，暂缓不自动重新入队 |
| 新增 `action`、`keep_ids` 等完整提交协议 | 保留现有 `merges`、`preserve`、`deferred_work` 字段，只限制当前步骤可用的字段和对象类型 |
| 自动取证、跨库引用修复的通用编排 | 首轮遇到证据不足或无法通过校验的引用冲突就保存原因并暂缓；根据具体失败再做局部修复，不先建框架 |
| 新建多份输入相互校验、审阅状态和指标体系 | 复用现有回放入口、manifest、工具记录和库校验，补足本试验缺少的结果摘要即可 |
| 为既有权限、版本、来源、分页规则再建完整测试矩阵 | 复用已有测试，只新增调度与受限提交产生的新行为测试 |

继续保留：完整来源输入、实际呈现和版本检查、合法引用、原子发布、来源追溯、有限调用额度，以及失败任务和初稿问题。简化不能依靠删除这些约束。

## 3. 首轮只实现固定的三个工作

在现有冻结报告回放路径中执行下列清单，不重新探索图片、不自动寻找小组，也不接管默认分析入口。

| 工作 | 程序提供的材料 | 模型要完成的判断 |
| --- | --- | --- |
| W1：特征比较 | F1、F2 的完整特征正文 | 是否描述同一外观；合并或有依据地保留 |
| W2：候选比较 | W1 合并后的拥有者、四个候选及直接必要前提 | 哪些是同一种机制，哪些差异应保留 |
| W3：下一独立组 | F3、F4 的完整特征正文 | 完成另一组合法决定，验证程序确实推进了工作 |

W2 依赖 W1 的拥有者合并。W1 未合并或被暂缓时，不把不同拥有者下的四个候选强行合并；记录 W2 未执行的原因。W3 独立于这个依赖，剩余额度允许时仍应执行。

程序固定工作身份、目标范围和材料版本，调用现有上下文与预算检查，实际发送后才登记呈现。模型不再自行选四库、扩大范围或管理工作 ID。

普通比较只提供当前已有文本材料，不常驻整幅图，不直接开放测量。确实缺少证据时记录具体对象、差异和问题；本试验不自动转入新的全图分析。

### 提交与失败处理

沿用现有字段，模型可见 Schema 与执行白名单同步收窄：

- `merges`：只能合并本工作中同类型的对象。
- `preserve`：没有修改时明确保留；有合并时可明确保留其余目标。
- `deferred_work`：给出具体原因；本试验暂缓整组，不同时发布局部修改。

普通步骤不暴露 `additions`、元素 `unresolved`、初稿问题处置和任意引用更新。继续复用 `IntegrationDecision`、`SubmissionHandler` 和 `LibraryStore`，不新增存储协议。以下只是当前字段的示意，实际使用运行中的完整 ID：

```json
{
  "merges": [{"kind": "feature", "members": ["F1", "F2"]}]
}
```

```json
{"preserve": true}
```

```json
{"deferred_work": ["两条描述的适用范围不同，当前不能确认等价"]}
```

成功回执后才推进。被拒绝的决定在同一工作额度内局部修复；耗尽额度、材料放不下或仍无法判断时暂缓，继续下一独立项。暂缓留在未完成台账，但不从 `ComparisonManager.pending` 中自动反复领取。首轮不实现自动重入；再次处理需要明确安排，已有额度不能悄悄清零。

后端仍在每笔事务中机械改写引用并执行最终校验。若无法合法发布，保存完整失败，不绕过校验；也不为证明成功而临时扩成跨库大提交。全局额度耗尽时停止，保留所有已发布结果与未完成项。

## 5. 验证做到足以判断这次改动

### 无网络验证

优先复用或扩展现有测试，新增覆盖只围绕两类行为：

1. 正常路径：W1 接受后使用实际规范身份进入 W2，W2 接受后 W3 也得到有效决定；当前类型、范围和字段限制生效。
2. 失败路径：越界或非法字段被拒绝，按既有额度修复或暂缓；依赖未满足时不执行 W2，独立 W3 仍可继续；暂缓不自动重试、已用额度不重置。

已有库事务、呈现、版本和来源测试继续使用，不为本文每条描述单独增加测试，不断言内部调用顺序等无关实现细节。实现稳定后按包约定运行一次 `make test` 和 `make lint`；只有出现新改动、失败或明确疑点才补跑相关检查。

### 真实服务验证

做一次固定报告、三个工作的有界试验，沿用已经验证可加载的输入与原有模型配置。运行前确定并记录总调用上限、每工作上限和有效输出预算，不在运行中自动增加。正常路径至少需要三次判断，局部修复另计。

本轮不同时改探索任务、模型和输出预算，不重跑整张图的探索来验证局部调度。第一次失败后先根据输入、工具回执和草稿定位原因；没有新假设或代码修复，不机械重复付费运行。

### 三项接受证据与一次结果检查

| 项目 | 通过条件 |
| --- | --- |
| W1 | 特征材料实际呈现，形成有依据的合并并取得回执，四个候选及来源保留 |
| W2 | 根据 W1 的规范身份完成四个候选的比较，全部目标被明确处置并取得独立回执 |
| W3 | 新工作中的 F3/F4 得到合法合并或保留回执；只进入下一组不算完成 |

三项必须分别有记录。试验结束后集中检查一次最终库引用、别名、来源和保留机制，并对照原文查看合并是否合理；不另建审阅服务、审阅状态机或逐事务人工审批。

W1 不合并导致 W2 无法进行、W2 被拒绝或 W3 未完成，都必须明确报告，不能靠一笔成功事务判定闭环通过。模型有合理的保留理由时保留该结果，不强迫合并；对预期存在分歧时，说明哪些步骤执行成功、哪些语义尚未验证即可。

反例直接包含在同一次 W2 中：不能因为都能产生柔和阴影，就吞并多层投影或渐变环。无需为每种保留机制另开一次真实运行。

已有失败探索任务和初稿问题继续影响全运行状态。因此该局部试验成功后，整体仍可为 `partial`；不能删除义务来得到 `completed`。单次成功也不证明稳定收益或自动发现全部重复项的能力。

- 复用现有工具日志、草稿和版本快照，最终附一份三步结果摘要。没有发现具体后端缺陷时，不重写 `LibraryStore` 或修改公共运行入口。

## 7. 小试验通过后再扩大

1. **26 个特征：**先用完整发现视图寻找疑似重复组，再复用已经验证的局部处理。若完整输入确实放不下，另行设计必要的分批和跨页补比；在该能力实现前，未覆盖范围明确保留，不能宣称已完成整库去重。
2. **关系和候选：**沿用局部处理，补齐关系端点、方向及候选前提检查。候选工作包含未参与特征合并的拥有者，不能遗漏这些条目。
3. **草图和证据例外：**按真实出现的引用冲突或证据缺口增加最小处理，不先实现通用编排。
4. **完整图片流程：**单独修复探索提示词对 `unresolved` 归属的歧义，以及同类错误只显示前四项的问题，然后再做完整实测。

规模扩大后如需重新处理暂缓项，必须有明确理由、保留原额度；不能直接循环领取全部 `pending`。这是保留的执行边界，不要求首轮实现事件唤醒系统。

第一轮主要看三步是否完成、是否保留不同机制、失败原因是否可定位。调用数、实际 token 和耗时从现有日志记录即可；没有可比基线或完整 usage 时，不报告成本收益。后续测试随新增行为补充，不把所有未来边界都变成首轮门槛。

### 后续复测与判断标准修复

第二次真实运行 `run-zl89nq9k` 中，W1 将共享提示词的“机制等价”要求套用于特征外观比较而暂缓，W2 因依赖未满足跳过，W3 成功。该结果表明第一次成功不能证明稳定闭环。

## 9. 默认入口的后续修复

后续完整运行仍在第一比较组因宽提交和修复错误停滞，因此按后续修复请求扩大了实施范围：默认图片入口与标准冻结回放共用 `ManagedIntegrationSession`。主整合先处理并独立复核初稿问题，再用本轮真实身份发现小组，按特征、关系、草图及候选顺序调用共享受限比较内核。每组 2—6 个目标，组数仅受原有总阶段与总调用额度约束；某组暂缓后继续独立组，不自动重入。
