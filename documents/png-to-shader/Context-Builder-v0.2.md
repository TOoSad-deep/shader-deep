# PNG → Shader：共享黑板与 Context Builder 设计草案

V0.2 · 2026-09-10 · 待实现、待细化。

本文承接 [三 Agent 架构与分层生成流程 V3](分层生成流程.md)，在 [Context Builder V0.1](Context-Builder-v0.1.md) 基础上，引入共享黑板，明确任务视图、按角色读写、版本绑定和结果回写方式。任务生命周期与三 Agent 分工沿用前序讨论，本文给出首版建议规则，不代表相关能力已实现或验证。

## 1. 核心设计：黑板、任务视图与模型上下文

三个 Agent 通过共享黑板上的业务记录协作。主图根据这些记录创建任务，Context Builder 按角色和任务选择信息，形成每次模型调用的上下文。

| 层次 | 职责 | 示例 |
| --- | --- | --- |
| 共享黑板 | 保存项目持续积累的目标、问题、实验、证据和已执行决定 | 目标 T2、基线 B7、倒影问题、候选 C12、评审 R8 |
| 任务记录与任务视图 | 定义本次工作，并指定它使用的黑板记录和制品版本 | 根据 T2，从 B7 出发验证倒影扰动假设 |
| Context Builder | 选择、加载、排列和压缩任务所需信息，加入任务内历史 | 加载参考和 B7 预览、展开相关代码、保留最新报错 |
| 本次模型上下文 | 模型在这一次调用中实际能看到的内容 | 角色指令、任务信息、选定图像与文本、有效历史、工具定义 |

**任务包在本方案中指“黑板上的任务记录及其绑定的材料视图”。** 任务记录长期保存，任务视图在读取时展开；它们引用黑板上的业务数据，必要时展开少量关键字段。派发可以只传任务 ID，由 Builder 解析出所需材料。

首版用主图维护的业务状态、实验记录和制品索引承载黑板；采用一套公共 Builder 加三个角色的选材规则。以上是应用内职责，可以用普通函数和现有存储实现。

```text
用户需求与反馈 → 主图更新目标和决定
                          ↓
                       共享黑板
                          ↑
主图创建任务记录 ──────────┘
          ↓ 任务 ID
Context Builder ← 读取任务视图、相关制品与任务内历史
          ↓
        模型调用
          ├─ 调用工具 → 保存制品、登记相关证据 → 继续本任务
          └─ 提交结果 → 主图核对、回写黑板、安排下一任务
```

主图继续负责全局派发、执行预算、状态更新、暂停与恢复。黑板提供协作数据，Builder 负责每轮输入；黑板记录的变化由主图处理并决定是否派发新任务。

## 2. 黑板保存什么

黑板按项目组织业务记录。下面是逻辑分类，具体字段和存储结构在实现时确定。

| 记录 | 最少保存的内容 |
| --- | --- |
| 目标与用户反馈 | 原始要求、整理后的目标版本、输出约束、保护项、反馈及其适用对象 |
| 场景理解 | 元素拆解、交互依赖、问题与观察区域、机制假设、不确定性 |
| 任务与实验 | 角色、问题、绑定版本、修改范围、预算与结束条件、实际尝试及完成情况 |
| 候选与证据索引 | 代码、资源、参数、真实预览、捕获条件、工具运行结果的引用 |
| 评审与实验结论 | 改善和退步、判断依据、验证缺口、假设受到支持或削弱的记录 |
| 决定与当前状态 | 实际采用或回退、局部工作版与整图保留版指针、用户接受记录、剩余预算和任务状态 |

模型假设、视觉观察、工具测量、用户要求和已执行决定分别记录。每项重要发现标明来源任务或作者、所依据的版本和证据；后续结论修正时保留旧结论的适用条件。

候选登记为可比较版本时，代码、资源、参数与预览应能一一对应。后续修改形成新的候选记录，避免同一记录指向的代码已经变化、预览仍代表旧版。

### 制品与任务历史放在哪里

| 内容 | 保存方式 | 进入模型上下文的方式 |
| --- | --- | --- |
| 代码、PNG、资源与大日志 | 由制品存储保存实际文件，黑板保存引用和必要元数据 | 根据任务直接加载，或使用工具按需读取 |
| Agent 完整任务历史 | 由各自任务会话保存消息、工具交互与工作摘要 | 选取当前任务需要的有效历史；其他任务通过引用回查 |
| 可跨任务使用的发现 | 形成黑板上的实验或结果记录，并附证据引用 | 新任务按问题和候选关联读取 |

任务内部的临时消息留在会话中；需要被其他 Agent 使用的候选、证据与结论进入黑板。这样既能跨任务积累认识，也能按任务限制上下文大小。

## 3. 按职责读写黑板

Agent 提交业务内容，受控工具或主图负责校验和保存。读写入口接收明确的任务、实验或候选标识，写入对应记录。

| 参与方 | 主要读取 | 可以提交或登记 | 生效方式 |
| --- | --- | --- | --- |
| 分析 Agent | 目标、场景关系、相关实验与评审、当前有效版本和预算 | 目标整理、问题诊断、假设、实验方案、采用或回退建议 | 观察和分析结论保存为带来源的记录；目标更新、任务派发和版本采用由主图核对执行 |
| 生成 Agent | 本任务目标、固定基线、实验要求、相关实现与证据 | 实际改动、候选引用、实验记录、实现限制 | 工具保存代码、真实预览和运行状态；主图处理候选后续流程 |
| 评审 Agent | 指定参考、基线与候选、比较条件、保护项 | 视觉差异、区域检查、判断不确定性和验证缺口 | 保存评审记录，交由分析综合；采用决定由主图执行 |
| 执行工具 | 本次操作指定的代码、资源与参数 | 编译、渲染、测量结果和制品引用 | 由程序记录真实运行结果，供 Agent 引用 |
| 主图 | 任务状态、业务结果和用户输入 | 有效目标、任务状态、预算、采用或回退、当前版本及用户接受记录 | 核对条件后更新；重要取舍与最终接受沿用 V3 的用户流程 |

共享存储采用按角色和任务读取的方式。首次评审默认获得目标、图像证据和真实限制；生成者的优劣解释、候选排名和其他评审结论不自动展开。后续按需读取工具也沿用这个范围，确需诊断时再明确补充实现材料。

Context Builder 的读取与压缩不改变业务决定。写入黑板需要走对应的结果或工具入口，不能把整个 Agent 内部状态作为业务状态覆盖回去。

## 4. 任务记录与版本绑定

主图根据当前有效状态创建任务记录。它直接保存任务要求，并引用目标、代码、图像和相关业务记录。

| 信息 | 内容 | 本任务中的变化规则 |
| --- | --- | --- |
| 身份与目的 | 任务 ID、角色、阶段、关联实验、当前问题或待验证假设 | 派发时确定 |
| 目标引用 | 目标版本、相关用户要求和反馈引用 | 固定绑定，按该版本展开 |
| 起始与比较版本 | 起始基线、局部工作版、整图保留版及各自用途；评审指定候选 | 固定绑定，不能仅引用“最新版本” |
| 工作约束 | 作用范围、关联依赖、允许修改范围、保护项、结束条件和返回要求 | 范围或核心假设改变时交回主图处理 |
| 材料入口 | 参考图、相关问题、实验、评审和实现资料的引用 | 核心输入绑定版本；补充材料时记录实际读取的来源版本 |
| 执行进度 | 当前候选、已完成操作、未解决事项和剩余预算 | 根据本任务的工具结果、业务结果和主图记账刷新 |

首次分析没有 Shader 基线时，直接提供原始需求和参考。目标尚未整理完成的字段标为待澄清，由分析提出整理建议。

任务视图在每轮调用时解析上述信息：固定字段从绑定版本读取，可变字段从本任务有效进度读取。单次构造选定的引用在该次调用中保持一致，并留存所用记录与制品的版本清单。

### 黑板更新时，旧任务如何处理

- **本任务进度更新：** 新工具结果、当前候选和预算进入下一次上下文，原始起点继续保留。
- **其他任务新增记录：** 不自动并入当前上下文；有关联时按需读取，并标明其任务和版本。
- **有效目标或整体基线改变：** 旧任务仍代表原有实验条件。主图在恢复或收回结果时检查差异，刷新任务并安排必要的重新渲染和评价。
- **同轮并行探索：** 各任务绑定同一个起始基线，使用各自输出目录；结果分别登记，再统一比较。

例如生成任务绑定 B7 后，全局整图指针变成 B8，Builder 仍按 B7 解释该任务。返回的候选可以保存为基于 B7 的实验结果；要用于 B8，须经过主图安排的重新验证。

## 5. 上下文生命周期

上下文以一次明确任务为边界，黑板中的业务记录跨任务积累。

| 角色 | 一次任务 | 任务内 | 新任务 |
| --- | --- | --- | --- |
| 分析与实验规划 | 一次目标整理、问题诊断、实验规划或结果综合 | 延续分析与资料查阅过程 | 从新任务视图及相关黑板记录重建 |
| Shader 生成与优化 | 完成一个实验，提交可评审候选检查点 | 延续代码读取、修改、编译修复、渲染与小步优化 | 新实验重建；同一实验恢复时延续有效历史 |
| 独立视觉评审 | 对指定版本进行局部或整图比较 | 延续看图、裁剪和区域检查 | 每次新比较重新构造输入 |

跨任务交接读取黑板上的业务结果和制品，不直接继承另一 Agent 的完整聊天。生成内部的一次编译修复或小步试验只推进当前任务，无需每次唤醒全部角色。

## 6. 按角色选择材料

每轮保留角色职责、任务目的、绑定目标和基线、修改范围、保护项、结束条件及结果要求。关键字段由任务视图直接展开，避免只依赖历史摘要。

| 角色 | 开始任务时直接提供 | 按需补充 | 默认留在历史或制品中 |
| --- | --- | --- | --- |
| 分析 | 原参考、绑定整图（如有）、目标、相关问题与依赖摘要、指定或相关评审、相关实验结论 | 具体候选图、区域裁剪、失败实验细节、实现片段、机制资料 | 无关问题的详细日志、其他 Agent 的完整聊天 |
| 生成 | 实验要求、相关参考与基线预览、代码入口、场景结构摘要、修改范围、依赖和保护项 | 实际修改所需代码、受影响的光照或倒影实现、相关历史尝试、技术资料 | 其他候选的整套实现、无关实验、已解决的报错全文 |
| 评审 | 原参考、指定基线与候选图、各版本用途、目标区域、保护项、捕获条件和验证缺口 | 带位置的裁剪、区域检查结果；确需诊断时的实现细节 | 生成者优劣解释、候选排名、无关或可能影响首次独立判断的评审结论 |

首版通过任务、问题、元素、实验和候选的明确关联选材。先提供相关记录摘要与可读取引用，需要细节时再展开。历史结论附适用版本，判断其是否能支持当前任务。

角色的工具定义和稳定指令由应用配置，任务视图提供相应业务范围。任务包不必重复保存整套工具实现或角色提示词。

## 7. 每次模型调用的构造流程

1. **解析任务 ID。** 从黑板读取任务记录，展开绑定目标、基线和比较对象，取得本任务最新进度与预算。
2. **配置角色能力。** 装入角色指令、工作方式、返回要求和当前工具定义。
3. **展开任务视图。** 提供当前问题、工作范围、版本、保护项和结束条件；刷新任务信息，避免逐轮重复追加。
4. **选择和加载材料。** 按第 6 节选择相关记录，加载必要图像与文本，保留来源、版本和信息性质。
5. **整理有效历史。** 加入当前工作摘要、近期完整工具交互和未解决问题。
6. **控制输入大小并调用。** 按第 8 节缩减材料，为输出留出空间；记录本次实际采用的材料清单和主要省略原因。

建议顺序是：稳定角色指令 → 任务视图 → 相关证据 → 历史摘要 → 近期工作过程。图像与说明一起提供，工具定义使用模型接口的对应字段。具体消息类型和 hook 在接入实际框架时确定。

Builder 的输出是本次模型请求，以及便于核查的材料清单。材料清单标明引用、版本、直接加载或摘要形式；它记录实际输入选择，不表示模型已经正确理解材料。

### 视觉材料规则

- 黑板中的图片路径用于定位；视觉调用通过图像内容块或看图工具实际加载所需图像。
- 图像标明参考、基线或候选身份，关联对应代码、资源、参数、尺寸、时间及其他捕获条件。
- 裁剪图附原图位置，局部任务保留判断构图和保护项所需的整图视野。
- 纯编译修复调用可以优先提供代码与错误信息；重新作视觉判断前加载有效图像。
- 旧预览明确标为历史材料，不能代表修改后的代码。图像缺失或条件不可比时，返回证据缺口，由执行流程补齐。

## 8. 上下文预算与历史压缩

上下文预算限制一次模型输入的大小，执行预算限制实验调用、时间等资源消耗；后者由主图维护，Builder 读取当前值。

可用输入空间根据模型容量、输出预留及余量确定，并计入工具定义和图像成本。具体数值在模型与调用方式确定后配置。

输入过大时，依次去除重复或无关展开内容，将已解决报错和大日志外置，压缩较早工作过程，再缩小非必要资料的展开范围。保留可回查引用、实际尝试条件、观察结果、选择理由和未解决事项。

保留当前任务约束、有效版本、未解决错误、近期完整工具交互以及视觉判断必需图像。裁剪时保持工具调用与结果配对；摘要保留观察、假设和已执行决定之间的区别。

压缩仅改变本次输入，黑板中的原始业务记录和制品继续保留。若必需材料仍超出容量，显式报告不足，由执行流程调整任务范围或调用配置后继续。

## 9. 工具结果与任务结果如何回写

任务内的工具结果与任务结束的业务结果分开处理：

1. **工具完成操作。** 保存代码、预览或日志，返回状态及引用；有效候选和可供协作的证据及时登记到黑板，原始工具交互保存在任务历史中。
2. **Agent 继续工作。** Builder 读取本任务新进度与相关工具结果，构造下一次上下文。
3. **Agent 提交任务结果。** 返回业务总结、证据引用、未解决事项和后续建议。
4. **主图核对并回写。** 核对任务、目标、起点和制品对应关系，保存结果记录，更新任务状态；需要采用、回退或派发新任务时执行相应检查。

任务结束记录引用已经登记的候选与证据，补充总结和结果状态。任务完成、编译成功、视觉改善、已采用以及用户接受分别表达。

| 结果部分 | 内容 |
| --- | --- |
| 公共字段 | 任务与实验标识、目标和起始版本、完成情况、证据引用、未解决事项、后续建议 |
| 分析结果 | 目标或拆解建议、问题诊断、假设变化、下一实验方案、采用或回退建议 |
| 生成结果 | 候选引用、实际改动、编译与渲染结果、实验记录、实现限制 |
| 评审结果 | 可定位差异、改善和退步、保护项检查、依据、不确定性和验证缺口 |

下一任务根据黑板上的这些记录创建。跨任务实验摘要保留：当时的问题与假设、目标和起点、实际改动、证据、结论的适用范围、未解决问题。

“建议采用 C12”由分析记录；“已将整图保留版更新为 C12”由主图执行后记录。主观取舍和最终接受按 V3 处理，并绑定具体版本。

## 10. 示例：通过黑板处理倒影偏宽

以下标识与结果仅为设计示例。T2 是目标版本，B7 是整图基线，E8 是实验，G8、R8、A9 是三个角色的任务标识。

| 步骤 | 黑板变化 | 本次任务的上下文 |
| --- | --- | --- |
| 分析提出 E8 | 保存“横向扰动过强”的假设、实验方案和保护项；主图创建生成任务 G8，绑定 T2/B7 | 生成读取 E8、T2/B7、相关参考与代码，明确修改范围 |
| 生成执行 G8 | 工具登记候选 C12、预览与运行结果；任务结果引用这些证据 | 生成保留本实验的读代码、修复和渲染过程 |
| 主图派发 R8 | 创建评审任务，绑定参考、T2、B7 和 C12 及相同捕获条件 | 评审加载指定图像与保护项，首次判断不展开生成者自我评价 |
| 评审完成 R8 | 记录“边缘更平滑，但整体宽度仍偏大”，附区域、保护项检查和不确定性 | 结果按任务与候选关联，可供分析读取 |
| 主图派发 A9 | 创建综合分析任务，绑定该组结果及当前有效目标和整图版本 | 分析读取 E8、C12、R8 的相关摘要与证据，判断原假设受到削弱 |
| 主图处理建议 | 核对后记录采用或保留决定，再创建下一实验任务 | 新任务明确使用实际选中的起点 |

若 G8 执行期间当前整图已更新为 B8，C12 仍登记为基于 B7 的结果。A9 可以读取这条历史证据，但其适用范围保持明确；主图须先安排在新条件下验证，才能将相关结果用于 B8 的采用判断。

可跨任务复用的记录示例：

> E8 在 T2/B7 上降低横向扰动，得到 C12。R8 观察到边缘变平滑，但整体宽度问题仍存在，因此“扰动过强是主要原因”的假设受到削弱。下一步可检查基础映射范围。附 C12 和 R8 引用；采用状态以主图决定记录为准。

## 11. 首版实现范围与待定项

首版围绕一个实验串行走通“分析 → 生成 → 评审 → 再分析”。应用层需要以下能力：

| 能力 | 首版范围 |
| --- | --- |
| 黑板读写 | 使用主图业务状态、实验记录和制品索引；提供按任务与角色读取、提交对应业务记录的入口 |
| 任务记录与视图 | 创建任务时绑定关键版本，每轮展开固定输入与本任务最新进度 |
| 公共 Context Builder | 三套角色选材规则、必要图像和文本加载、历史整理与输入预算控制 |
| 结果处理 | 工具证据登记、任务结果归档、主图核对与状态更新 |

物理存储和消息接入复用项目现有能力后确定。并行探索先保留固定基线与独立输出的设计规则，首个闭环可用串行任务验证数据交接。

验收重点是可观察的信息流：

- 黑板保存的记录能被后续任务按关联读取，任务视图不会展开无关历史。
- 同一生成任务能接着最新错误修复，恢复后仍能对应原目标和基线。
- 视觉评审实际加载正确图像；初始材料和按需读取均遵循角色范围。
- 全局基线变化后，旧候选保持原始来源，采用前检查新条件下的适用性。
- Agent 建议与主图实际决定分别记录；输入压缩保留关键约束和工具交互。

| 待定项 | 确定依据 |
| --- | --- |
| 黑板记录与会话历史的具体存储位置 | 当前应用代码、主图状态及已有持久化能力 |
| 字段与读写入口的具体定义 | 以上最小数据流和首个真实实验 |
| 输入预算、图像尺寸、代码展开范围、摘要阈值 | 实际模型限制、调用方式与 Shader 规模 |
| 每轮调用及工具结果处理的框架接入点 | 已安装框架版本与真实请求链路 |

本版已明确黑板协作和上下文构造的职责关系；以上实现细节仍需在接入时核对。本文未进行运行时代码或模型调用验证。
