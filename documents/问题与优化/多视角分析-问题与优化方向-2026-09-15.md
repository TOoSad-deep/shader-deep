# 多视角分析：问题与待优化方向

记录日期：2026-09-15。范围：编码前的多视角分析、主 Agent 统一测量、补充复核和结构化汇总。

本文根据已经保留的运行结果、诊断日志和检查记录整理。测试已按用户要求停止，本次仅补充文档，没有新增真实模型调用、运行测试或修改代码。下文的建议与验收条件属于后续工作，不表示已经实现或已获准继续测试。

目前最需要改进的是两件事：**让已有分析能够可靠交付；让证据支持的范围准确传递到最终结论。** 继续扩大测试数量或增加视角数量，不能直接解决这两个问题。

## 1. 保持不变的架构边界

沿用已经确认并实现的流程：

```text
分析子 Agent 模板 + 视角配置 + 独立任务实例
    → 首批独立分析，提交报告与取证需求
    → 主 Agent 检查覆盖和关键分歧，合并需求
    → 批次间由主 Agent 统一测量，程序保存并复用证据
    → 主 Agent 按需派发补充分析 / 定向复核
    → 结构化汇总，保留来源、失败任务和未知项
```

- 子 Agent 不直接调用测量工具；测量发生在批次之间，不引入子任务执行中的实时请求调度。
- 新视角继续由主 Agent 根据模板创建配置，不为每种视角另写一套 Agent。
- 共享证据后的复核属于补充分析，不能作为新的独立投票。
- 分析模块结束于报告交付，与后续代码生成、渲染评审和持续决策解耦。

数据结构和执行规则见[架构文档][architecture]。

## 3. 已经落地、应保留的改进

| 改进 | 已有作用 | 仍然存在的限制 |
| --- | --- | --- |
| 主 Agent 批次间统一测量 | 子 Agent 提需求，测量与证据保存集中执行 | 尚未证明需求优先级合理，也未在本批观察到复用收益 |
| 固定图像、区域和方法记录 | 证据可以追溯到同一输入；相同操作和有效参数可复用 ID | 不同区域即使目的相似也不是同一测量，不能任意合并 |
| 带原图坐标的剖面摘要 | 减少模型手动数长数组索引的错误；完整数组保留 | 极值算法有采样与阈值限制，不能自动给出语义解释 |
| 补充 / 复核任务声明缺口和预期依据 | 后续派发有明确目的，报告和证据按需选入 | 字段齐全不代表任务能取得新证据或改变结论 |
| 来源与证据校验 | 可检查归属、引用对象、证据可见性和类型 | 不能证明一句话中每个子判断都被证据支持 |
| 传输与恢复记录 | 区分逻辑调用、网络尝试、输出截断和格式反馈 | 输出、调用次数和总体耗时仍需要统一考虑 |

最后追加的窄范围 JSON 结束括号恢复及精确语法反馈，属于**代码已写入、验证未完成**，不列为已确认解决的问题。

## 4. 问题清单与优化建议

优先级含义：P1 为下一次开发优先处理的交付或正确性问题；P2 为后续效率、可观测性和结果管理改进。所有条目目前均为待处理。

| 编号 | 优先级 | 问题 | 建议落点 |
| --- | --- | --- | --- |
| A01 | P1 | JSON 精确错误反馈链尚未通过验证 | 工具参数解析、下一轮上下文 |
| A02 | P1 | 格式 / 字段错误反复消耗主 Agent 预算 | 工具契约呈现、错误恢复策略 |
| A03 | P1 | 长输出与修复挤占最终交付预算 | 输出粒度、阶段预算、停止行为 |
| A04 | P1 | 一条“测量支持”结论混入未验证判断 | 原子结论、证据支持范围、汇总检查 |
| A05 | P1 | 关键几何误判没有被复核消除 | 定向问题、复核结果使用方式 |

### A01：JSON 精确错误反馈链尚未通过验证

**已观察到：** 最新单元测试 `test_unrecoverable_json_supplies_precise_location_in_next_image_context` 失败；测试未在下一次模型请求中观察到预期的 `JSON syntax error:` 和 `column`。冻结批次不含该补丁，因此不能用那 9 轮为补丁背书。[证据][parser-validation]

**影响：** 错误位置即使已经生成，也尚未证明能帮助下一轮修复。当前工作区不能标记为检查全部通过。

**待优化：** 先定位原始参数、解析器返回、反馈保存、Context Builder 注入到最终请求之间的断点。现有证据还不能判断是生产链路问题、模拟响应问题，还是测试构造问题。恢复仅限无歧义的多余结束括号，完整工具入参仍须通过校验；不得猜测缺失字段或补全截断意图。

**后续验收：** 使用本地固定响应覆盖反馈确实进入下一次请求、合法窄范围恢复只执行一次、含歧义或截断的调用不执行。失败用例修复后再执行对应本地检查；本次没有补测。

### A02：格式和字段错误反复消耗主 Agent 预算

**已观察到：** 极光样本主 Agent 第 6、7、8 次均提交无效 `finish_analysis` 参数。保存的诊断分别包含字符串引号未转义、对象提前结束、末尾多一个闭合括号。发光矩形样本在第 1、5、6、7 次出现 `lens.name` 缺失，第 7 次还缺少 `objective`。[极光诊断][json-diagnosis]、[极光执行记录][aurora-run]、[矩形执行记录][shiny-run]

**影响：** 已有视角报告无法转成综合交付；重复同类修复消耗分析预算。

**待优化：** 错误反馈给出明确字段路径、最小合法参数形状和修正目标。对连续同类失败设置有限修复次数，随后进入简短收尾或记录明确失败。优先改善现有工具契约的呈现与反馈，不默默补造视角名称、分析目标或证据内容。

**后续验收：** 用固定的缺字段、引号错误和重复失败序列验证：反馈可见、无效调用没有副作用、达到修复上限后有明确状态。格式故障不能被归类为网络故障无限重试。

### A03：长输出与格式修复挤占最终交付预算

**已观察到：** 已结束 9 轮共出现 29 次输出上限事件。波纹样本主 Agent 在第 3、4、5、6、8 次触及输出上限；极光、矩形、波纹最终均耗尽 8 次主调用预算，没有综合报告。[波纹执行记录][ripples-run]、[停止清单][stop-manifest]

**影响：** 单次 token 上限已经生效，但反复要求重新生成长报告仍可能使整个分析无法结束。单纯增加 token 或调用上限尚无收益证据。

**待优化：**

- 减少同一判断在多个汇总字段中的长篇复述，优先交付影响实现的关键条目。
- 为最终汇总预留逻辑调用额度；余额不足时限制新增复核任务，允许以明确未知项结束。
- 输出截断后要求具体缩减范围，而非泛化地重新提交整份长报告。
- 最终综合无法形成时，仍提供程序整理的“已有报告与失败清单”入口；不得将其标为成功的 `AnalysisSummary`。

**后续验收：** 用固定的连续截断、部分视角失败、剩余预算不足序列，验证不会执行截断工具、不会掩盖缺失任务，已有成果始终可读取。新状态语义如有必要，应先与现有调用方兼容规则一起设计。

### A04：测量支持范围不清楚，未验证判断进入实现建议

**已观察到：** 多瓣图元的 `implementation_hints` 把“目测 8 瓣”“孔径与外径比约 0.30”等写在同一条声明中，并整体标成 `measurement_supported`。引用的正交剖面可以支持尺寸读数，不能据此证明瓣数。该报告同时在分歧部分保留瓣数未决，却在关键观察和实现提示中继续使用具体瓣数。[多瓣图元综合报告][balls-result]

磨砂样本的前景 / 背景亮暗关系有数值支持，但报告用不同位置的蓝色对照直接排除普通 alpha 混合，证据不足。[检查记录][reviews]

**影响：** 来源 ID 和数值都合法，后续生成 Agent 仍可能把未验证几何参数或机制推断作为实现约束。这是内容正确性问题，结构校验无法完全解决。

**待优化：**

- 同一条结论尽量只有一个可核查判断；将实测尺寸、目测瓣数、机制假设拆开陈述，各自绑定依据。
- 优先通过现有字段约束和综合检查落实；确需扩展结构时，再引入支持范围或适用区域，避免仅为分类重复建表。
- 比较数值前说明采样区域是否可比；无法观察到对应位置的未遮挡颜色时，保留混合机制的竞争解释。
- 检查关键观察、未知项与实现建议之间的一致性；未知几何参数应作为待定参数传给后续模块。

**后续验收：** 用已有报告制作本地反例：尺寸测量不能让瓣数获得实测标签；局部扫描线结论不能扩展为全图结论；已声明未决的参数不能在实现建议中变成已确认值。复杂因果判断仍需人工审查。

### A05：关键几何误判没有被定向复核消除

**已观察到：** 星形角数仍在 5/6 之间未确认；多瓣图元报告仍给出 8 或 8–10 瓣，已有检查已将其记为错误判断。后者两个针对瓣数和遮挡的核验任务均因预算耗尽未交付。液态玻璃的细颈等轮廓尺寸也未得到可靠确认。[停止与汇总][stop-summary]、[多瓣图元综合报告][balls-result]

**影响：** 角数、瓣数、朝向、间距会直接决定基础图元构造。多份报告重复同一目测结论，不能消除共同误判。

**待优化：** 让主 Agent 按“会改变哪项实现决策”排序复核需求。每个复核任务聚焦一个问题，指定一个清晰实例、已有裁剪及必要证据，要求可核查的计数 / 定位过程。证据不足或复核失败时，在综合观察和实现建议中同步保留未知；无需为了给出确定答案继续增加视角。

**后续验收：** 从既有图片中选少量关键对象保存人工标注依据，比较具体参数而非整篇报告相似度。优先检查瓣数、星角数、格距和裁切方向；本次未新增标注或真实模型验证。

### A06：测量全部用满，但优先级和实际收益不清楚

**已观察到：** 最后已结束的 9 轮全部使用了 8 项唯一测量，复用计数均为 0。关键瓣数、精细轮廓仍有未解决项。[停止清单][stop-manifest]

**解释边界：** 用满预算不自动证明测量浪费；复用为 0 也不证明去重实现失效。可以确认的是：本批没有提供实际减少重复测量的效果证据，且现有测量未解决所有关键问题。

**待优化：** 主 Agent 在调用前明确每项需求对应的关键分歧、预期会改变的结论及已有证据是否足够。先处理高影响缺口，保留后续取证额度，允许无需测量时直接结束。相同图像、操作、区域和有效参数复用；近似区域仍作为不同样本处理。

**后续验收：** 本地验证相同请求复用、不同区域不误合并、无需求时不测量。后续如单独授权真实样本验证，再记录测量对应的问题是否被回答，不以“测了多少次”作为效果指标。

### A07：传输改善尚缺整体时间和用量边界

**已观察到：** 早期长请求曾出现 ReadError / RemoteProtocolError，部分发生在约 60 秒附近；最后已结束 9 轮没有记录请求异常。当前有单请求超时、有限重试和调用上限，但没有整个分析的硬截止时间；流式 usage 曾出现累加口径差异。[历史诊断说明][historical-notes]、[架构文档][architecture]

**影响：** 不能据此认定服务链路问题已根治，也不能从逻辑调用数准确推导成本。多轮模型请求和复核仍可能带来较长等待。

**待优化：** 明确整个分析的截止时间与取消传播规则；分别记录网络错误、输出截断、参数错误、预算耗尽和用户中止。token 计量先明确服务原始 usage、每次请求值和汇总规则，避免把重复累计值作为账单依据。根因未确认前，不把问题归因于并发、模型或网关中的某一层。
